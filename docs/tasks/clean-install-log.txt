5. What is verified vs. what is blocked
================================================================================
VERIFIED
  - resources/dsh (142.98 MB, 13 368 files) + resources/node/node.exe (83 MB) are produced by
    scripts/bundle-dsh.mjs during `electron-builder --win --dir` (beforePack) and the bundled
    runtime answers --version: 0.2.2-rc.1.
  - With PATH containing no node/dsh/multica/pnpm, the bootstrap resolves resources/dsh and
    resources/node by path, runs the shipped node against the shipped CLI (boot chain: 99 entries),
    writes runtime-profiles/dsh.json, and logs `registered bundled runtime`.
  - No global runtime is consulted at any point: with `node`, `dsh`, `multica`, `pnpm` all absent
    from PATH the probe still passed.

BLOCKED
  - `electron-builder --win --dir` does not exit 0 on this machine: rcedit cannot commit the
    version/icon resource ("Fatal error: Unable to commit changes", 4 attempts).
  - The dist\win-unpacked build cannot be launched at all: resources\app.asar is corrupt
    (header offsets point at other files), so Electron 44.9.3 exits 1 with no output and never
    evaluates out/main/index.js. Therefore the assertion was NOT made against the packaged exe.
    The run above used the same main bundle through the electron default-app entry, which is the
    code path that contains resolveBundledDshPaths/probeBundledDsh/writeRuntimeProfile.
  - dist\win-unpacked\resources\dsh has no node_modules (4 files instead of 13 370), so a real
    install would fail resolveBundledDshPaths() on the entry path and show "no bundled runtime".
    "Install and go" is therefore not satisfied by this build, independent of the two issues above.
