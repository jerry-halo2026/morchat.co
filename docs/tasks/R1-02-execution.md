## 顺序与验证

- [ ] 固定两 Bot 最小输入版本，旧 run 不被能力更新热改；复用原生配置，缺保留/加载证据才最小补齐。
- [ ] 用假 provider 只测网关协议、请求防重、未知/迟到用量、预算准入，不记为真实计费或 DSH E2E。
- [ ] Windows 原生 DSH 按固定发行物/官方路径接原 daemon；验证受限身份、文件/网络/浏览器边界、Python/Node、并行与取消，不能把 worktree/profile 当隔离证明。
- [ ] 定向 @ 经过服务端判权/防重，重复/ACK 丢失、普通讨论、引用/code、同名/失权和多目标部分失败均有可见回执。
- [ ] 显式 deliverables 自动采集与幂等上传；中央持久确认后才显示已归档。run 终态、执行 token 失效且本机重启后，在当前合法授权下补传，不重跑模型；撤权则拒绝。链接逃逸、半写文件、对象成功关联失败均测试。
- [ ] 原生界面显示各 Bot 回复、追问、执行中补充、停止请求/实际停止区别、离线等待原因、成果与用量四维状态；真实不支持 steer 则明确降级，不伪造消费确认。
- [ ] 所有无模型测试通过后，一次性请求公司模型入口、确切型号/配置位置/预算上限；没有批准不得使用历史账号或聊天 Key。
- [ ] 经批准跑 Windows Electron 合成真实链路，校验本地文件 hash、自动关联、真实 provider usage/唯一入账；无真实 usage 留 UNKNOWN。独立 review 与原生回归后合入集成分支。
