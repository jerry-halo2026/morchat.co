# 自动保存与最小双设备接续证伪方案

> 2026-11-05，两台 Windows 11 x64 原生设备的待执行验证方案（Mac 预备）。本轮只写文档，没有编写测试代码、安装服务、调用模型或实施断电/断网。Ethan 已确认：要接续工作，不搬进程；保存点必须自动，不能依赖员工手动提交。本文件是 P0 的最小实验规程，不是编码实施计划或执行授权。

**目标：**证明所选最小技术组合能自动留下完整的公司保存点；原执行设备不可用时，另一台获授权设备能继续工作；不能以丢文件、重复动作、旧写覆盖或越权换取可用性。

**架构：**Multica 是统一客户端/后台及唯一 task/run/调度权威，中央持有已确认保存点关联，Git/版本资产持有实际内容；A、B 各运行本地完整 DSH harness，模型经公司网关调用云端。接续创建新尝试和新工作区，不迁移旧进程；不依赖 Paperclip remote adapter/PCWS，不导入 OpenMausBot runtime。

**技术范围：**一个选定 harness、两台独立 Windows 11 x64 原生设备、固定发行物及版本；Mac 仅保留接口准备，不阻塞首轮；不以 VM、WSL 或 Docker 作为客户端依赖或替代验收。先按 [原生运行与 Harness 核查](NATIVE-RUNTIME-RESEARCH.md) 做原生能力预检和选路，获实施授权后建立 Multica 权威任务关联＋公司自动保存/恢复的最薄链；NG-01–06 全部通过后，才计分验证 W1→W2 与 W2→W1 的 Git/普通文件恢复；不扩展工作流、多引擎产品或任意桌面软件控制。按多供应商 Chat Completions／Messages 需求，DeepSeek Harness 调整为优先验证候选，Codex App Server 保留对照/备选；不是已通过选型，NG-04 协议门禁见原生核查 §4.1。

**DSH 优先的组件细化：**按 [Windows DSH 最小接入](WINDOWS-DSH-INTEGRATION.md) 优先沿 Multica 官方 daemon DSH 路径验证。ACP 非必需协议；MXC 等仅为待验证隔离组件。冻结实际 Windows build/有效 tier、公司 profile、run 级模型通道或更细工具隔离；在唯一 Multica 权威下完成自动保存、条件提交与恢复验权，再完成 WI/NG。不能把能聊天、HTTP 成功、手动上传或会话落盘当作计分前提已满足。以下保存/损失/恢复参数全部保持不变。

**依据：**[工作空间接续设计](WORKSPACE-CONTINUITY.md)、[群协作与设备池](DISTRIBUTED-COLLABORATION.md)、[源码证据](CROSS-DEVICE-REFERENCE-RESEARCH.md)。本方案是 WC/DC 的第一轮小实验，不能替代完整门禁或上线验收。

## 1. 自动保存的硬要求

### 谁来触发

由受管理 runtime/工作空间服务执行，不依赖模型记住提示词、员工点击保存、手动 Git commit/push、下班关程序或主动交接。用户可以主动保存，但它不能成为任何正向测试的必要操作。

自动触发包含：

1. 输入准备完成后先确认初始保存点 CP0，随后才开始可恢复工作。
2. 文件变更完成或受控工作单元结束时触发；等待人、等待子任务、受控暂停/交接前也触发。
3. 有未确认变更时按周期兜底检查，不因持续编辑而无限延后；文件事件丢失仍能通过周期比对发现。
4. 只变了进度/工作摘要/效果回执也参与保存，不因文件未变就忽略任务上下文。
5. 失败重试、查询丢失的确认回执、客户端/上传服务重启后的回传恢复由系统完成。权限或代次已变化时停止旧发布，转有权的恢复核对流程，不能自动重试到成功为止。

### 自动保存不等于自动接受半成品

保存前在受管理写入边界形成一致截面，先生成不可变本地暂存，再传到公司并发布任务关联。上传期间可以继续有界工作，但新的字节仍标为未确认；保存失败、积压或滞后超限时停止累积新工作并告警，不静默丢弃唯一副本。

员工看到“公司已保存至某步骤/版本”，其依据必须是中央持久提交，不是本地落盘、上传进度 100% 或 AI 自报。自动保存不改业务验收结论，不自动合并代码/冲突，不自动发布 skill。

任意软件尚未写到磁盘的编辑器内存不在首版保证内；对纳管目录已落盘的支持文件，不能再要求员工手动提交到公司。长工具必须提供受控的阶段性保存边界，或在时限内暂停/分块；以“任务没结束”为由长期不保存，不能通过。无法支持的工具/文件应在执行前明示并拒绝可接续承诺，不得在失败后临时移出范围。

## 2. 最小环境与测试资料

### 两台执行设备，不是两台电脑承担一切

- **设备 W1、W2：**两台独立 Windows 11 x64 原生电脑。每轮 A 表示故障源、B 表示接手端：先 W1→W2，再 W2→W1，分别记录全部切点。两者属于同一公用 Agent 的预授权池，使用不同设备身份和独立本地工作区。初始任务确实落在 A，B 同时执行另一无冲突任务；B 接手后须能与原任务并行，不默认每设备单任务。
- **中央后台、Git、版本资产存储、公司模型网关：**独立于 A、B，整个实验中除指定故障外保持可用。不能把后台放 A 再同时断电，造成测试对象混淆；中央不运行员工 harness。
- **身份：**两名测试员工；公用 Agent 接续任务的业务负责人不因执行设备更换而自动改变。另用 B 的被撤销/未授权身份做负测试，不额外要求第三台硬件。完整 DC/WC 的第三设备、跨部门和规模测试仍保留。
- **安全：**专用可丢弃测试环境、合成资料、公司测试模型通道，无生产业务凭据、个人登录态或真实客户内容。外部写动作只用隔离测试接收端。不得直接切断员工日常工作机电源。
- **断电方式：**经单独授权，在备份完善的专用原生测试电脑上模拟突然整机失电/强制断电，不先优雅退出触发保存，不对员工日常机器实施。仅结束 harness、关闭网页、断远控、锁屏、休眠与实际整机断电分别记录，不能互相代替；关闭虚拟机不能计为本实验通过。

### 一份可重复比对的工作包

选择一个通用“整理资料并形成分析报告”任务，含两个工作区：

- Git 项目：已在公司保存的基线、测试中产生的未推提交、同一文件的 staged/unstaged 不同修改、删除、获准未跟踪文件。测试步骤可通过工具产生这些状态，但不能额外手动上传来帮助恢复。
- 普通目录：文本报告与二进制表格；一对相互关联的文件携带同一个阶段标记，暴露混合版本问题。
- 任务证据：已完成步骤、待完成步骤、子任务/资产操作 ID；给出可确定的内容校验或业务断言，不比较大模型措辞是否完全相同。
- 排除样本：合成的私人内容和假凭据标记，放在明确未纳管目录；不得进入公司保存点。样例不使用真实秘密。

恢复前 B 的目标工作区必须为空，不得预先复制 A 的中间态、共享 A 的磁盘或从 A 偷取文件。预置公共依赖可以，但工作内容只能来自公司已确认版本。文件完整性的主要证据是清单与实际哈希、Git 分层差异；最终 AI 文案可以变化，但必须正确承接已确认工作。

### Windows 原生断言与 Mac 预备边界

原生安装、公司认证、Python/Node 与选定浏览器、权限隔离、进程树取消、休眠/唤醒、文件兼容和真实 Multica 任务关联与保存点接入先按 NG-01–06 核验。任何一端不通过，不进入计分 DV。第一次安装的系统授权或正常业务审批允许人工确认，但自动保存/补传不能靠人工。

工作包使用跨平台相对路径，预置受支持依赖而非复制 A 的 venv/node_modules；两端核对实际字节和 Git staged/unstaged 层次，不自动做行尾转换。中文/空格路径作为正例，名称大小写/Unicode 碰撞、Windows 保留名/ADS/尾点尾空格、链接逃逸、文件被占用作为负例；不能静默改名或漏存仍称完整。检测不兼容后保留公司版本并明确拒绝激活。

同为 Windows 也不代表应用/授权/硬件能力相同：A 独有能力的任务不能盲目派给 B；B 拒绝不兼容步骤是正确负例，不替代双方均具备能力的 R1 工作必须接续的正例。普通文件/Git 接续不复制系统 ACL、原机进程、个人 HOME 或浏览器登录态。

Mac 预备保留平台生命周期、安全存储、路径/名称、工具权限和 capture/restore 接口，存储内容不写死盘符/POSIX 路径。首轮不开发/验收 Mac；后续另测 Mac 原生及跨系统恢复，Windows 成绩不覆盖这些能力，也不代表所有 Windows build。

## 3. 运行前冻结的试验参数与证据

以下是本轮建议冻结值，不是 Ethan 已批准的损失承诺，也不是实测 SLA。正式执行前记录并确认系统 build、版本/摘要、模型 ID、隔离策略、工作包和网关条件；没有授权/参数确认不能计入验收。变化即新一轮实验，不能看到结果后放宽门槛。

| 参数 | 推荐值 | 含义与判定用途 |
|---|---|---|
| CP0 / EVENT_COALESCE | 开工前确认／2 秒 | 先有可恢复基线；工作单元结束/等待/暂停触发，事件合并不能饿死周期检查 |
| SAVE_INTERVAL | 30 秒 | 有未确认变更时的周期兜底；文件事件丢失也必须发现 |
| SAVE_DEADLINE | 30 秒 | 应触发保存至中央完整确认，含安全边界、采集、上传、关联；不能只计上传 |
| CONFIRMED_LOSS | 0 | 已确认文件、版本及已提交业务效果不能丢；发现一次即完整性失败 |
| UNSAVED_AGE_LIMIT | 60 秒 | 正常联网支持负载下，最早未确认变更的积压界限；30＋30≤60，不包含未返回的模型思考或任意软件未落盘内存 |
| UNSAVED_BYTES_LIMIT | 5 MiB | 未确认变更/待传内容与预留在途输出总额度；字节或年龄任一到限停止累积，不能只数新增文件而忽略改写/删除元数据。按统一变更清单口径计量，不将已确认基础字节重复计入 |
| HEARTBEAT / LEASE_TTL | 5 秒／20 秒 | 故障探测和执行资格，不等于进程终止；中央校验当前代次，不能只靠本地时钟或自报 |
| OFFLINE_DEADLINE | 30 秒 | 从断联到旧端禁止新的有效模型/共享动作；已在途请求可能完成并产生费用，要对账 |
| RESUME_DEADLINE | 180 秒 | R1 故障发生至 B 校验、激活新尝试并完成首个有效后续步骤；包括检测、对账、下载、启动和真实云模型步骤 |
| SAFE_UNIT_BOUND | 10 秒 | 支持的文件写入单元需能在此界限到安全保存边界；不是强杀模型来伪造一致截面，不能仅拿 interrupt ACK 当全部写者停止 |
| WORKSET_PROFILE | 每任务归档范围≤20 MiB、≤2,000 文件、单文件≤5 MiB | Git 历史也计入归档范围；合成小代码/文档/二进制资料，模型与依赖固定；不代表视频/大表格目标 |
| NETWORK_PROFILE | 每台到中央有效上行≥20 Mbps、往返≤100 ms | 故障注入前测定；中央数据库/对象存储可用，带宽/恢复通路全耗时仍计入期限 |
| REPEAT_COUNT | 每方向、每故障切点至少 3 次 | 逐样本达标，不用平均或最快值掩盖失败；零故障小样本不是生产可靠性证明 |

保存失败/断网时暂停并显示未确认风险；长时间离线不能继续积累工作并声称仍有 60 秒 RPO。暂停不会使未确认内容变成已备份，也不会阻止已有变更的墙钟年龄增长；断网负例记录最后确认覆盖点与停工前积累，正常联网基线超限仍判失败。最大可丢失范围指上述可保存变更，不承诺在途模型输出和费用可回滚；实际缺口未知时不能编造精确损失。

全量保存的带宽只是待测成本：单按 20 MiB/30 秒约 40 MiB/分钟/持续修改任务，事件触发和中转可能更多；先复用正确链路，不提前另建增量同步引擎，也不把小包成绩外推到公司规模。
空闲且内容未变不要求制造新版本，不能把保存点日期较旧误当数据有损失。记录的是未确认变更的年龄、数量与覆盖步骤。断网后暂停可避免继续扩大风险，但不等于已经确认的损失窗口为零；恢复失败或超限必须明确记录。

每个样本记录：测试 ID、故障切点/方式、任务/run/attempt/写入代次、中央保存点 ID/父版本/提交回执、文件清单哈希、Git 基线/index/工作层、操作回执、A/B 进程与工具来源、事件顺序、耗时、权限变化、截图和最终结果。中央事件顺序用于判定，时长用统一观测时钟/单调计时，不直接相减两台未经校准的本地时钟。

证据不只来自截图或设备自报：须读取权威保存点与实际存储对象、B 实际文件和任务关联。禁止读取供应商原始 Key。结果记录到事先指定的 RESULT_LOG，每个子样本独立标记 PASS、FAIL 或 NOT RUN/BLOCKED；后两者不算通过。

## 4. 测试顺序与明确失败条件

以下每项的子切点均须在 W1→W2 与 W2→W1 两个方向独立执行并记录，不能任选一个或单方向代表整项通过。故障触发应由记录到的阶段屏障控制，不以随便等待若干秒替代；若现有接口缺少可观测切点，记录缺口，待后续授权建设最小测试夹具，不假装已经可执行。

### DV-01 自动保存与并行基线

- [ ] A 做主任务，B 同时做独立子任务。全程不点保存/同步，不手动 commit/push，不额外提醒模型保存。
- [ ] 分别验证工作单元结束的事件触发，以及屏蔽文件变更通知但不破坏周期检查时的兜底触发；让工作继续到至少两个自动确认保存点。
- [ ] 单独让任务仅更新工作摘要/步骤、没有文件变化；再验证等待人、正常暂停前的保存。长工具持续产出时检查能否自动到安全边界，不等待整任务结束才保存。
- [ ] 校验提交清单、文件和任务截面；记录 A/B 实际执行重叠及保存耗时。

**通过：**所有触发独立有效，满足冻结时限/积压界限；真实并行、会话/目录不串，周期触发不靠手动或模型自觉。

**失败：**缺任何触发、漏掉进度变化、持续编辑无限推迟、只能结束时保存、超过时限仍显示正常，或用全公司/每设备固定单任务换取保存正确性。明确暂停可阻止损失，但受支持基线任务反复无法自动形成新点仍不算通过。

### DV-02 公司确认后断电（含回执丢失）

- [ ] 在中央已持久提交 CP1 后，A 不经过正常退出直接断电；A 整个恢复期间保持不可访问。
- [ ] 再做一轮：中央已经提交 CP1，但对 A 的确认回执被丢弃，然后断电。判定依据是中央实际提交，不是 A 是否看见绿色提示。
- [ ] 系统按 R1 核对和隔离旧代次，自动选择 B；B 从空工作区恢复，并完成一个原未完成步骤。不允许人工复制文件、手动补提交或重新输入丢失上下文。

**通过：**B 获取中央最新已确认完整版本；Git 分层/文件哈希/任务版本匹配，已完成操作被跳过；达到 RESUME_DEADLINE，A 离线不妨碍继续。回执丢失不造成重复保存/重复任务或退回旧版本。

**失败：**任何已确认字节缺失/损坏，恢复依赖 A，B 只是远控 A，重复执行已完成效果，或必须员工手动保存后才能接续。恢复进程启动但没完成实际后续步骤不算成功。

### DV-03 保存中断电与一致截面

- [ ] 自动 CP0 已确认；A 产生下一阶段修改，使两个关联文件更新到同一新阶段。分别在“采集未完成”“只上传一部分对象”“对象齐全但任务关联尚未提交”中断 A。
- [ ] 另在采集阶段让外部写者抢写关联文件，或尝试绕过受管理编辑入口，观察系统是否拒绝不一致截面。
- [ ] B 查询权威保存指针，只从真正已提交点恢复；半包仅是待处理/隔离材料，不得直接覆盖当前版本。

**通过：**没有完整新提交时使用 CP0；若故障前实际已经完成权威新提交，使用该新点。任何情况下不得把半旧半新文件视为同一版本。记录未确认内容及风险；原机无法核对时标“缺口未知/至多覆盖到 CP0”，不能编造准确丢失字节数。

**失败：**只检查文件存在、不核对关联版本；部分上传即标可接手；遗漏文件仍标完整；偷偷使用 A 数据；或自动保存长期滞后超过已约定界限。丢失界限内、从未确认的新改动本身不构成零损失违约，但必须如实显示。

### DV-04 断网不关机：旧进程仍活着

- [ ] **全断网：**隔断 A 的网络，保留其进程；B 与中央可用。记录旧端停止新模型/工具动作的边界，系统不得把失联直接当作物理终止。
- [ ] **部分断网：**只断 A 与控制面/续租链路，保留 A 到模型网关、Git/资产入口的网络，验证不能利用其他通路继续旧执行权限。
- [ ] **提交竞态：**把 A 一次写请求停在“预检已通过、权威提交尚未生效”；换代激活 B 后再释放旧请求。相关未知效果必须先收敛/对账，R1 的生效点须真正检查新旧代次。
- [ ] B 自动从最新可恢复点接续并产生新保存点；不等待 A 回网，不依赖停止旧进程来掩盖写入权限缺陷。

**通过：**达到 OFFLINE_DEADLINE 后旧端不得发起新的有效动作；B 在 RESUME_DEADLINE 内推进。旧进程即使仍做局部计算，也不能更新任务、正式 Git/资产或使用旧授权发起新模型请求。换代之前已获准的在途模型请求可以完成/产生实际费用，必须对账，不当成零消耗或自动归罪于新 run。

**失败：**部分断网绕过撤权，旧请求在换代后仍能提交，长期双写，或对已符合 R1 条件的任务仍只能等 A 回来。网络断开但没有验证旧进程存在、没有实际提交竞态，不足以通过此项。

### DV-05 旧机重连与迟到材料

- [ ] 在 DV-04 后保持 B 的新版本已提交；让 A 恢复网络，重放旧任务状态、保存点发布请求、上传和模型请求，包括重复/乱序的同一回执。
- [ ] A 保留一份断网前已产生但未确认的独有改动；校验其只能成为有来源的待核对候选，不能恢复旧正式写入权。
- [ ] 分别测“账号仍有效、旧尝试过期”和“账号/设备已撤销”两种情况；后者必须拒绝旧凭证，不因资产归公司就绕过撤权。

**通过：**B 的当前状态与版本不回退、不被覆盖；旧重复回执不产生第二次效果。有效身份重新鉴权后可按限范围上传旧证据；撤销身份的材料须由有权接管人另行导入。候选保留不等于正式发布，不能显示任务已完成。

**失败：**重连即恢复旧租约、同步最后写入覆盖 B、覆盖前未经内容/版本确认，或撤权身份仍能读取新保存点/调用模型/发布成果。

### DV-06 两端文件冲突与无冲突对照

- [ ] 从同一已确认基线拆两个合法子任务/候选工作区给 A、B，各自修改同一文本位置和同一二进制表格，等待系统自动保存双方候选，不让两个有效尝试直接写同一活动目录。
- [ ] 第一份集成后再提交第二份，强制其预期基础版本已过时；同时保留一轮 A/B 修改不相交内容的对照。
- [ ] 用获授权审阅选择或显式合并形成新版本；人类编辑走接管/导入版本，不绕过活动工作区边界。

**通过：**双方候选自动保存且均可读取；冲突明确保留，不覆盖、不假装二进制已自动合并。无冲突工作真实并行，只有目标集成点局部协调；合并后关联新的验收版本。

**失败：**最后上传者获胜、任何一方已确认版本丢失、静默覆盖/擅自宣称合并成功，或为躲冲突将所有任务排成串行。允许人工解决内容冲突；这不违反自动保存要求，但不得要求人工操作才能保住双方版本。

### DV-07 自动重试、容量和假成功

- [ ] 保留控制面，分别阻断存储上传、阻断任务关联、丢弃关联确认回执；再暂停并恢复本地回传服务。观察恢复后是否无需员工操作自动重试/查询同一逻辑保存的结果。
- [ ] 校验同一冻结版本重试不换成新的业务操作；更新的工作快照有新的版本，不能混用旧请求 ID。模拟缓存接近限额、磁盘满和保存持续超时。
- [ ] 在待上传/待关联时执行正常保留清理流程，检验不能误删唯一副本或引用中的对象。B 下载阶段注入缺失/损坏对象，校验失败不得激活执行。

**通过：**有界退避与自动恢复；失败立即可见，达到界限停止新增工作，已预留在途输出也不造成无界增长。权限/代次有效时自动补确认；失效则安全核对而非盲重试。缺失/损坏拒绝恢复且不报成功。

**失败：**需要员工点击“补交/重试”才能保存、无限积压、满盘仍运行且丢字节、重试产生重复业务效果、清理破坏已确认点，或文件损坏仍展示可接手。工具/引擎崩溃可能不能继续原进程，但已冻结保存包的回传恢复不能依赖原模型进程活着。

### DV-08 已完成动作、未知结果与权限负例

- [ ] 保存 CP1 后在中央创建一个子任务/资产，丢弃 A 的结果回执，再断电；B 恢复时必须查到并复用已提交效果。
- [ ] 对隔离测试接收端注入“动作已发生但回执未知且无法查询”的 R2 反例；不得自动再做一次。模拟启动许可已提交而 ACK 丢失，不能当作没开始。
- [ ] 独立重置环境，在 B 下载前撤销权限，以及下载完成但新尝试激活前撤权；分别测试设备有权/管理人无权、管理人有权/设备无权。重新给予合法双授权且其余条件满足后才允许恢复；账号属于管理员组不等于 Agent 获得该权。授权拒绝不能靠旧保存点中的权限快照绕过。

**通过：**确定已完成的不重放；未知动作阻塞有权核对，不伪报成功；无权 B 不能取得数据/启动/调用网关。已经合法下载的字节不能承诺凭撤权远程抹除，但不得再授予执行或新资料。

**失败：**重复效果、换 attempt ID 绕过去重、未知动作自动重试、无权恢复。R2 正确阻塞只算安全负例通过，不能抵消 DV-02/04 中 R1 必须能自动接续的正向要求。

## 5. 总体判定：什么会证伪当前方案

| 结果 | 判定 |
|---|---|
| 已确认版本丢失/损坏、混合保存点、旧写覆盖、重复业务效果、权限泄漏 | 发现一次即 FAIL，停止依赖该能力的建设；不以多数通过/重跑直到成功掩盖 |
| 依赖员工手动保存/提交/补传，或模型自行决定是否保存 | 自动保存要求 FAIL，即使最终能接手也不能通过 |
| 受支持 R1 工作无法在冻结时限内自动形成保存点/接续，只能等待原机 | 可用性 FAIL；安全拒绝不能冒充已满足工作接续 |
| 未确认改动在约定界限内未找回，但清楚提示并从完整点继续 | 不自动判完整性失败；真实记录损失。若已确认内容也丢，或实际超限，则 FAIL |
| R2 未知结果、授权不足、全部合格设备离线 | 正确阻塞可作为对应负例通过，不宣称该任务已恢复；不允许扩大设备权限或中央代跑 |
| 缺少试验参数、必要切点/日志/权威证据或测试未执行 | NOT RUN/BLOCKED，不是 PASS；缺测不能批准下一阶段 |

全部 DV 子样本达到约定重复次数、无阻断缺陷且证据可复核，才标“最小双设备实验通过”。仍不代表完整 WC/DC、全部操作系统、负载性能、灾备或生产条件已经通过。失败应定位是适配/实现问题还是架构假设问题；修复后用同一条件复测。若必须手动保存、中央执行、原始 Key 下发、放宽权限或牺牲并行才能通过，则否决当前技术组合，返回方案评审。

## 6. 最小建设与执行顺序（本轮不执行）

以下是 G4 的接续子流程，不替代总体 [G0→G1 预检→G2 版本生效→G3 权限撤销→G4 接续→G5 合流](DISCOVERY-BASELINE.md)。G2/G3 的安全与版本前提先通过，再计分 DV；无需先实现完整产品 UI。NG/DV 两台原生设备与完整 DC/WC 第三不合格设备负例分别记证据。

1. **前置确认：**确认两台 Windows 11 x64 原生范围、参数、版本/摘要、合成资料及专用设备；按原生核查的多协议要求做两端能力预检沿 Multica 官方 daemon DSH 路径核查，必要时比较备选后冻结一个载体，核对设备与中央相互独立；这里不要求 NG-06 已接通。没有真实试验/实施授权不进入下一步。
2. **建立最薄验证链：**仅接任务/设备、本地 harness、公司模型通道、自动保存与恢复；读取上述阶段证据并提供可控故障切点。无须先做完整群聊、面板和业务连接器，必要状态用受控诊断页/日志呈现；正式任务权威不得用 mock 替换。建好必要接入后完成 NG-01–06 全部验收，NG-06 验的正是这条真实链，全部通过才进入下一步计分 DV。
3. **先跑 DV-01：**自动保存和并行基线不通过，先修它，不靠手动提交继续演示。
4. **按 DV-02→DV-05：**确认后断电→保存中断电→断网旧进程存活→旧机重连，逐步证明恢复与旧写隔离。
5. **完成 DV-06→DV-08：**冲突/对照、自动重试与资源失败、效果/权限负例。保存中断子切点和晚提交竞态不可省略。
6. **独立核对证据后出结论：**报告每个子样本、实际损失/耗时、未通过项和适用范围；由 Ethan 评审是否进入完整 P0/P1，而非自动开工。

本方案的审查重点已分别落到用例：事件丢失/长工具→DV-01/07；中央提交但 ACK 丢失→DV-02/07；半开连接/预检后迟到提交→DV-04/05；文本/二进制及无冲突对照→DV-06；保存后效果/下载后撤权→DV-08。没有遗漏项被“以后再处理”隐含跳过。
