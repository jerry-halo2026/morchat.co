# morchat MVP 分阶段建设顺序

> v14 设计评审稿，2026-11-05。按中央协作控制、员工本地完整 harness、云端模型与公司统一 Key 管理重排；撤回中央 harness 优先及服务器默认执行员工任务。只规划后续建设，本轮不执行代码、安装、部署或业务调用。没有试点规模与契约证据前，不承诺固定周数。

## 1. 建设主线

先对授权设备池、群上下文、同机/跨设备并行及任务文件一致保存/换机接续做可证伪验证 → 打通真实客户端协作与本地执行切片 → 完成跨部门面板、资产与用量闭环 → 双业务场景和规模/故障回归 → 内部发布。并发正确性不是 P3 才补的性能优化。

MVP 是 P0–P3 的合计交付。P1 可演示可试用，但不是完整上线；不得只演示“能聊天”“能点浏览器”或“能生成日报”就宣布平台完成。工作流/低代码平台不是任何阶段的前置依赖。

完整产品主线为“目标→人机团队→拆分认领→协作交付→复盘沉淀→下次复用”，详见 [产品流程](D:/dev/morchat.co/docs/PRODUCT-LIFECYCLE.md)。Bot 就是 AI 同事，工程保持 Agent 名称。组织助手 Bot、Bot 模板/岗位包、小队模板和 skill 改进是同一条链上的能力；模板不等于实例，run 不等于新 Bot，不是四套另建系统。最小案例评估进入 P2，不推迟到 P4。

## 2. P0 设计、最小接入与证伪

### 前提与最小自建范围

本轮仅文档修订，不启动实现。后续另获实施/实验授权，再按 [Discovery 基线](D:/dev/morchat.co/docs/DISCOVERY-BASELINE.md) 冻结当期测试契约、分派 owner、建立真实仓库/任务卡与验收证据。

首版只建 B01–B08：企业权限桥、统一协作客户端、组合与受控发布、版本证据与授权资产、Windows 本地 runtime、设备派发 adapter、自动保存/双设备接续桥、公司模型网关/成本回执。它们是八个工作边界而非八个服务；直接复用、外围适配和 Paperclip 原生扩展见基线 §1，禁止用“薄适配”掩盖原生强制点/PCWS 的工作量。OpenMausBot 可不成为运行依赖；Multica 只参考，不拼接第二任务/skill/成本后台。

### 顺序与交付

1. G0：明确当期 D01–D10 输入、C01–C08 的 TEST-FROZEN 子集、版本/参数/正负 fixture、实施卡和独立审核人。先允许最小验证实现，不要求应用已存在。
2. G1：在员工账号有本机管理员权限、Agent 仍受限的真实前提下，验证 Windows 实际 build/tier、DSH+ACP+MXC、公司模型两个协议、密钥与本地隔离、取消/真实停止预检，建立真实 Paperclip 身份/任务最小链路；不能拿服务器 local adapter 冒充员工执行。
3. G2：版本生效先证伪。验历史保留/GC、导入包冻结与副作用、原生条件激活/回退、候选回写、最终技能集合、per-run 精确物化及实际消费，覆盖 PC-06 与 LC 版本子集。
4. G3：撤权再证伪。覆盖源材料、测试快照、历史、缓存/回执、原生内部服务、运行中与离线重连；关闭未启用入口。安全更新不被历史版本/旧 session 绕过。
5. G4：真实 remote adapter 与 PCWS 员工节点最小扩展接通后，完成 NG-05/06，再跑双向 DV-01–08，补 DC-01–08/WC-01–12。NG/DV 两台 Windows 足够做对应最小样本；完整门禁另需第三不合格设备。task-only、mock 或人工 Git 不计通过。
6. G5：在同一冻结组合收齐 PC-01–20、NG-01–06、WI-01–10、DV-01–08、DC-01–08、WC-01–12 及 G2/G3 的 LC 契约子集，形成 BUILD-FROZEN 与补丁/升级回归基线。

具体子样本及 FAIL 条件只按 [Discovery §4](D:/dev/morchat.co/docs/DISCOVERY-BASELINE.md) 与所链接专项，不重造六套测试系统。实验参数唯一来源 [DV §3](D:/dev/morchat.co/docs/DUAL-DEVICE-VALIDATION.md)，尚待事前签认；测试后不能放宽。原生 NG-06 需要最小节点实现，不能要求先通过 NG-06 才允许写其验证适配，避免循环前置。

### 退出与失败分支

P0 使用合成数据/最薄验证入口，不要求先完成 P1–P3 全部客户端体验；完整 US-01–21/LC-01–12 留给最终产品验收，但版本/权限/接续的硬契约不得拖到 P2 才研究。实际接口、源 SHA/patch、样例与报告经过提供方/消费方/安全审核后，才从 TEST-FROZEN 升为 BUILD-FROZEN 并解锁对应产品实现。

FAIL、NOT RUN、BLOCKED 都不算通过。先判配置/适配/原生扩展/架构失败并复验；身份代理、原子认领、导入、内部写回、最终准入/证据读取缺 hook 时评审最小 Paperclip patch，不能用共用管理员凭据或第二权威掩盖。原始 LLM Key 不下发、无个人计费回退；首版第三方业务只读，本地工作写和公司资产回传另授权。

若只能靠全局/设备单任务、扩大设备/内容权限、下发 Key 或中央 harness 代跑才成立，否决当前组合并提替代路线。工作区/venv/worktree 不作为安全隔离保证，迟到成本和未知效果仍要对账。模型/日志/上传容量与控制链、备份恢复及撤权必须保留既有专项门禁，不因新增模板演示而删减。

## 3. P1 客户端与执行最小纵向切片

### 交付

- 一家公司，部门/员工/AI 名册、登录和最小资源权限；账号开通明确业务、操作、AI 和费用范围。
- 同一个桌面客户端：群聊、消息、@、任务卡、我的工作、最薄个人/部门进展面板；员工与负责人均可建群，敏感内容与私密群独立授权。
- 可选组织助手和等价人工入口；在获授权范围受理目标、推荐已有人员/AI、预览组队/拆分差异并受控应用。两个最小岗位包对应的 Bot 模板示例、具体 Bot 实例、一个小队模板/实例；优先已有包与名册，显示来源/能力版本、权限/工具就绪状态与部分失败；不建市场、任意插件编辑器或新任务引擎。
- 一条目标 → 同群多人多 AI → 明确派单/认领 → 员工助手默认设备、公用 Agent 自动选池 → 隔离并行/授权上下文交接 → 公司资产交付的通路；Paperclip 是任务/run 权威，长执行不阻断消息/取消/状态。
- 公司云模型连接与受控访问路径；原始 Key 不下发客户端或任务代码环境。保留最小用量回执、预算准入和未知费用状态，不到上线末期才补。
- 客户端完整 runtime：受控准备/固定版本 harness、独立公司配置、设备绑定/撤销、本地模型—工具循环、独立浏览器、受控 Python/Node/文件。最小设备池策略/原子领取/并行隔离/局部资源锁、公司模型准入、暂停/短租约、离线分类和回执对账同步进入切片。
- 文件第一次产生就有来源、公司归属、权限和上传提交状态；Git 与普通目录的自动中间态保存/有界重试、完整清单及真实换机接手从本阶段进入，不依赖员工手动提交，不等到最终成果才上传。按 [任务与工作空间接续](D:/dev/morchat.co/docs/WORKSPACE-CONTINUITY.md) 区分业务/执行/保存/验收状态；未经确认不能显示可接手，未经验收不能显示正式交付。
- Bot 配置历史和 skill 版本直接复用；指令/资源自动不可变快照与能力清单在首次生效即记录，run 留实际版本证据。模板/能力升级不换 Bot 身份，也不静默改实例，不等到 P2 才补历史。
- 持久待办、幂等请求、同步延迟和失败可见；受限运行诊断入口不要求员工另登参考产品。
- 输入/产物版本、业务负责人、接收/验收责任从首条任务可见；交接回执与退回修改可用。复盘先能关联来源、纠错和基础版本形成候选，不自动发布。

### 退出条件

两名用户用各自账号完成一条工作；未安装个人 Agent CLI 的干净试点设备可由客户端准备完整 runtime，harness 进程和工具确实在本地，公司网关转发至云模型。中央不代跑员工 harness。本机浏览器、Python、Node 和文件上传逐项有证据；同机无冲突任务实际重叠执行，公用 Agent 在池内两设备可自动选择、入群但未授权设备不可执行，等待人释放可释放资源，不要求先接真实办公软件。

同时证明无 Key 下发、越权目录/设备及未经批准的生产外部写请求被拒、重复建单/工具回执/成本回执不重复生效；一次断线/重连与等待人期间重启不丢任务；公司确认保存后原机断电，获授权新设备能从一致版本继续，确认前缺口明确。输出尚未归档时不能显示交付完成。本阶段可先用合成或人工提供资料，不依赖千川。另验证员工与负责人都能发起；关闭组织助手仍可手工完成；重复组队不多建对象，岗位未就绪不执行；保存不替代验收。

## 4. P2 团队协作与资产用量闭环

### 交付

- 跨部门组队、目标/子任务依赖、认领冲突、转派与阻塞责任。
- 人→AI→人和 AI→AI 跨设备交接，传递获授权任务/资产而非个人电脑身份；父任务等待子任务释放执行槽。重复唤醒、循环、资源锁、取消和未知结果有确定处理。
- 断线/休眠/重连先核对租约与回执，旧代次不覆盖当前任务、真实费用仍记账。员工助手离线等待本人设备；公用 Agent 未启动自动改选、满足 R1 隔离/安全重算或 R2 可信终止且已对账的恢复边界自动接续、未知副作用阻塞核对；资源绑定无法迁移或全池不合格就等待，无服务器兜底。
- 内嵌个人、部门、公司和跨部门面板共享同一任务事实：同部门普通任务明细默认可见，跨部门开放获授权项目/任务及对应进度、交接、阻塞和交付；敏感内容/私密群另授权。
- 公司资产目录、基本权限检索；员工和负责人可自然语言辅助创建/修改获授权 Bot 模板/岗位包与小队模板，形成版本差异；复用原生模板与历史，不开发平行模板库；发布权独立，实例不静默热更新，重新实例化再验权。
- 复盘→候选→原生案例/测试运行→业务评审→受控发布→新任务实际复用→撤回/退役。复用 Paperclip 正文、版本和测试执行，只补企业评判与传播政策。至少原案例和不同输入，失败不发布，版本实际加载可验证，重要评测证据不随短期 issue 清理丢失；设备更换不改变资产身份。
- Paperclip 成本与已支持预算机制接通角色面板；补部门/项目与责任人归属快照、按权汇总、迟到/未知回执对账。首版个人/部门做归集，不默认承诺其独立硬预算。
- 成员加入/退出历史权限、降权后的索引/缓存/后台任务/设备租约处理、离职接管与个人连接替换。过期租约只获限范围证据上传、已撤销身份拒收旧凭证；异常/未知结果由具任务管理和证据权限的接管人核对并批准；已验证安全条件的池任务按预授权策略自动接续。交接包含中央资产、检查点、依赖/版本和未完事项；新设备重新授权并开接续 run，不复制个人 Cookie/Key，不保证原始 CLI 会话可迁移。

### 退出条件

两部门、员工助手与公用 Agent、至少两台授权池设备完成并行协作，并用未授权/数据不匹配设备验证拒绝；同部门非参与者可读普通任务，跨部门参与者可看获授权业务流转但看不到整个对方部门或越界依赖。群卡、待办、面板和资产同源或明确提示延迟。

完成一次 skill 改进与另一员工新任务复用、一次评估拒绝、过期候选冲突、撤权拒绝及回滚验证；岗位包/模板维护与发布权限分别可测，换人或离职接管后公司版本仍可使用；真实调用包含责任归属与费用状态，重试和失败调用不漏记，不因员工调岗重写历史。不通过资产、设备与权限门禁不得宣布上线。

## 5. P3 双场景业务验收与内部发布

### 交付

**场景 A，千川只读分析：**公司连接器读取获准账户和明确口径的数据，形成分析任务；员工本地 harness 获准读取输入，经云模型分析并在本机生成文件，员工反馈后成果归档。中央连接器的数据读取不等于在中央运行分析 harness。先用选定账户验证再扩展；保留已有 45 户资料，不将数量作为平台常量或唯一上线条件。不执行预算/启停生产写入。

**场景 B，跨部门活动方案：**不调用千川，运营/内容员工与 AI 完成目标拆分、不同员工设备上的完整 harness/工具与人协作、文档交付、反馈、知识/skill 沉淀和复用。关闭千川连接器后仍能完成。按六步产品流程使用岗位包/小队模板，员工和负责人分别发起；再换一名员工和不同输入，核对所用模板/skill 版本与验收证据。

统一演练模型 Key 轮换、设备吊销/离线、调用与文件防重、旧租约回执、权限撤销、未知结果、迟到用量、预算准入、离职交接和备份恢复；确认客户端/runtime 安装/更新/回退、兼容版本和运行手册。

灾备演练增加旧中央快照恢复时设备仍在线、旧写迟到、凭证已撤销和业务效果已提交的组合：先隔离新旧控制面执行权，使用不复用恢复世代，重建当前授权/效果并对账后再派发；不得复活旧权限或重做已完成操作。

按 P0 目标压测同机多任务/子 Agent、跨设备并行、模型 429/网关限流、集中日志/上传/面板推送及队列满额；验证等待释放槽位、本机办公影响、背压和失败可见。不用“本地执行”代替容量证据。本轮两台 Windows 11 x64 均须有对应原生证据。Mac 仅保留平台接口/资产格式准备，其实现与原生/跨系统验收后续单列；不阻塞 Windows 首轮，也不冒称其他系统/build 已支持。

### 退出条件

PRD 的 US-01–21、LC-01–12、DC-01–08、WC-01–12 全部有证据（含自动保存的 DV-01–08 子集），工程基线的运行安全门禁通过；无权内容不能借模型、面板、费用明细或本机工具泄露。恢复后能继续未完成任务并访问正确版本/权限的成果；确定的性能、费用、撤销时限与恢复目标经过实测。业务团队试用阻断项解决后，才称为首版内部 MVP。

## 6. P4 后续独立立项

按内部使用证据选择：更多操作系统、通用桌面操作、在首版案例验证之上的批量/统计 skill 评估与更多连接器、原生移动端、部门/个人独立硬预算；千川生产写入及资金机制；对外开户、计费和多租户验收；必要时接 Coze 云。

常在线执行节点/云端执行池不列为当前默认后续建设项：Ethan 已确认全部合格员工设备关机后可以停工；只有将来明确提出无人在线仍要工作的需求才重新评审。低代码画布、流程生成器、Restate 等不因旧稿提及就自动建设。本地大模型和完整离线 AI 不是当前方向。任何扩展都需重新检查许可、数据和权限边界。

## 7. 并行建设与合流

只按 [工程基线 §5](D:/dev/morchat.co/docs/ENGINEERING-BASELINE.md) 执行：文档权威→契约冻结→模块单 owner→任务卡/写集/依赖→隔离工作流→独立评审→串行集成→目标基线回归。P0 最小切片可按 TEST-FROZEN 实施；产品并行须依赖相应 BUILD-FROZEN，不允许先各写一套再接线。

同一 Superpowers SDD 计划一次一个实现者；独立工作包才可各自计划/台账/worktree 并行。共享接口、迁移、锁文件和 Paperclip patch 是单写者热点；worktree 不消除语义冲突，无法隔离就串行。模型显式按机械/集成/高风险分级，任务与提交关联真实 agent ID，详见工程基线。

千川连接器可在 P1/P2 准备，不阻塞通用协作；资产、权限、公司 Key、最小计量与自动保存从首条切片存在，不先裸跑再补。没有真实资料/部署授权不得执行外部验证。
