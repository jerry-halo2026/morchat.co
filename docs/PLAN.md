# morchat MVP 分阶段建设顺序

2026-11-06。当前设计：**Multica 单底座，Windows 本地 DSH，云端模型，中央公司治理**。Ethan 已批准 R1-AUTH-r1 三切片连续开发；准备后继续验证、最小修复与首轮验收，不包含未批准的真实模型费用/生产部署。C01–C08 仍 DRAFT，见 [Discovery](DISCOVERY-BASELINE.md)。

## 0. 当前主线与范围

先跑通统一客户端和 Agent 协作，再接知识库/多维表 CLI/MCP。公司内部自托管，保留未来公司边界，不先做外部收费/白标/市场。千川只读只是首个样例，另需一个非千川业务流程证明通用性。

### 0.1 暂缓的连接器

企微新版 CLI、腾讯文档企业 SaaS 的官方入口已核查；无测试租户/员工授权，既有文档编辑、行字段权限、撤销和离职接管全部未实测。飞书仍是已接受的内容主存储候选，未决定替换；Docmost 自托管备选，smart_table/ima 保留研究。不开这些功能时 KD-01–08 不阻塞核心协作；一旦启用必须先满足相应门禁。不得借暂缓跳过平台附件、受控缓存、Bot 上下文与资产交接。

### 0.2 开发顺序不等于重新选底座

Multica 整套产品直接复用，包括我的工作、项目/看板/甘特/状态工作流、Issue 多人评论、Squad、Inbox、权限/撤销基础、daemon/DSH/附件/用量/VCS；Paperclip 只治理参考；OMB 只协作规则和经审独立子件。没有 Paperclip 后端集成阶段、OMB 整体对话框抽取阶段或新任务系统建设阶段。v4 只列体验要求，不要求重建其菜单/页面；证据见 MULTICA-BASE-EVALUATION 的原生优先复核。

**本轮新fork复核不增加阶段：**三手册全文和REA卡已核，重复建设项（第二claim/adapter/runtime/账本、首轮entitlement重写）撤回；差额见REFERENCE-REUSE §7–8。候选新SHA164290ee…未运行，新旧样本结果分开。D:/evose-audit为Ethan的只读参考；主目录已启动Multica切换但未与本树合并，现有morchat.co已确定为唯一产品仓，同仓不同工作树的正文尚未合并；D01只收敛接入与基线，不再选仓，不能混用同名MC编号。

**D02 产品政策已确认、验证尚未运行：**一公司一个 Workspace、部门/资源细权，项目授权默认覆盖后续普通任务、私密单授。MC-S1-r8 的 MC-01/01G 按 MINIMUM-CHAIN §9（NM-ACL-r1）先用合成身份做无模型权限矩阵，覆盖持久搜索/WS/附件/通知、受托身份与选机判权；通过后按 R1-AUTH-r1 继续 Bot 文本/资产链实现；真实调用只等待对应 S1-C 预算批准。负责人角色不代替内容授权；权限入口未闭环不放真实资料。不增阶段、不先建设完整组织后台或权限微服务。

## 1. 开工准备（G0）

唯一产品仓已定为现有 morchat.co；GitHub 远程空仓已创建并关联。MC-00 已启动，根级导入完成，本地检查与缺口见 [执行记录](tasks/MC-00-results.md)；Actions 尚未运行、未推送。D:/dev/multica 是固定上游来源而非第二产品仓；目录/Git/检查命令/公开上传规则唯一正文为 ENGINEERING §8–§11。工程准备自身不以前置全部 C 已冻结或 CI 已存在为条件，避免 bootstrap 循环；产品任务不因此豁免。

1. 按 README 确认唯一权威文档和当前目标 SHA；绑定 B01–B08 owner、审核人及热点单写者。
2. 按最薄纵切冻结 C01/C02/C04/C05/C06/C08 的测试样例与拒绝规则；C03/C07 可并行设计，依赖共享字段先联合签认。所有契约先 DRAFT→TEST-FROZEN，不以“文档写了”当实现成功。
3. 任务卡写清目标、非目标、写集、原生入口、版本、依赖、幂等/权限/失败语义、测试与证据、合并顺序；正式实施另需授权。
4. 精确版本、Windows 安全组合、公司网关、设备池、保存/恢复阈值等按 Discovery D01–D10 定案，不由各 agent 自选。

### 1.1 当前长任务：准备到首轮三切片开发验收

**范围及授权：[R1-AUTH-r1](ROUND1-DELIVERY.md)**。顺序 R1-00 基线收束→R1-01 多人协作权限→R1-02 本地执行成果用量→R1-03 Leader/版本/撤权/双设备可靠性→MC-08 同一版本独立验收。执行总计划见 [连续计划](superpowers/plans/2026-11-06-round1-continuous.md)，实际状态看 ACTIVE。
准备、实验与最小产品修复在同一授权内连续推进，不把“准备就绪”当 Goal 完成；所消费子集先 TEST-FROZEN，再实证修复到 BUILD-FROZEN，不要求全部远期功能同时冻结。
已准本地提交、专用集成分支和明确隔离合成库；不需再次逐步询问。main、公开 push、真实资料、生产、外部业务写入和未批准模型费用仍禁止。旧阶段正文里的“另获实现授权”现由 R1-AUTH-r1 对上述范围满足，未消费功能仍不放行。
缺模型额度/第二设备时只阻塞相应真实验收，继续无依赖开发；未测不算通过，不宣称首轮完成。无合格设备等待不是要求中央代跑。下列 P0/P1–P4 保留为能力及发布验收总纲，不新增第四个开发切片。


## 2. P0 核心契约证伪（G1–G5）

顺序为 **原生路径/附件与桌面安全预检＋已失败委托边界前置回归→获权文本回传汇合→自动归档与验收纵切**；完整企业门禁仍保持 **G1→G2 版本→G3 撤权→G4 双设备→G5 合流**。前置复测 G3-R6 基础准入不是跳过后续撤权或降低既有安全门槛。每一步可做最薄界面，不能先铺满页面再发现协议不成立。

| 波次 | 最小交付 | 失败出口 |
|---|---|---|
| G1 | Multica 官方 DSH 路径和受限 Windows 执行、公司网关；修复附件裸 URL 权限旁路，收敛 Electron 安全；真实取消/工具边界；先复验 G3-R6 基础委托一致性，再按 MC-05G 先验文本汇合 | 需放开 Agent 全盘权、下发公司 Key、中央代跑或匿名资产才能工作，否决组合；已知 uploads FAIL 未修复前不放真实资料 |
| G2 | Bot/模板/skill 不可变发布与运行 pin、并发发布/回退、实际字节保留 | current/latest 漂移、旧 run 回写正式版、回退恢复旧权、发布无字节，FAIL |
| G3 | 当前权限贯穿消息/摘要/历史/文件/模型输入/提交；在线撤销与受控清理，离职资产接管 | 仅隐藏 UI、缓存/原始 URL/旧任务绕过、公司接手依赖离职者登录，FAIL |
| G4 | 原生队列上的授权设备选择、同机/跨机独立并行、自动保存、双设备恢复、旧机重连与文件冲突 | 手动 commit/上传才能接续、旧 epoch 写成功、冲突覆盖、全局单任务掩盖问题，FAIL |
| G5 | 同一冻结基线的适用 PC/NG/WI/DV/DC/WC/MSG/OP/LC 门禁及证据归集 | 关键 FAIL/NOT RUN/BLOCKED 不放行；模拟或单机成绩不外推 |

具体失败断言不在此复制，统一用 Discovery、专项参数及原始实验记录。已有 Web @→DSH 文件/回复/token 局部通过；新增合成组队实验已复现身份借权/创建归属 FAIL，单机成员并行回传成立但最终汇总未通过；自动归档和完整企业链未过，不能直接进入发布。

## 3. P1 客户端最小纵切

**入口：我的工作→目标/项目与任务→对话/任务线程 @Bot→本地执行→中央成果→验收/用量。**

- 使用预置岗位包/Bot/小队模板样例走最小实例化，不在 P1 建完整模板维护发布界面；版本生效与权限契约仍按 P0 验证。
- 同一 Multica 壳、设计变量、共享任务卡和数据源；员工/负责人/老板仅当前授权范围不同。
- 首页待认领/待处理/待回答/待审批/待交付；群对话与任务线程有明确关联；每个 Bot 原回复、进度、等待原因和成果可回溯。
- 按 PRODUCT-EXPERIENCE §3.7 将体验映射到完整原生页面；保留现成看板/甘特/工作流/Inbox，只限制未验证的写动作。预置输入和归档/验收补差，不另写只读壳。原生甘特不是新增前置工程；跨任务阶段/自动排程仍后续。
- 群中真人派工须结构化 @，禁普通评论自动回退；单目标 Bot 对话、结构化委派及依赖结果等其他入口仅按 C02 唤醒矩阵的显式获权意图执行；稳定 Bot ID、持久意图、防重和局部受理；任务负责人不被 @ 隐式覆盖。
- 自动归档是 run 交付流程一部分，不依赖模型记得上传或人工补传；公司资产有权限、版本/hash/接收回执。
- 追问/许可/补充/停止至少有可靠回执与状态；不支持同轮 steer 则明确下一轮/安全中断，不能吞消息。

退出：同一真实客户端纵切有正反例；Web 和 Electron 分开报告。P0 协议可先验证，不把 P1 全界面当 G0 前置。

## 4. P2 团队、版本与治理体验

- 在 P1 预置样例上补齐维护、受控发布与自然语言变更体验：两岗位入职包、两个 Bot 模板、一小队模板；真人负责人/员工组队、认领和有界多 Bot 协作，模板不携权限或私人记忆。
- 版本候选→评审→发布→实际运行→复盘→复用；独立旧 run 不热更新，回滚不复活授权。
- 部门目标/进度/风险/审批/用量面板，老板聚合其获授权范围；跨部门只显示获授权流转。
- 公司资产接手、受控缓存清理状态、离线等待和可恢复工作包可操作。
- 原生看板、Issue Workflow、父子任务 stage/条件唤醒、计划日期和 GanttView 直接保留；P2 只补企业授权/验收和已证实的阶段展示/准入差异，不把跨任务流程整体列自建。计划日期沿原生日历日，不把执行 timeline 当计划；自动排程另议，不引入第二工作流引擎。

退出：两员工/负责人从目标到复用完成六步流程；所有适用 US/LC/MSG/OP 验收完成。页面功能不能降低 P0。

## 5. P3 两场景内部试点与发布

合成资料先行，再经授权使用小范围真实资料。千川只读与一个非千川场景复用同一任务/权限/资产链。做数据库与私有对象备份恢复、升级回滚、撤职/离职、费用对账与员工设备关机演练。只能报告实测范围和限制，不宣称全平台/全供应商/多系统通过。

## 6. P4 后续独立立项

有实际需求和测试授权后再启用知识/表格（KD 门禁）、企微/飞书/腾讯连接器、工作流、macOS、移动端协作、更多 harness。移动端不默认执行桌面 harness；外部售卖/改品牌须重新核对许可。AI 自我升级首先是受控模板/skill 迭代，不是自动改平台源码和安全政策。

## 7. 并行开发与合流

以 B owner 和契约切片分工，不按 Paperclip/OMB/Multica 三套仓库分工。设计/测试准备可并行；共享权限/DTO/数据库迁移先定唯一写入者，独立 worktree 隔离文件但不能解决语义冲突。模型按任务难度与已授权可用模型选，不以多开 agent 替代依赖管理。审核/合并按 ENGINEERING-BASELINE 的门禁，不把本轮文档整理当门禁已部署。

## 8. 当前待评审的最薄任务包：MC-S1

详见 [最小链路契约与任务卡](MINIMUM-CHAIN.md)。撤回单人单 Bot 先验收的范围：首轮必须真实多人群、多 Bot 定向并行与结构化交接，群/上下文权限、逐目标派发回执、结果汇合及防信息风暴一并验证。单 Bot 仅用于排障。建议双人、双 Bot、双授权 Windows 设备；Web 联调后在 Windows 桌面做真实两账号验收，不以假成员或单人演示替代。此为 G1 协作验证面和 P1 用户路径准备，不改变 G2→G3→G4→G5 企业放行顺序。

v4 低保真已有两角色合成走查，不是真实双账号/双设备验证。当前推荐先在原生 Project＋父 Issue＋两个独立工作 Issue 的评论/小队完成多人协作；S1-D 已确认独立群入口后补；首轮不新造群表、不删私密权限要求。首轮/后续映射见 PRODUCT-EXPERIENCE §3.7；不沿旧 Paperclip＋OMB v1–v3 或 v4 合成对象直接施工。
