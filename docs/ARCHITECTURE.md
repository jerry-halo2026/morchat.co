## 1. 核心选择与替代路线

| 路线 | 取舍 | 当前结论 |
|---|---|---|
| 三套产品同时部署再同步 | 短期界面丰富，但三套身份/任务/记忆难统一，维护与授权成本高 | 不采用 |
| 全部自建 | 控制力强，但重复建设执行、任务记录与 skill 版本 | 不采用 |
| 自有企业层 + Paperclip 内核，其他项目选件复用 | 企业语义自有，已有执行能力复用；需要企业适配、必要原生扩展和契约测试，不能预承诺零核心改动 | Ethan 已确认方向 |

核心原则：一个产品、一套企业身份和权限、一份任务核心事实；先分派业务责任，再按授权选择执行设备。员工助手默认本人设备，部门公用 Agent 自动选择预授权池；同群不授予设备控制权，同机与跨设备均允许资源范围内并行。统一客户端内置可管理的完整本地 runtime；harness 模型—工具循环及浏览器/Python/Node/文件处理在员工设备，模型推理在云端。中央协作控制与公司模型访问层保留服务端，原始 LLM Key 不下发。工作流平台不在本期运行依赖中。

**原生范围更新（2026-11-05，以最新确认为准）：**首轮为两台 Windows 11 x64 原生设备，Mac 保留平台接口/数据契约准备，不阻塞首轮；不能用 VM/WSL/Docker 替代员工原生环境。公司模型接入面向 OpenAI Chat Completions／Anthropic Messages 等协议，不绑定某一模型品牌；Ethan 已确认 DSH 优先核查，Codex App Server 保留对照/备选，并非固定发行物和安全组合已验收。Paperclip Runner 只优先复用可验证部分，不因底座选择而承诺其 Windows 全链已可用。原生组件/快照入口缺口及前置门禁见 [原生运行与 Harness 核查](D:/dev/morchat.co/docs/NATIVE-RUNTIME-RESEARCH.md)。

## 2. 模块划分

下列是职责分解，不是新增建设范围。首版交付/复用清单归并为 [B01–B08](D:/dev/morchat.co/docs/DISCOVERY-BASELINE.md)，实际模块 owner/共享热点归 [工程基线 §5.2](D:/dev/morchat.co/docs/ENGINEERING-BASELINE.md)。原生服务内部路径可能需受控 patch；保持 Paperclip 唯一事实并不意味着只能外围 HTTP 代理。

| 模块 | 责任 | 边界 |
|---|---|---|
| morchat 统一客户端 | 我的工作首页、协作对话、内嵌公司/部门面板，以及组织、工作、资产能力、连接治理与设备入口 | 同一客户端按权限展示；浏览器辅助入口不自动拥有本机能力 |
| 企业与访问模块 | 复用原生公司/user/membership，扩展真人部门/岗位、群成员、AI 使用权、资源策略与离职交接 | 企业差异规则权威；不另建公司账号主库，不把人映射为 Agent；外部 IdP 映射依 C01 |
| 协作模块 | 群、消息、来源标签、待办通知、群与任务关联 | 讨论不是任务状态数据库；入群不自动授予所有关联资源访问权 |
| 任务接入模块 | 以真实调用者授权调用 Paperclip，处理外部 ID、幂等、并发和同步 | 不另建可独立修改的任务核心状态机 |
| Paperclip | 公司/成员、Bot 与 AI 汇报图、目标/项目/任务、Inbox/人工决策、审批/执行补充、技能/测试、文档/成果、包/导入、连接/动作审查、例程、运行/审计/成本及整体前端 | 按企业权限和已验证开关逐项开放；不是完整人事部门系统、harness 或企业设备管理器。全功能与实际路由见复用 §4.6 |
| 资产与改进模块 | 扩展原生成果/文档/skill 的来源、权限、保留、维护人、候选与业务评判 | 原生正文/版本/测试优先，不建平行记忆库，不把所有聊天自动发布为知识 |
| 连接与工具模块 | 复用 Paperclip Apps/连接引用、grants、动作审查与调用基础；补文件/千川等业务来源范围、只读策略和适配 | 不另建连接授权主库；工具动作、消息通道、模型凭据分域。调用时验权，原生工具批准也不能提升首版外部只读边界 |
| 公司模型访问层 | 云模型鉴权、供应商 Key 引用/注入、准入与限流、用量回执 | 原始 Key 只在受控服务与秘密存储，任务代码环境和员工设备不持有 |
| 员工本地完整 runtime | 管理固定版本 harness、公司独立配置、模型—工具循环、会话/事件与恢复缓存 | SDK/受控安装均可，但不依赖员工个人 CLI/Key；不自建第二套协作调度 |
| 中央设备池与派发管理 | 员工助手默认设备、公用 Agent 授权池、数据/能力/容量筛选、自动选机、领取/资源预留、租约、回执/撤销 | 扩展并关联 Paperclip task/run；入群不自动入池，选机不扩权，中央不代跑 |
| 工作空间与接续适配 | 优先扩展 Paperclip workspace/snapshot，关联公司 Git、版本资产、完整保存点与执行效果 | 对象先存、权威指针后生效；不增加任务权威，不把 Agent 公共目录当项目盘 |
| 本地工具宿主/工作空间 | 在允许范围运行浏览器、Python/Node/文件，落实进程/目录/网络限制与资源锁 | 随本地 runtime 运行；本地缓存不是任务或资产权威，无服务器默认执行池 |

自有中央模块优先模块化单体，客户端、API 与核心后台 worker 分开；Paperclip 独立运行，不预先拆微服务。中央 worker 可处理连接器读取/令牌刷新、资产校验/索引、审计和备份，但不启动员工任务 harness/浏览器/任意代码执行池。模型网关保留服务端以保护 Key，可独立扩容；它转发请求而非运行模型或 Agent 循环。Ethan 已确认无合格在线设备时可停止工作，不追求全部员工关机后的无人值守执行，也不为此增加常在线节点。中央继续按权接收/校验状态、业务数据、操作记录、版本、成果和用量，支持协调、治理及恢复，不接替本地任务执行。

明确撤回中央 harness 优先。首版采用中央协作控制＋员工本地完整 harness＋云端模型；无员工设备可执行则等待，不能静默回退服务器或未授权的同事设备。AI 摘要/skill 等启用的后台 AI 任务同样派到授权本地 runtime，不隐藏另一条中央执行路径。首版所有启用模型调用绑定真实 Paperclip 任务/run；明确提问可形成可见轻量任务，任务外自动标题等模型功能关闭，不另建无任务服务调用通道。详细定义见 [统一客户端与执行环境](D:/dev/morchat.co/docs/CLIENT-RUNTIME.md)。

Windows 首轮具体载体优先验证官方 ACP SDK＋MXC原生ProcessContainer，整DSH/每run独立边界；浏览器另域。Paperclip外部远程adapter与PCWS节点扩展是两处不同接入，不能只接任务就宣称文件可接续；真实费用以公司网关回执入原生账，不用ACP上下文占用代替。详见 [最小补齐与WI失败门禁](D:/dev/morchat.co/docs/WINDOWS-DSH-INTEGRATION.md)。

完整功能选取见 [复用 §4.6](D:/dev/morchat.co/docs/REFERENCE-REUSE.md)：Paperclip 原生公司/成员、人工决策、连接治理、技能工作室等不能因八项差异清单或五屏低保真未单列而被删除。保留能力不等于给全员开放：路由挂载、开关、真实身份/资源政策、执行准入均分别验证；原生例程与插件/实验功能按登记决定是否启用。

| 人工请求、执行补充与任务待办 | Paperclip interaction/approval/queued-comments/attention 及原生任务 | 首页、线程和面板是同 ID 投影；只扩传输/部门授权/整次协作控制，普通群未读另属消息域 |
| 应用连接、工具 grants 与动作审查 | 优先 Paperclip 原生连接/授权/toolActionRequest 等对象 | 企业模块叠加业务来源/动作范围与设备资格；模型网关不成为平行连接配置/授权系统 |
| 模型成本与已支持预算 | Paperclip 成本/预算记录 | morchat 保存部门/责任归属及授权汇总；网关回执须防止与 adapter 重复记账 |
| 模型供应商凭据 | P0 选定的公司秘密存储 | Paperclip/模型访问层引用；客户端仅用限范围凭证，不同步原始 Key |

## 4. 身份与权限

一次操作至少记录：公司、真实发起人、实际执行 Agent/服务、被委托身份、目标资源、来源任务/群、权限版本、关联请求 ID。

- 人类登录身份映射到 Paperclip 用户，AI 映射到 Agent。服务凭据不能替代真实调用者的业务权限。
- 权限同时覆盖请求入口、异步 worker、对象下载、检索、模型上下文和消息投递；不能只检查 Web 页面。
- AI 读取上下文取任务授权与资源策略允许的范围。向群返回内容时还要检查群受众，不能把有权读取的私密资料无条件贴进群。
- 禁止直接修改 Paperclip 数据库绕过规则。生产外部写入只经过获准业务连接器，本期千川只读。本稿 MVP 中本地浏览器/Python/Node 对真实第三方业务只开放已验证读取/导航/下载，不能绕过连接器提交、外发或修改业务记录；获准本地目录写入和公司资产上传是独立允许能力。测试环境写动作须用隔离账号与合成数据，未来生产写入另行设计。
- Paperclip 的原生授权不能准确表达某个业务范围时，先限制该入口；不得用“内部自用”作为绕过理由。
- 是否启用 SSO、如何代理用户及哪些 API 可准确传递身份是 P0 门禁；未验证前不承诺无缝单点登录。

### 4.1 部门面板与业务流转范围

面板是员工、负责人和老板的共同能力。已确认：部门内普通任务的明细与业务流转默认同部门可见，不以任务参与者身份为前提；负责人看明确负责部门的管理视图；公司管理角色看公司总览。敏感内容和私密群单独授权，角色级别与普通任务默认权限都不能解除这些限制。查看权限不自动授予编辑、分派或管理权限。

跨部门项目/任务采用显式、可撤销的资源授权。项目级授权覆盖授权项目内普通任务及其对应业务流转，任务级授权覆盖指定任务及授权交接信息；敏感内容和私密群仍需单独授权。参与者能查看授权范围内的阶段、进度、责任、交接、阻塞和交付，不只接收最终结果。跨部门面板是同一任务事实的授权投影，不增加第二套状态。

授权不扩展为对方整个部门，也不自动让参与者的直属负责人获得同样范围。依赖连线不自动传播读取权限，越界依赖只可使用已获授权的必要交接信息。部门归属、角色、资源策略及群受众共同决定最终访问，不只判断一个 department_id 或管理员标志；敏感来源/附件限制优先，普通任务默认可见不能覆盖来源限制。

查询投影、统计计数、导出、缓存、检索、模型输入与群投递均执行相应范围；无权内容不能通过汇总泄露。调岗或撤销授权后重算可见范围并失效相关缓存，历史工作归属不因人员调岗被自动搬到新部门。

首版采用任务核心字段一套 ACL，群消息和附件/资产分别一套 ACL，不做任意字段级脱敏引擎。普通任务可引用受限附件，但未授权者不看到附件名称、内容或可推断秘密的摘要；任务核心标题/说明/阻塞/交接字段必须本身可公开给其任务受众。若核心字段来自敏感源且无法证明安全，则整条任务转受限并重新检查投影/索引，而不是先公开再自动脱敏。经有源内容访问权和发布权的人确认，才可发布独立安全版本到普通任务；源权限不被改写。规则细节见资产文档。

### 4.2 账号、设备与模型边界

账号建立时明确公司/部门/角色、资源范围、AI/工具使用权、费用归属；设备身份、电脑使用权、浏览器会话、目录和网络能力单独登记授权。能看部门面板不等于能操作同事电脑；能使用公司模型不等于能读 Key。入群、委派或提升职位不会自动合并所有人的权限。

员工保留本机管理员权限已确认；平台管理 Agent 而非整机，不新增 MDM/全盘控制前提。正常 Agent/harness/工具不继承员工管理员权限；安装授权与运行授权分开。服务端在领取与执行时检查当前授权，本地执行器落实实际文件/进程/网络限制。仅设置工作目录或 venv 不足以隔离任意 Python/Node 代码。离线授权只能依靠有期限的租约，断联停止新动作；不能声称中央撤销能瞬时到达失联设备。

### 4.3 公用 Agent 的设备池边界

员工助手默认本人指定授权设备，不跟随群主或请求人的电脑；公用 Agent 仅在预授权池自动选机。入池要覆盖 Agent/请求范围、工具/目录、数据可承载性、资源/时段及撤销；设备和管理人必须均有对应资料授权，且与 Bot/任务权限取交集；个人设备管理员可能读取进程数据，不承诺从其手中隐藏已落地资料。资料增量、会话恢复和换机接续同样重新校验。空闲不等于合格，入群/角色提升不等于授权。共享的是获准群消息、任务/资产版本，不是员工全部模型会话或登录态。详见 [群协作与设备池](D:/dev/morchat.co/docs/DISTRIBUTED-COLLABORATION.md)。

## 5. 一次协作如何执行

目标到复用的业务契约见 [产品流程](D:/dev/morchat.co/docs/PRODUCT-LIFECYCLE.md)。组织助手、入职样例和复盘/skill 测试与普通 AI 一样创建真实 task/run，经获授权员工设备运行；不隐含中央常驻推理服务。助手是可选协调角色，可多任务隔离并行；手工入口不依赖助手在线。业务负责人/验收人不冒充原生 responsibleUserId，项目临时上下文进入 per-run 输入，不改共享 Agent 全局配置。

岗位包/模板只能声明能力需求，不能自带 grants、私人记忆或任意运行插件；版本组合按当前授权解析，已发布选择、原生 run 快照与本地实际加载分别留证。企业发布政策应覆盖原生 API/UI 和导入路径；仅隐藏按钮不构成边界。


1. 群消息先作为消息保存；用户明确建任务或接受 AI 的任务建议后，创建 Paperclip 任务并建立来源关联。
2. 任务创建使用幂等请求标识。跨系统失败保留待修复记录，通过查询/对账修复，不先给用户显示“创建成功”。
3. 认领/转派经过授权和并发检查，以 Paperclip 写入结果为准。接口能力不足时停止该能力上线，不另建暗中覆盖的状态表。
4. 中央先确定承接 Agent，员工助手路由本人默认授权设备，公用 Agent 自动选池内合格设备。权限/数据/工具/本地资源/容量检查后，设备原子领取并确认租约/预留，再启动完整本地 harness。云模型走公司网关；任务/run 独立会话与目录，同一 Agent 或同机可并行多个独立任务。创建/派发/接收/启动分别记录，契约 P0 验证。
5. AI 委派生成明确子任务/交接请求，绑定目标 Agent、parent task/run、输入版本和权限；普通回复不产生新的 Agent 唤醒，无承接者则待认领/分派。接手者验权，消息/控制与执行队列分离，长任务不堵住收件/取消/状态。循环、重复、并发与费用有可测边界。
6. 需要人或子任务结果时持久化等待并释放设备执行槽，发待办/交接通知；不让父 harness 占着唯一执行槽空等子任务，不依靠常驻模型进程等待。
7. 人回应后，按已确认的继续执行契约发起/恢复相应运行；不能假设任意中断都能原地续跑。
8. 上下文按授权快照和增量版本同步；目标/资料变化后交付前重新核对，过期结果不覆盖新决策。文件经校验、公司存储确认、版本与权限登记后为已归档；完整保存点确认且当前授权有效才可接手，另经业务验收才成为正式交付；本机生成但未上传显示待归档。结果回原任务/授权群，面板随权威事实更新，用量按同一运行关联记账。

## 6. 同步、故障与恢复

优先使用固定版本正式支持的事件或 API；若无可靠订阅，采用带游标/更新时间的轮询与定期对账。具体方式由 P0 验证确定。

自有命令与关联记录使用事务性 outbox/inbox 或等效持久化机制：至少一次投递 + 去重 + 重试上限 + 人工修复入口，不承诺跨产品分布式事务或业务 exactly-once。

进程重启后恢复待处理消息、待办和未完成关联。设备断联停止新模型/工具动作；在途操作尽力取消/保存检查点，中央撤销受短租约窗口限制。重连先核对权限、租约代次与操作回执，再决定续跑。旧代次不能覆盖当前任务状态；迟到证据待核对，真实费用仍幂等入账。

租约过期不证明旧动作未发生；未知副作用未查清不能自动重跑/跨设备转派，取消不等于回滚。仍有效的账号/设备可重新鉴权获得仅旧 run 的证据上传权限，失效账号/设备旧凭证全部拒收；材料进入隔离核对区，接管人必要时用自己获授权的恢复导入操作提交。异常/未知结果由任务管理权与证据访问权兼具的责任人核对并批准接续，运维权限不代替内容权限；公用 Agent 在满足 R1（共享写入已隔离且可安全重算）或 R2（旧执行/资源可信终止）的接续条件，检查点及其后已提交效果已对账且无未知项时，按预授权池策略自动接续，不需逐次人工批准。中央网关/供应商保留独立费用证据，不因设备撤销丢账。

员工助手默认设备离线则等待本人设备；公用 Agent 未启动任务自动改选合格池设备，已发 offer 必须可撤销且迟到领取被拒。已运行任务遵循安全接续/未知阻塞分类，不因离线或租约到期盲目重跑。默认从中央检查点和已归档资产创建接续 run，不承诺任何 CLI 会话能跨设备搬迁。加密有界本地缓存满额时暂停并提示；设备损坏前未上传的内容可能无法恢复。

不在本期引入 Restate、n8n 或通用 DAG 来解决所有等待；先用持久任务/交接和后台 worker。未来需要跨步骤长事务时另立决策。

提交时须验证当前代次、任务/输入版本及权限；网络发送前校验不够。优先权威端条件写入；若无此能力，所有相关入口须经过可证明的同资源顺序提交协议，跨系统超时待确认时阻止冲突换代/提交，不能释放进程锁就认定旧请求失败。不支持两者则否决候选接入，outbox/幂等不能替代这一门禁。该控制只约束同资源提交，不把 Agent 执行全局串行化。

恢复边界包含操作序号、已提交业务效果/结果引用与未完项，尤其对账检查点之后已成功的子任务/资产/文件，接续不重新执行已完成效果。启动许可提交但 ACK 丢失视为可能执行。数据承载与原始 session 资格贯穿运行，在增量资料/工具能力首次到达宿主前核验，身份/权限变化而无法证明旧会话安全时用当前授权重建。完整反例见 [分布式协作 §6](D:/dev/morchat.co/docs/DISTRIBUTED-COLLABORATION.md)。

### 6.1 分布式执行的容量边界

撤回每设备默认一个活跃执行链。跨设备默认并行，同机无冲突任务允许并行；每个 task/run 隔离模型 session、可变工作区/产物，多个客户端实例/子 Agent 共享真实资源配额。共享 Agent 的多任务可并行，不得用 Agent 全局会话、全局设备锁或反复改写共享 cwd/env 造成串行或串数据。

浏览器/GUI/同文件写入只对冲突资源互斥，等待人/子任务释放可释放容量和写锁；到安全点并持久化快照后释放，无法安全释放则资源阻塞。续跑重新授权/取锁/核对版本，避免多资源环形等待。按设备 CPU/内存/进程/IO、公司模型 RPM/TPM/预算准入及中央日志/上传背压设置有界容量，数值经 P0 测定；不将容量限制等同单任务。

消息/派单接收/取消/状态通信不被长执行占住，中央队列允许多设备并行领取。同一派单唯一有效领取与不同任务并发须同时成立。P0 即需真实同机/跨设备并发和池内故障验证，不能拖到 P3 或只模拟收件；[DC-01–08](D:/dev/morchat.co/docs/DISTRIBUTED-COLLABORATION.md)未通过不得宣称此技术组合可行。

### 6.2 文件、进度与换机接手

分工优先于迁移：目标拆成独立子任务，同一公用 Agent 可在多设备并行创建隔离 run；每个可写工作区只授予一个当前尝试，成果按版本汇合。同一任务需要并行探索时显式拆子任务/候选，不共享可变目录。

完整设计为 [任务与工作空间接续](D:/dev/morchat.co/docs/WORKSPACE-CONTINUITY.md)：保存 Git 未推提交/index/dirty/获准 untracked、普通二进制及任务/效果边界；受控一致采集、不可变上传、Paperclip 条件提交后才标可接手。保存成功、业务完成、正式交付不同。优先复用已有原生快照基础，员工节点 transport/企业协议仍待验证，证据见 [跨设备参考研究](D:/dev/morchat.co/docs/CROSS-DEVICE-REFERENCE-RESEARCH.md)。R1/R2 是本轮待评审的接续细化，不把租约过期等同终止。

## 7. 员工端与管理台

员工、负责人和老板的日常入口是同一 morchat 工作台，“我的工作”为默认首页，侧边栏进入对话等功能；面板内嵌，账号与资源权限决定功能和内容。浏览器辅助入口可复用界面，但无设备授权不具备本机工具。已确认 Paperclip 前端源码作为整体基础，适配后的任务/项目/详情是日常入口；OpenMausBot 对话源码接入同一壳。未经企业权限适配的原样管理员台仍仅供受限执行管理与诊断，不能直接开放给全公司。

业务面板读取 Paperclip 任务/运行投影 + 自有组织/指标信息。优先复用 Paperclip UI 布局、任务行、列表/看板/详情等源码，补薄组合，不另造等价前端；但不能以 iframe 嵌入就宣称权限统一。原生台的详情、搜索、下载、写操作和身份映射都必须单独检查。

OpenMausBot 对话展示/输入/过程折叠以源码抽取适配为首选；设备配对、电脑操作、文件处理或记忆组件另按依赖和许可选择；其 Client 模式不会同时启动本地电脑操作进程，需适配中央后台 + 保持本地完整 harness 的 runtime，不能原样使用关闭本地驱动的模式。若依赖整个 server/store，则评估适配与独立实现成本，不把整套产品拉进运行栈。Multica 不进入运行依赖。

详见 [面板与员工端](D:/dev/morchat.co/docs/PRODUCT-EXPERIENCE.md)。

前端按工作对象组织，不按参考项目组织：同一任务在首页、对话线程、工作面板使用同一 ID/详情和服务端状态；群消息/任务线程/执行详情分层，保留各 Bot 原回复。命令/事件适配集中在 B02，任务/run 仍唯一在 Paperclip；前端数据经默认拒绝的企业路由/字段白名单，保留原生数据形状及权限，不透明代理全部 API，也不向员工发管理员凭据。读权限在分页/计数前生效，附件直链、WS、缓存合并和迟到响应均纳入同一边界；不引入完整 OpenMausBot 前端 Store 或 Multica 后台。消息可见、上下文可读和执行唤醒三条授权路径，以及原生触发防重，以 [群协作 §4](D:/dev/morchat.co/docs/DISTRIBUTED-COLLABORATION.md) 为准。信息架构与共享界面规则只在 [体验 §3](D:/dev/morchat.co/docs/PRODUCT-EXPERIENCE.md) 定义，不在各模块另建导航规范。

## 8. 技术组织建议

- 客户端前端已选沿用 Paperclip 的 React/TypeScript 基础，接 OpenMausBot 对话展示源码；API/worker 优先 TypeScript；桌面壳优先评估 Electron 以便复用 OpenMausBot 能力，但不是已锁定选型。P0 对照设备授权、IPC/页面隔离、分发更新和许可成本选择，不在本轮安装。
- Postgres 保存企业、协作、关联和资产元数据；文件使用受访问控制的对象存储；检索先满足基本全文与权限要求，不先建设复杂知识图谱。
- Paperclip 的数据独立管理；可共享基础设施但不跨库直接写表。数据库迁移由各自模块/服务负责。
- 消息实时推送使用 WebSocket 或 SSE 的具体选择后定；持久消息先落库，推送不是事实来源。
- 云模型与工具连接由公司管理，开发测试与生产凭据隔离；原始 LLM Key 不进入员工设备或任务代码环境。Python/Node 是任务工具环境，不等于再增加 Python 核心后端；不会仅为拼装参考项目同时引入多套核心技术栈。

## 9. 为产品化保留的边界

公司范围贯穿表、文件、缓存、检索、队列、导出与凭据；账号和公司成员关系分开。首期仍只开放一家公司的部署与登录，不宣称多租户已验收。

平台核心没有千川账户、部门名称或某位员工身份常量。未来的 Coze 云以外部能力接入，输入输出、运行关联、数据传输与授权需再验证；公司资产和任务事实不随之迁出。

## 10. 后续决策与验收
