# morchat 整体架构与职责边界

> 2026-11-06，现行架构约束。Multica 是统一客户端、中央后台与唯一 task/run 调度底座；这是底座选择，不是企业能力已验收。B01–B08 为现行模块分工，实际责任人待绑定；C01–C08 均为 DRAFT，未冻结的接口不能直接分派生产开发。历史全文已归档，旧 Paperclip 实现绑定不再作为施工指令。

## 0. 当前事实与不可混淆的状态

- 已验证：真实 Web 明确 @Bot → Multica 原生任务/run → Windows 原生 DSH → 本地文件、线程回复和 token 记录。Electron 已构建启动不等于桌面交互验收；token 不等于真实货币成本结算。
- 未通过：自动文件归档。人工辅助上传后预览、鉴权下载、哈希验证通过，不能拼成自动闭环成功。
- P0 失败：本地 `/uploads` 原始地址匿名返回 200；鉴权 API 返回 401 不能排除静态文件旁路。桌面外部内容隔离也仍需收敛。未证明其他存储配置同样泄漏。
- 新增实测失败：对话组队可借 runtime owner 管理权，归属与发起者不一致；修正派工格式后单机成员并行回传成立，但截至采集未形成最终汇总。仅合成 API/CLI 样本，不算真实 UI/双机通过；详见 Multica 证据的合成组队实测。
- 未验收：完整部门/私密权限、撤权、双设备派发与接续、版本组合实际加载、公司模型出口及真实费用。实验只证明相应样本与路径，不推广成整个产品可用。

事实入口：[Multica 基座验证](MULTICA-BASE-EVALUATION.md)。`D:/dev/refs` 与 experiments 是只读研究/实验依据；不能把实验配置、历史候选或演示权限当生产默认值。

## 1. 核心选择与范围

一个产品、一套企业身份与权限、一份任务事实。先确定业务责任与 Agent，再选择有权承载数据的执行设备。优先沿 Multica 原生任务、Agent、小队、daemon、DSH、上传和运行记录路径补齐；不能把 Paperclip 的字段/接口换名后声称 Multica 已具备同样能力。

| 项目 | 当前角色 | 禁止的外推 |
|---|---|---|
| Multica | 统一客户端、中央后台、唯一任务/run 调度及企业扩展承载底座 | 原生存在不等于权限、版本、费用、恢复已通过企业验收 |
| Paperclip | 公司治理语义参考；经依赖、许可、测试审查的独立源码候选 | 不部署常驻后台，不保存权威任务/版本/成本，不整体移植前端/运行栈 |
| OpenMausBot（OMB） | 协作操作链参考；无隐藏运行依赖的纯 helper 候选 | 不引入完整 chat/store/runtime 或第二自动派工链 |
| 外部知识/表格服务 | 后期通过官方 CLI/MCP/API 接入的内容提供方 | 不成为另一个任务/群聊/Agent 调度系统 |

当前只做公司内部自托管，不对外销售或提供组织外托管服务。公司边界和未来部署隔离保留，但不是已经实现的多租户产品。品牌、分发及依赖许可按固定版本审查，不因内部使用忽略署名/NOTICE 等义务。

运行选择为中央协作控制 + 员工 Windows 完整本地 DSH/harness + 云模型。首轮两台 Windows 11 x64 原生设备；Mac 保留接口，后续独立验收。不依赖 VM/WSL/Docker、员工个人 CLI/订阅/Key。公司原始模型 Key 不下发。没有合格在线设备就明确等待，中央不代跑，也不静默借未授权同事设备。

## 2. 模块职责与原生优先

模块是职责边界，不预设新增包/微服务。优先完整使用 Multica，而非仅提取零散组件；精确文件、事务位置和新增路径经代码核查后才冻结。原生 AppRail、我的工作、项目看板/甘特、状态工作流、Issue 评论、小队与收件箱是直接复用对象；v4 不是替换这些页面/对象的要求。

| 模块 | 责任 | 边界 |
|---|---|---|
| B01 企业权限 | 身份映射、部门/岗位、普通与敏感资源、撤销和离职交接 | 复用成员/角色、Agent Access、runtime sharing、成员移除事务/断联/搜索草稿清理；只补公司全域编排、细权/资料交集、责任交接及清理回执，不重建身份或离职系统 |
| B02 统一客户端协作 | 原生客户端、任务/小队/消息入口、明确唤醒、通知与面板投影 | 一份 task/run 事实；不导入 OMB chat/store 或另建任务状态库；多人群缺口在同一后台扩展，不把讨论等同任务或唤醒 |
| B03 组合发布 | Bot/岗位包/小队的配置、指令、skill 版本组合及生效记录 | 原生能力先核查；缺失版本元数据需明示扩展，发布不带权限/凭据 |
| B04 资产版本 | 公司成果、稳定引用、不可变证据、来源 ACL、保留与接管 | 一份内容权威；自动接收、版本与授权缺口需实现验证，不能照搬旧快照语义 |
| B05 本地 runtime | 原生 daemon/DSH 接入、版本分发、进程/工具生命周期与隔离 | 不重写已支持的 DSH 适配器；不把 daemon 用户权限当 Agent 安全边界 |
| B06 可靠派发 | 授权设备池、容量、领取、租约、attempt、取消/回执 | 在 Multica 唯一调度中扩展，不另立任务状态机或第二调度器 |
| B07 工作接续 | 自动一致保存、效果对账、恢复与换机接手 | 复用 repocache/local_worktree、自动收尾 commit 和终态报告重放；它们不等于公司已确认工作文件。补周期保存/普通文件/分层与跨机恢复，不引入 PCWS |
| B08 模型与用量 | 公司出口、供应商协议、准入、原始用量/费用回执及结算 | 原始 Key 留中央；token/上下文使用不替代账单，费用只留一个权威结算路径 |

中央后台/worker 承担协作、授权、资产接收/索引、审计、模型网关和备份；不启动员工任务 harness/浏览器/任意代码执行池。后台 AI 摘要等功能若启用，也绑定真实 task/run 派给授权本地设备；任务外自动模型功能先关闭。网关转发模型请求不等于中央运行 Agent 循环。

新fork164290ee…已静态抽核，结论见REFERENCE-REUSE §7，尚未迁移实验成绩或冻结产品checkout。内部自托管可沿原生配置禁用Cloud entitlement，不必先改Provider/Stripe；企业权限与公司模型预算仍单独强制。

源码参考结构已只读核对：Multica 的 `apps/web`、`apps/desktop`、`server/internal`、`server/pkg/agent`、`server/migrations`；它们是上游结构，不是本仓已导入的工程。不得另造一套 TypeScript 中央后台只为延续旧设计。具体扩展位置、数据库迁移、API/event/错误形式待契约冻结；未验证的新路径一律标“提案”。

## 3. 数据权威与契约

| 对象 | 唯一权威与扩展规则 |
|---|---|
| 真人身份、成员与工作区 | Multica 原生身份/工作区基础 + 一套明确归口的企业组织扩展；外部 IdP 按稳定标识显式映射，不用姓名猜绑定，不把人映射为 Agent |
| 部门、角色与企业授权 | B01 企业政策叠加原生授权；管理、查看、调用、发布分别判定，不复制另一份可独立编辑的账号主库 |
| 任务、依赖、运行、执行身份 | Multica task/issue、run、Agent 是唯一核心事实；业务负责人、来源群等缺项按契约扩展，不假装旧字段原生存在 |
| 小队、消息与通知 | 优先原生对象和关联；讨论、任务评论、执行详情分层。投影/意图回执只记投递确认，不持有第二任务状态 |
| Bot 配置与发布组合 | Bot 是 Agent 的产品称呼，不增第二 Bot 配置库；B03 记录已发布组合及实际消费证据，原生配置能力不足时扩展同一权威链 |
| 指令、skill、文档与交付版本 | 优先原生内容对象；B04 明确每类正文的唯一存储和不可变版本/保留机制，不能假定已有历史回滚/测试工作室；活动日志或 hash 不是历史字节 |
| 设备 attempt/租约/保存点 | B05–B07 与真实 task/run 关联的扩展，不反向替代任务权威；原生字段映射必须核查 |
| 用量与成本 | Multica 原生运行用量优先；B08 补公司网关/供应商证据和幂等结算，唯一账本在 Multica task_usage/统计域及其同域扩展，精确 schema/事务待 C08 冻结，不部署 Paperclip 成本库 |
| 外部知识/业务资料 | 选定提供方保存正文/源历史/源 ACL；morchat 保存稳定引用、读取版本证据、责任人和任务审计，不默认全量镜像 |
| 千川等业务数据 | 保留业务域，核心任务只用通用资源引用和指标契约 |

B01–B08 对应 C01 身份、C02 任务命令事件、C03 组合生效、C04 资产证据、C05 runtime、C06 派发续租、C07 接续、C08 模型成本；**全部 DRAFT**。先冻结被当前切片消费的接口、正反 fixture 和所有权，再实现；不为完整系统一次冻结全部猜测。状态、编号和变更入口以 [Discovery](DISCOVERY-BASELINE.md) 为准。

每个映射保留稳定 ID、版本/事件标识及时间。模板不是实例，小队模板不是成员，run/attempt 不是新 Bot；版本回退不恢复旧权限、凭据或已撤销来源。

## 4. 身份与权限

一次操作记录公司、真实发起人、实际 Agent/服务、委托身份、目标资源、任务/来源、权限版本与请求关联 ID。服务凭据不能代替真实用户业务权限；prompt、角色名或工具参数不能自断言权限。

### 4.1 部门、跨部门与敏感资料

**原生实现边界已核实：**新 fork 164290ee 的 Workspace 是原生最高协作隔离边界，但不是已验证的安全保证；Project/Issue 主要按 workspace 成员放行，未发现项目/任务私密 ACL。owner/admin/member 不表达部门内容范围；普通 member 也不等于只读访客。Agent Access 管调用，runtime sharing 管借机，Squad 管分工，三者均不授予资料权限。个人 Chat 有 creator 边界，不等于多人私密任务；附件还有独立旁路风险。源码与官方依据见 [复用证据 §8](REFERENCE-REUSE.md#8-公司部门workspace-映射复核2026-11-06)。

部门内普通任务明细及业务流转默认同部门可见，不要求参与任务；负责人管理明确负责的部门，公司管理角色看公司总览。敏感资源和私密群必须单独授权，管理角色不自动解除限制。查看不等于编辑、分派或管理。

跨部门按项目/任务显式、可撤销授权，只覆盖获授的普通任务、进度、交接、阻塞和成果，不扩张为整个对方部门，也不自动授权参与者的上级。依赖边不传播权限；越界只交换获准的必要交接信息。

任务核心字段、群消息和附件/资产分别执行各自 ACL。受限附件不因普通任务引用变公开，未授权者也不能看到泄密名称/摘要；核心说明含敏感源则整单受限，不能靠自动脱敏先公开。安全派生版本须由有源访问权与发布权的人确认。

权限在请求、worker、分页/计数、检索、导出、下载直链、缓存、模型上下文及群投递全部执行。Bot 可读不等于群受众可读；调岗/撤权重算范围并清理缓存，历史归属不自动搬到新部门。原生授权不能表达的范围先限制该入口，不能用内部自用或隐藏按钮替代后端拒绝。

#### D02 映射与项目继承（产品决策已确认）

2026-11-06 Ethan 确认：**一公司一个 Workspace，部门与资源权限细分；项目授权默认覆盖后续普通任务，私密内容仍单独授权。** 这是产品政策确认，不是 C01 字段/事务冻结、权限实现或测试通过。下表保留决策取舍，其他尚未签认的实施默认不能随之升级。

| 选择 | 直接得到什么 | 无法省掉的代价 | 本轮建议 |
|---|---|---|---|
| 一公司一个 Workspace，部门作组织/授权范围 | 同一成员、Agent、Project/Issue、run 与用量事实；跨部门不用复制任务/Bot | 必须补资源级查看/操作授权及全部出入口，不能零改直接装入真实公司数据 | **已选定**，最贴近频繁跨部门且保持一套事实的目标 |
| 每部门一个 Workspace | 原生成员边界可粗隔离部门普通业务 | 跨部门加成员会放开整区；专项区会拆散任务关联、Bot 实例与授权；私密任务仍不能在区内隔离 | 仅作全体有权数据的粗隔离试验，不作为公司长期映射 |
| 每个独立安全域一个 Workspace | 可容纳真正互不共享的业务实体 | 不是完整部门模型；公司汇总、跨域协作/迁移仍要额外设计 | 有实际隔离需求再单独评审，首轮不建多区编排 |

已确认关系：公司先与一个原生 Workspace 显式绑定；部门是其内部组织成员关系/负责人范围，**不是 Workspace、Project、Squad 或标签的别名**。项目是跨人/跨部门的工作容器；Issue 是唯一工作事实；Squad 是可复用分工，设备只是执行宿主。保留未来公司标识映射，不先造第二公司账号库、多租户控制台或跨区任务系统。具体字段/迁移仍由 C01 冻结。

| 范围 | 已确认产品约束与实施建议；字段/动作映射仍待 C01 冻结 |
|---|---|
| 部门普通项目/任务 | 必须有明确归属部门；当前该部门成员默认可读普通明细和流转，非参与者也可读。创建/评论/认领/编辑/分派/管理分别判权，不把部门可读扩为全员可改 |
| 跨部门项目/单任务 | 授权者本身须有授予权；可授具体人或明确组织范围及动作。项目授权默认覆盖已有及后续普通任务，仅继承授予的动作，不把只读扩大成编辑/分派；私密内容和独立受限来源另授。单任务授权不顺带开放项目其他任务、父任务正文或同事部门。最小导航只包含获准信息 |
| 敏感/私密任务 | 独立显式授权，**不继承部门、项目、Squad 或管理员的普通读权**。普通项目内可有受限任务，但列表、依赖、统计和摘要不能泄露它；受限核心说明不可拆成公开单再靠附件隐藏 |
| 员工与负责人 | 员工默认 native member；部门负责人另绑定受管部门与管理动作，不为管部门升 workspace admin。管理范围不自动向下级部门/跨部门参与者的上级传播；多部门任职须明确登记 |
| 老板与平台管理员 | 老板的公司普通业务总览需要明确业务授权，不从 owner 身份推导；受限明细仍单授。技术管理员管配置/账户，不因管理身份读私密。数据库/宿主运维特权不在应用 ACL 防护承诺内 |
| 调岗、离职与资产 | 部门默认权限随有效成员关系变化；资源归属不随员工调岗搬迁。显式跨部授权逐条复核，离职停用全部公司访问并交接业务责任；公司原件和审计留存，不以清缓存删除资产 |

**新成员历史默认的推荐：**部门普通内容按当前成员关系可读该部门已有普通历史；私密不继承，跨部授权的历史范围必须明确。不额外引入按入职日期切分普通任务历史的系统；这是 D02 待确认建议，不冒充用户已定。项目改归属、转为私密或扩大受众必须预览影响、校验授权并留痕，不能靠改标签/移入项目隐式扩权。

**上下文和成果不能向更宽受众传播：**Workspace context 只放全公司均可读的公共约定；部门材料放受控项目/任务来源，不能写入全区 context、全局 Bot 指令或全区可见 Squad 描述。Leader 只能读取自己获权的子任务并向当前受众报告获准信息；涉及私密来源的汇总另建受限交付或由有权人确认发布，依赖关系不自动授权。

#### D02 最小补齐与放行边界

不另造权限微服务或复制任务表。B01 在原生服务里补最小组织关系、作用域角色/授予权与 Project/Issue 受众策略；B02/B04/B06 消费同一判权结果。必须覆盖：

1. 资源读、写、分派与委托入口；直接 API 和经 Bot 的请求同样判权。创建私密资源须原子保存限制，不能先全区公开再收窄；私密模板不得携带旧授权。
2. 列表/详情/父子关系、搜索、统计、收件箱通知、WS 订阅及推送、日志/回放和导出。原生本地全文索引会同步全区任务/评论/项目，必须覆盖 manifest、snapshot、changes、持久副本和迟到响应；不能只过滤搜索结果。未适配入口关闭，不能继续后台同步。
3. 附件上传、API 下载、裸存储路径、预览/Range 和分享链接均按所属资源与来源许可校验；个人 Chat 的 creator 规则不能被附件接口放宽。
4. 撤权复用原生成员移除、断联与本地索引删除基础，扩到资源级版本/清理回执、在途 Bot 上下文和设备资格。敏感资料不持久离线；离线待清理与已阻断访问分开记，不承诺远程抹除员工自行复制件。
5. 派工仍取发起人/有效委托、Bot、资源、设备及管理人资格交集；公司一个 Workspace 不等于公司任意设备可跑。先无模型权限矩阵，再受托执行、回传和归档；顺序及反例纳入既有 MC-01/01G，不新增调度系统。

目前只完成静态确认，相关新 SHA 动态验证 NOT RUN。映射及项目继承已确认，但权限路径未闭环前不得放真实受限资料；可在隔离实验中用全部虚构内容设置“按政策应无权”的测试身份，以验证拒绝。不能以首轮只做两个部门为由降低私密和跨部要求。无模型验证的唯一操作规程与判失败条件见 [MINIMUM-CHAIN §9](MINIMUM-CHAIN.md#9-不调用模型的合成权限验证nm-acl-r1)。

### 4.2 账号、设备、模型与公用 Bot

账号权限、设备身份、电脑使用权、目录/会话/网络能力分开登记。员工本机管理员权限是前提，不等于 Agent/harness/工具获管理员执行权限；安装授权与运行授权分离，不把工作目录、venv、worktree 当安全隔离。平台管理 Agent，不强加整机 MDM，也不承诺抵御管理员主动篡改宿主。

员工助手默认本人指定授权设备；公用 Bot 只用预授权池。每次派发、增量资料、恢复与换机都取委托人、Bot、任务、资源、设备及设备管理人授权的交集，并检查工具、容量和外发政策。设备与管理人均须有资料授权：空闲、同部门、入群或角色提升都不能代替。不能承诺向设备管理员隐藏已落地资料，也不能借其私人登录态执行。

原始公司模型 Key 只在受控中央服务/秘密存储；本地用限范围短期访问能力，不回退个人计费。断联停止新动作；撤销传播受短租约与联网状态限制，不能声称离线瞬时生效。

生产外部业务写入本期不开放；本地浏览器/Python/Node 只做已验证读取/导航/下载，不能绕连接器提交、外发、付款或修改记录。本地获准目录写入、公司资产上传、隔离测试写入分别授权。禁止跨域直接改底座表绕过事务和授权。

### 4.3 委托不借权，治理分硬规则与工作约定

2026-11-06 已实测：A 直改 B 小队被拒，A 委托共享 Bot 执行却借 B 管理能力成功；对话新队归 B，A 无管理权。证据见 [组队实验](MULTICA-BASE-EVALUATION.md#2026-11-06-合成组队实测权限-fail汇总未闭环)。这是 C01 强制点缺口，不靠修改提示词、隐藏按钮或扩大成员权限修复。

- 服务端从可信身份链解析真实发起者、实际 Bot/run、授权委托者与目标；设备管理人是执行宿主责任人，不是隐式业务授权人。原生 token 可保留设备运行语义，但不能用其 UserID 单独裁决组队/资源管理权。
- 动作必须在有效委托内，且同时满足 Bot、任务/资源、工具、设备及管理人资料资格等限制。A 无此权且无有权主体的明确委托时，直调与经 Bot 调用都拒绝；B 有权不构成 A 的授权。有正式委托时记录授予者/受托者/动作/对象/期限和撤销，不凭 prompt 自称授权。首轮不建设通用代理授权平台，先覆盖此次小队和派工动作。
- 组队成功须有原生对象 ID、当前成员/职责、归属及实际可管理人回执。创建归属由已确认政策与可信委托决定，不能静默登记 runtime owner；不得通过改写历史 originator 掩盖设备身份差异。创建者与业务维护人字段如何映射仍由 C01 冻结。
- 项目职责、交付格式、沟通习惯属于给人/AI 的工作约定；权限、工具准入、费用/派单限额、审批、停止属于服务端/受控执行器硬规则。自然语言或 rules JSON 不直接执行，不允许 Bot 改软规则后突破硬规则。
- 明确授权内的选人派工不逐步审批；超范围则拒绝或产生有权者待办。批准记录绑定动作、确定参数/对象版本、期限及使用边界，执行时复核当前授权；询问参数不是授权，模板/版本回退不恢复旧委托。

这些规则复用 Multica 身份、Squad、原生队列与审计接缝；B01 负责授权、B06 负责派发强制，B02 只呈现结果。C01/C02/C06 仍 DRAFT，未批准具体新 schema 或产品实现。

## 5. 一次协作如何执行

1. 消息先是消息；用户明确建任务、@ 指派或接受任务建议，才走经过授权的原生命令。消息可见、上下文可读和执行唤醒是三条边界，不因普通回复反复唤醒。
2. 创建/认领/转派在唯一任务权威上幂等、条件提交；外部 ID 和意图仅作关联。超时先对账，未确认不显示成功；接口不足不另立暗中覆盖状态表。
3. 先定承接 Agent，再筛设备，原子领取/预留与租约确认后启动本地 DSH。创建、派发、接收、启动分别留证，同一 Agent 可并行多个隔离 task/run。
4. 委派生成明确子任务/交接，关联 parent task/run、输入版本、目标 Agent 与权限。无承接者等待认领/分派；循环、重复和费用有界。项目临时输入不反复改共享 Agent 全局配置。
5. 等人/子任务时持久化等待，在安全点保存并释放可释放槽位/写锁；不让父 harness 占唯一槽空等。回复后按真实继续执行契约恢复/建接续 run，不能假设任意中断能原地续跑。
6. 交付前重验当前授权、输入与任务版本。文件先校验/不可变上传，再由权威提交版本/ACL/引用确认，才标已归档；本地已生成但未上传显示待归档。保存成功、可接手、运行完成和业务验收是不同事实。
7. 回复原任务/获授权群，面板按同一事实更新，用量与真实运行关联。组织助手可选；其离线不阻断人工入口，也不暗藏中央推理服务。

## 6. 同步、故障、并发与恢复

采用固定版本已验证的原生事件/API；订阅不可靠则带游标轮询与对账。可靠投递用持久化 outbox/inbox 或等效机制，至少一次 + 去重 + 有界重试 + 人工修复，不承诺业务 exactly-once 或跨产品原子事务。

旧代次不能覆盖当前任务；提交时同时核验租约/代次、版本、权限。优先权威端条件写；否则需证明所有相关入口受控的同资源顺序提交与超时待确认协议。进程锁、发送前预检、outbox 都不能替代这道门禁；不支持则否决接入，不把局部一致性要求变成全局串行。

### 6.1 真实并发与控制通道

同机无冲突任务与跨设备任务允许并行；每个 task/run 隔离 session、可变工作区和产物。共享 Bot 不意味着共享全局 session/cwd/env。浏览器、GUI、同文件仅按冲突资源互斥；等待到安全点才释放资源，不能让父子互相持锁。

按设备 CPU/内存/进程/IO、模型 RPM/TPM/预算与上传/日志容量做有界准入和背压。消息/派单/状态/取消不被长任务或满载日志堵住。同一派单唯一有效领取与不同任务并发必须同时满足，P0 真机验证；不能用固定单任务回避缺陷。

### 6.2 离线与工作接续

未启动的公用 Bot 工作可改选合格设备，撤销旧 offer 并拒绝迟到领取；员工助手默认设备离线则等本人设备。已运行任务断联不等于未发生，租约过期不等于旧进程终止，取消不等于回滚。启动许可提交后 ACK 丢失视为可能执行。

自动接续依赖当前授权与完整保存点，以及检查点之后已提交效果的对账；已完成跳过、未完成续做、未知阻塞。R1（共享写隔离且可安全重算）/R2（旧执行与资源可信终止）是待验证安全分类，不能凭租约/进程自报满足。安全条件已验证则预授权池自动接续，不逐次人工批准；未知副作用交具任务管理和证据访问权的责任人核对，运维不越权。

接续默认从中央检查点/已归档资产新建运行，不搬 OS 进程，也不保证原始 CLI session 跨机可用。保存范围包括授权 Git 中间态、dirty/untracked、普通二进制和操作/业务效果边界；不可变对象完成后才提交权威指针。先用实际 DSH/Multica 验证，不能把旧 Paperclip 快照结论当已存在实现。

本地缓存加密有界、自动上传、有界重试；满额暂停，中央确认前不删唯一待上传副本。未上传前设备损坏可能丢失。仍有效身份可重新鉴权申请旧 run 限范围证据上传；撤销凭证拒收，由有权接管人恢复导入。迟到真实费用仍幂等结算，中央保留独立供应商证据。重连先对账权限、代次、会话与效果，无法证明旧 session 当前合法则重建。

## 7. 统一客户端与外部资料

统一产品沿 Multica 原生客户端、任务/Agent/小队/daemon 路径；业务面板是同一任务事实的授权投影。同一任务在首页、对话、面板保持同一 ID/详情与服务端状态，不为不同模块再装一套路由/Store/组件库。原生存在的能力经逐项权限审查后开放；Paperclip 功能目录不是必须搬入的产品清单。

界面可见不等于后台安全：详情、搜索、附件、WS、缓存合并、迟到响应和真实动作都要验权。普通网页不能获得桌面 preload/Node/任意文件能力；桌面 `webSecurity:false` 等现状需整改验证，不能直接加载外部办公网页后宣称安全内嵌。浏览器辅助入口无设备授权不具备本机工具能力。

### 7.1 外部知识/表格的后期接入边界

外部知识、业务表格和官方 CLI/MCP 为后期能力，供应商、排期和嵌入形式未冻结；不同时启多套正文主库，不提前造通用表格后端。选定提供方保存正文、源历史与源 ACL；morchat 保留 provider/tenant/稳定资源 ID、版本证据、来源/维护人、公司接管责任、task/run 引用及操作审计。外部待办/工作流不成为第二调度。

显式绑定公司用户与 provider 身份；SSO 不是权限/停用同步，Multica token 不是外部供应商 token。Bot 委托失效必须拒绝，不能降级管理员/App 凭据；原生工具名白名单不等于资源/行/字段授权。长期秘密留中央，CLI 同机凭据示例不直接充当远程 broker。源端 ACL 与企业/Bot/设备/外发限制取交集。

先验回源权限，再评估隔离内嵌；没有安全组件则打开获权原文，不关浏览器安全策略。写入须有源端原子版本条件或经验证等价协议；代理先读后写不能挡源站并发，未满足只开放只读/独立草稿/建议。源版本不是不可变交付，必要时按授权保存证据快照。

撤权/离职后阻断后续访问、清理受控缓存、撤销凭据与索引；公司任务/交付及应保留的源本体、版本证据和审计按政策交公司接管，不能为清缓存删除公司源资产。外部公司接管权限须预先建立，不能依赖离职员工个人账号。无法保证失联设备或已导出副本远程抹除，应记录未完成清理并阻断重连访问。

## 8. 工程组织与门禁

遵循 [工程基线](ENGINEERING-BASELINE.md)：先任务卡/owner/写集和依赖，再切片冻结契约、fixture 与契约测试；共享 schema/迁移/锁文件/原生 patch 单写；独立审核和单通道合流。worktree 不能消除接口语义冲突。没有脚手架、CI 或测试证据时不得宣称已建立。

现行 PRD 定范围，本文定权威边界，Discovery 定契约状态，专项定协议，PLAN 定依赖顺序；历史 archive、研究、实验只供事实对照，不能直接成为开发指令。底座绑定矛盾必须修正正文与消费者，不以文首声明掩盖旧指令。
