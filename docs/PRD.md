# morchat 产品需求与首版 MVP

**首轮实施授权已更新：**R1-AUTH-r1 已批准三个切片连续开发；首轮交付和授权见 [ROUND1-DELIVERY](ROUND1-DELIVERY.md)。不增加本 PRD 的功能范围，不等于 C01–C08 已冻结或产品已通过验收。

> 版本：v17，2026-11-06。Multica 是统一客户端、后台和唯一任务/run/调度底座；中央控制＋Windows 本地 DSH＋云端模型。本文定义产品要求，不把参考产品能力迁移为已实现事实；C01–C08 均为 DRAFT，未冻结。



## 1. 产品定义

企业 SaaS Agent 协作平台，面向公司的人与 AI 共同工作：组织成员围绕目标组队，通过任务交付成果，把有价值的工作方法和知识变为公司可继承、可复用、可改进的资产。

当前服务自己的公司，内部自托管，不对外销售。保留公司范围、真实身份、资源授权、连接器和资产可迁移边界，不提前建设客户自助注册、订阅计费或跨公司协作。

### 是什么

- 公司、部门、负责人、员工与 AI 同事共同工作的空间。
- 支持人与 AI、AI 与 AI 组队，员工和负责人都可以发起协作。
- 目标、任务、讨论、交付物和经验有连续的来源关系。
- 工作资产不依附创建人的个人账号或电脑；离职、转岗后可交接。
- 首轮为两台 Windows 11 x64 原生设备，Mac 只保留平台接口/数据契约准备、不阻塞首轮；不以 VM、WSL、Docker 作为员工使用前提。两台 Windows 均须验证，本地无合格能力则明确拒绝而不服务器代跑。公司模型通道面向 OpenAI Chat Completions／Anthropic Messages 等协议，模型品牌不限定；逐型号验证能力，不保证兼容标签等于 Agent 可用。
- 所有人使用同一客户端，面板按账号与资源授权展示；完整 harness 和授权工具在员工本机执行，模型推理在云端；中央负责协作、任务控制、用量与资产。

### 不是什么

- 不是 AI-only 公司模拟器，不把真实员工建成 Agent。
- 不是千川报表、预算审批工具或只面向管理者的后台。
- 不是三个独立产品的门户拼接，不要求员工在多套系统重复维护工作。
- 不是通用 IM 替代品、低代码平台或自动改写自身代码的系统。

## 2. 核心对象与关系

**Bot 就是 AI 同事。**正式 Bot 实例使用 Multica 中唯一稳定 Agent 身份，不另建影子身份/配置。真人使用真实用户身份，不为组织图建成 Bot。模板、实例、小队与 run 分别版本化/关联，不能用同一版本号混同。

公司 → 部门与真人/Bot；目标 → 项目/任务 → 子任务与交付物。小队包含真人和 Bot，也可以全部为 Bot；小队协调不替代人类组织与业务问责。群、项目、小队不强制一一对应。

**D02 产品决策已确认（2026-11-06）：**一家公司对应一个 Multica Workspace；部门是内部组织/授权范围，不按部门复制 Workspace、任务或 Bot。项目授权默认覆盖后续普通任务，私密内容仍单独授权，继承不扩大动作范围。原生 Project/Issue 保持工作权威，部门普通默认可读、跨部显式授权和私密独立授权须补服务端资源权限后才成立；不是“现成装好就已满足”。取舍与边界唯一正文见 ARCHITECTURE §4.1，场景见 PRODUCT-EXPERIENCE §4.3；C01 仍 DRAFT。

| 对象 | 职责与关系 |
|---|---|
| Bot 模板 | AI 同事的可复用配方，引用岗位材料、配置、指令内容与 skill；复用经核验的 Multica 载体，模板不足则最小扩展，不携带旧授权/记忆 |
| Bot 实例 | 具体 AI 同事，有稳定身份、维护人和实际授权；可来自模板或复用已有实例，能力升级/换设备不更换身份 |
| 小队模板/实例 | 模板定义真人/Bot 槽位、能力与交付关系；实例映射真实成员并引用确定版本，不为每次组队克隆全部 Bot |
| 任务/run/attempt | 任务是工作；run 是 Bot 一次执行；attempt 关联具体设备派发/恢复。一项工作可有多次运行，一个 Bot 可并行执行多个隔离任务 |
| 能力与版本 | 配置历史、指令不可变快照、skill 版本、模板来源通过能力清单关联；不是另一份可编辑 Bot 或新版本存储引擎 |

岗位入职包是职责、材料和就绪检查，可供真人或 Bot 使用，不是第四套 AI 身份。临时子 Agent 默认只是任务执行细节，不自动进入公司 Bot 名册。

群成员加入不自动获得所有历史附件/关联任务权限。Bot 的职责、工具与资产权限分开；员工助手 Bot 默认本人指定授权设备，部门公用 Bot 在预授权设备池自动选机。身份、维护人、请求人、费用承担方、模型、harness、设备和会话分别管理；Bot 不是电脑或常驻进程，同机/跨设备无冲突任务均可并行。

每次受控生效的 Bot/skill 改进都须关联可取回的配置、指令内容、skill 和输入版本。Multica 现有载体优先复用；不可变历史、候选隔离、条件发布和 run 实际加载证据须逐项验证，缺口按 B03/B04 最小扩展，不承诺它已有 Paperclip 的历史/测试 API。模板 hash 不等于可恢复历史；GC 后须仍能取回获保留字节。详见 [产品流程](PRODUCT-LIFECYCLE.md)。

## 3. 角色与使用方式

| 角色 | 主要入口 | 首版能做什么 |
|---|---|---|
| 老板 | morchat 公司目标面板 | 下目标、看部门进展/阻塞/交付和业务指标；查看受授权的详情 |
| 部门负责人 | morchat 所负责部门面板与工作群 | 看本部门目标与业务流转、建小组、分解目标、指派或认领任务、处理阻塞、维护部门知识与 skill；其他部门仅看专项授权范围 |
| 员工 | morchat 工作群、我的工作、本部门面板与获授权跨部门协作视图 | 默认查看本部门普通任务明细与流转；查看获授权跨部门项目/任务及对应流转；自行组队、认领/交接任务、交付与维护有权编辑的资产；敏感内容和私密群单独授权 |
| Bot（AI 同事） | 统一名册/任务入口，工程映射同一 Agent | 接受明确任务与上下文、调用授权工具、请求补充、委派允许的子任务、提交有来源的成果 |
| 平台管理员 | 统一 Multica 客户端内受限治理入口 | 管身份映射、连接健康、审计、恢复；管理权限不自动等于业务内容访问权，不另开 Paperclip 执行台 |

具体入口边界见 [面板与员工端](PRODUCT-EXPERIENCE.md)。

## 4. 首版用户故事与验收

以下验收要求为 MVP 设计门槛，不是已测成绩。试点至少覆盖两个部门、两名人类参与者和两个 AI，并覆盖老板/负责人/员工角色，可由实际试点人员兼任允许的角色。

| 编号 | 用户故事 | 可观察的验收结果 |
|---|---|---|
| US-01 | 老板下目标，负责人组织工作 | 目标有指标口径、负责人、期限；任务能追溯目标；面板区分任务进展和业务效果 |
| US-02 | 员工或负责人发起人机工作群 | 二者均可创建群；邀请真实员工及有权使用的 AI；非成员访问被拒；新增成员的历史访问策略可检查 |
| US-03 | 对话形成任务，人员认领与交接 | 可从消息建立任务，保留来源；重复提交不重复建单；认领冲突有明确结果；撤销/转派留痕 |
| US-04 | 人与 AI、AI 与 AI 接力 | 至少完成一次人→AI→人及一次 AI→AI 子任务交接；每次交接有任务 ID、授权上下文、状态、结果；不能靠群聊自报成功 |
| US-05 | 员工、负责人和老板按范围看真实进展 | 同部门非参与者也默认能看普通任务明细和流转；负责人有部门管理视图，老板有公司总览；跨部门参与者能看获授权项目/任务的进度、交接、阻塞和交付，不看到对方其他业务；敏感内容和私密群单独授权；群卡/待办/面板同源并显示更新时间 |
| US-06 | 成果沉淀并复用 | 成果关联任务、来源、版本和权限；一次复盘产生候选，经过案例验证与有权发布后，在另一条任务中复用明确版本；记录本地实际加载与验收证据，不把候选或测试完成当已发布 |
| US-07 | 调岗或离职不丢公司能力 | 撤销账号及运行权限，移交未完成任务、AI/资产维护职责和连接依赖；继任者按新授权继续工作，个人隐私不进入交接包 |
| US-08 | 首个场景接千川，但平台通用 | 千川只读分析走同一任务与资产链；另用“跨部门活动方案”完成完整交付与复用，不依赖千川字段 |
| US-09 | 同一客户端提供完整本地 runtime | 在未安装个人 Agent CLI、无个人 Key/订阅的试点设备上，客户端可受控准备引擎并运行本地完整 harness；浏览器/Python/Node/文件回传逐项验证，中央不代跑；各角色无需另登录参考产品或先绑定具体办公软件 |
| US-10 | 账号、设备与工具边界独立且可撤销 | 入职时配置部门/角色/AI 范围，另行绑定设备与目录；同部门可读任务不产生电脑控制权；断联/撤销/换设备有明确状态，不重放已发生副作用 |
| US-11 | 公司统一供给云端模型并管理用量 | 员工无需 Key；客户端、任务代码、日志无供应商原始 Key；模型/额度受控，用量关联责任人、任务和部门/项目，重复回执不重复计费，未知费用不记零 |
| US-12 | 本地产物成为可交接公司资产 | 上传提交前显示待归档；成功后有稳定资产 ID、版本、权限和来源，换设备/维护人仍可访问，个人目录和登录凭据不自动沉淀；归档/提交/指定人验收分开，历史链接固定字节，重试与替换不重复或覆盖，OP-05 验证 |
| US-13 | 同机与跨设备并行且不串数据 | 同机至少两项无冲突任务真实同时运行，跨设备独立任务并行；共享 Agent 多任务会话隔离，冲突资源局部互斥；等待释放资源，按实测配额限流，不固定单任务、不把两任务用例当容量上限 |
| US-14 | 离线分类，不使整个团队停工 | 员工助手离线等待本人设备；公用 Agent 未启动自动改选、满足 R1 隔离/安全重算或 R2 可信终止且恢复清单覆盖已提交效果后按池策略自动接续，未知结果阻塞核对；旧租约不覆盖、费用不丢，未上传风险明确，不盲重跑或中央代跑 |
| US-15 | 公用 Agent 自动选授权池，员工助手有默认宿主 | 群主/发消息人不决定宿主；公用 Agent 在至少两台合格设备间选择，设备与管理人均须有资料授权；撤销/资料或工具不匹配节点被排除；员工助手不自动借同事电脑，入群不入池 |
| US-16 | 各 Bot 回复可见且多人多 AI 有序协作 | 群/任务线程保留各 Bot 署名原回复与 task/run，汇总不覆盖；群内普通消息不唤醒；单输入框 @ 选中 Bot 后发送，无模式选择，稳定 ID 及受众验权；有效提及/结构化交接才定向派工，不扫引用/Bot 输出 @；重连/多入口不多跑，根链限额可截停循环；共享获授权上下文而非全部会话；长任务不堵取消/待办；同一持久追问/批准多入口投影，补充可按 revision 改/撤，停止 run/本次协作与中断继续分开，按 MSG-01–08、OP-01–04 验证 |
| US-17 | 原机不可用后，获授权继任者能从公司自动确认版本继续 | 系统自动触发/周期兜底/有界重试，无需员工手动保存、commit/push 或补交；保存 Git 中间态与普通文件，空工作区换机验证字节/任务/效果一致；区分业务/执行/保存/验收四状态；旧设备不能覆盖、未上传缺口明确，R1/R2 分类通过 WC-01–12 |
| US-18 | 员工与负责人都能使用 AI 组织助手 | 自然语言整理目标、推荐已有成员/AI、预览拆分与组队变更；按本人委托范围执行，缺权可见；助手停用仍可人工建群/认领/验收，模型工作仍是本地 task/run |
| US-19 | 岗位入职包使人和 AI 明白职责并真正就绪 | 包含职责/不做事项、材料、Bot 配置历史、指令内容快照和 skill 版本引用、工具需求及小型岗位检查；权限声明不自动授权；登记/安装/实际加载/通过检查分别显示 |
| US-20 | 复用 Bot 模板与小队模板，建立真实 AI 同事和小队 | 员工/负责人可在授权内辅助生成修改；Bot 模板创建/更新具体 Bot，小队槽位优先绑定已有真人/Bot；引用确定模板与内容版本，升级不静默改实例；预览新增/绑定/变化/缺权与部分失败，不带旧记忆/凭据/授权或自动例程；重试不多建，OP-06 验证 |
| US-21 | Bot 能力与 skill 改进有版本、评估和受控生效/撤回 | 至少原案例和不同输入；评估仍走 Multica task/run，业务评判独立于执行成功；候选不漂入生产，新 run 消费获准配置/指令/skill 组合，归档失败不生效，回退不改历史或复活权限。首版纠正平台任务/归档资产并保留候选；外部知识条件更新按 KD 后接，不作为首版退出条件；评估失败、撤权、过期候选和过期 Undo 负测保留，OP-07–08 待验 |
| US-22 | 从同一个工作首页进入对话、任务与成果 | 默认我的工作；角色范围面板、项目/任务列表和看板、对话任务线程、稳定 Bot ID 的 @ 派单与各 Bot 署名回复同源，进度和成果串联；断线/无权/失败不假成功。统一 Multica 应用壳和任务/run；原生项目甘特直接保留，企业排期差异按 P2 评审，非 P1 硬门禁；C02 映射原生日历日期语义，不用执行起止冒充计划 |

### 4.1 本轮收敛：自主协作要受权且能闭环

2026-11-06 Ethan 确认：完整 Multica 基座不变；Evose 只提供治理/工作面参考，不追加竞品模块。US-18/20 的对话建队和 Leader 选人派工在明确委托内自主执行，超范围才拒绝/请求授权；设备管理人的权限不能被借用。US-04/16 要有派工受理、可信成员回传与可靠汇合，不能以模型文本或 run completed 代替交付。US-12 的自动归档、指定真人验收继续保留。

已测委托/归属 FAIL 和最终汇总未闭环见 MULTICA-BASE-EVALUATION；增员、永久 Bot、撤权与双机等未覆盖项不转 PASS。先修现有强制点与回传路径，不重建组织/任务/审批系统。首轮仍沿原生任务协作；知识/表格、外部 CLI/MCP、完整治理编辑器、商业积分和复杂套餐不新增到本轮。契约与验收顺序见 MINIMUM-CHAIN r7 / Discovery。

## 5. MVP 范围

首版按 B01 权限、B02 客户端协作、B03 模板发布、B04 资产版本、B05 runtime、B06 设备派发、B07 保存接续、B08 模型用量划分差异工作，不是八个服务。对应 C01 身份权限、C02 任务命令事件、C03 组合生效、C04 资产证据、C05 runtime、C06 派发续租、C07 接续、C08 模型成本均为 DRAFT，不能提前按冻结接口施工。Multica 可用能力直接复用，缺口显式适配；Paperclip 仅治理参考及独立源码候选，OpenMausBot 仅协作机制/独立 helper 候选，不导入第二套 chat/store/runtime。

### 必须包含

1. 单公司运行；部门、成员、负责人、AI 名册和公司范围的数据边界。
2. morchat 统一桌面工作台，以“我的工作”为默认首页，侧边栏进入对话等功能；工作群、任务线程、各 Bot 独立署名回复、明确提问/委派、附件/链接、同源任务卡、未读、站内待办及内嵌角色面板。附件类型/大小受控；浏览器辅助入口不替代本机能力。
3. 最小目标/项目/任务；拆分、认领、委派、依赖、阻塞、交付与反馈。任务、run、派发与调度唯一事实在 Multica；企业业务责任与权限缺口在此边界内扩展。
4. 最少可用 AI 运行与小队协调；每次模型调用绑定 Multica 真实任务/run，明确提问可建可见轻量任务，任务外自动标题等模型功能关闭。沿 Multica 客户端/daemon 接 Windows 本地完整 DSH，模型在公司统一云端通道；公司 Key 不下发通用 harness、客户端或任务代码环境，可暂停和撤销后续动作。

**运行时段边界：**不要求所有员工关机后继续工作，无合格在线设备时允许任务等待，不将其判为必须增加云端/常在线执行池的缺陷。正常在线协作和满足条件的跨设备接续仍须验收；中央保留任务、已确认资产及治理能力，不代跑员工 harness。

### 知识库与多维表格：已确认要求与分期建议（2026-11-06）

- 员工和负责人均可维护自己的工作知识库/业务表，也可查看或编辑明确授权的共享资源。个人工作区指维护与授权范围；工作内容仍按公司资产政策留存，真实个人隐私不纳入。
- 知识库至少区分资源查看、修改、分享/授权和发布；表格还必须分别判定行查看、行修改、字段查看、字段修改，读权不等于写权。新建/删除记录、改字段结构和扩大共享范围另行授权。
- Bot 不是管理员代理：实际权限不超过委托授权、Bot 自身授权及本次任务范围，数据落到本地前还验设备/管理人资格。入群、@、知道资源 ID 都不增加权限。
- 例：同一客户表中，销售仅看其获授权客户，能改跟进记录但不能看成本；财务可看获授权客户的结算字段。销售的 Bot 也不能读取成本或修改结算；负责人身份不自动获得敏感字段。跨部门任务只获得对应行/字段，不开放整表。
- **分期：**先完成统一客户端和 Agent 协作；知识/业务表外部连接器后接。后续最小编辑范围、行/字段权限、源授权与离职接管按试点和实测确定，不能因延期取消权限门禁。
- 后接知识库不扩为办公套件：先文本/Markdown、附件引用、版本历史、受控共享和搜索；复杂排版、多人光标和公式/自动化不承诺。优先集成现成服务，不自建等价正文引擎。

实施与验收边界见 [资产与学习](ASSETS-AND-LEARNING.md)。外部资料接入与中央任务/run 权威分离；本轮不新增连接器调研或实现。

### 内容主存储选型与知识接入范围（2026-11-06）

## 6. 一条端到端验收场景

当前低保真 v4 的页面和分期以 [PRODUCT-EXPERIENCE §3.7](PRODUCT-EXPERIENCE.md#37-项目工作面低保真-v4) 为准：同一项目串联多人对话、任务看板、业务流程、排期、知识能力、收件箱与成果。MC-S1 首轮验证多人/多 Bot 核心链，完整原生工作面直接复用，补预置上下文、权限和真实交付；S1-D 已确认先用任务评论，独立 IM 群入口后补。P2 仅补原生不足的跨任务阶段/企业排期及版本维护，P4 接外部知识/表格等。完整产品关系纳入设计不等于全部首轮开发；v4 本地合成走查不替代下列真实验收或任何 P0。

员工或负责人提出跨部门活动目标 → 组织助手澄清验收与责任并优先复用现有人员/AI，员工也可手动完成 → 从小队模板建立本次实例，岗位包经权限/版本/工具检查就绪 → 人与 AI 拆分、认领真实任务 → 员工助手在本人设备、公用 Agent 在授权设备池并行执行，依赖步骤按实际成果交接 → 系统自动保存中间态、公司确认归档 → 指定人验收或退回修改 → 复盘形成带来源与基线的 skill 候选 → Multica 评估任务/run 加业务评审 → 授权发布明确版本 → 另一员工用模板和新输入，在新任务验证实际加载与效果 → 原维护人退出后授权继任者继续使用。

至少覆盖一次人→AI→人、一次 AI→AI、一个评估失败不发布、一次旧版本回退，以及组织助手不可用仍能人工工作。完整操作与失败显示见 [产品流程 §4/§7](PRODUCT-LIFECYCLE.md)。

千川只作为另一条只读场景的输入连接器；关闭它后上述通用链仍须成立。

完整走查必须包含：Bot 追问而不是猜需求→有权真人回答→执行中追加并改/撤未消费要求→一个批准/拒绝及过期反例→按明确范围停止且无关任务继续→显式继续→确定版本提交/指定人验收→平台任务/资产纠错与 skill 候选→另一员工复用。员工与负责人使用同一界面和相同命令权威，区别在当前授权；“负责人”不自动读私密资料或代所有人批准。OP-01–08 纳入原有纵向测试，不再建操作中心。

## 7. 质量与边界

本文要求的自动保存、未知阻塞和不搬进程是已确认方向；US-14 所引用 R1/R2 精确策略及实验阈值仍须按 Discovery 的 C06/C07 和 D06/D07 签认、实测，不因进入验收栏就声称已冻结。

- 创建群、使用 AI、执行工具、查看资料和发布公司级资产分别授权；不以 prompt 代替服务端鉴权。
- 首版任务核心字段共用任务 ACL，消息/附件/资产独立授权；核心字段含敏感源且未确认安全时整单受限，不承诺任意字段自动脱敏。
- 普通任务的部门默认可见是读取规则，不自动授予修改、指派或管理权。敏感来源、私密群和受限附件的权限优先；项目/任务授权不沿依赖连线扩展。
- 工作私密仍可属于公司，个人隐私单独排除；留存不等于全员可见，也不等于无限期留存。
- UI 未获确认的请求显示处理中/失败，不先标成功；异步同步显示时间和异常。
- 外部副作用单独处理幂等、结果确认与撤销边界；撤回任务状态不等于撤销已发送的外部动作。
- 本地处理不等于数据不出设备：进入云模型的文件片段、页面文本和工具输出仍须符合资源授权与公司外发策略。
- 员工保留本机管理员权限；平台只管 Agent 授权，不接管整机、不以 MDM 或管理员权移交为前提。Agent 不继承员工全部权限。公用 Bot 仅在设备与管理人均有对应资料授权的节点运行，新增资料/恢复/接续重验，不承诺阻止本机管理员主动复制已落地数据。
- 账号权限、设备授权、执行环境上限共同约束动作；公司统一供给模型不扩大资料或电脑访问权。离线撤销和在途费用不能承诺瞬时生效或绝不超额。
- 本地化分散计算，必须支持同机/跨设备并行并以资源容量约束；不能用每设备固定单任务替代正确性。员工助手与公用 Agent 的选机/离线策略不同；无合格设备则等待，不扩权、不中央代跑。
- 未归档文件、检查点若随失联设备损坏可能丢失；资产交接以公司已提交版本为准，不承诺任意 CLI 会话可迁移。
- 界面响应、设备负载、排队时延、模型成本与生产 RPO/RTO 待 P0 根据试点规模确定；双设备规程已列小文件条件下的候选保存/恢复门槛，尚待确认实测；未经测量不写成现有保证。
