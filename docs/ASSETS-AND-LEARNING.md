# 公司资产与持续升级闭环

> 2026-11-06，产品与资产验收要求。Multica 是唯一客户端/后台/任务/run/调度底座，B04 资产版本、C04 资产证据等接口仍为 DRAFT 未冻。工作资产按公司政策留存，个人隐私除外；留存不等于全员可见。本文不是能力已实现或制度审查通过的声明。

## 1. 三类内容，不混成一个记忆库

| 层次 | 内容 | 用途 |
|---|---|---|
| 工作记录与成果 | 消息、任务、文件、报告、决策依据、必要运行证据 | 交接、追溯和复盘；不自动成为通用知识 |
| 业务知识与上下文 | 指标口径、业务事实、项目结论、失效日期和适用范围 | 按当前权限检索；有来源、可纠正 |
| 可复用能力 | skill、SOP、检查清单、角色/小队协作模板 | 有版本、适用条件、测试案例和维护责任 |

工作流模板不是本期资产类型的必需实现。工作方法可以先以 skill、SOP 和小队协作模板沉淀，不依赖低代码引擎。

## 2. 资产模型的最小要求

每项资产记录：公司、类型、稳定 ID、来源任务/消息/运行、执行设备/工作空间及 harness/工具版本、内容哈希、创建者、管理部门、维护人、版本或正文引用、可见/可用/可编辑/可发布范围、状态、保留规则、依赖和变更审计。

公司归属与个人创建者分开；部门是管理责任范围，维护者可更换。仅在明确授权下生成部门/公司可复用版本，不通过改标签把私密资料直接公开。

skill 正文优先沿用 Multica 现有载体；历史版本、发布和实际加载证据逐项验缺口，Paperclip 版本能力仅作参考。公司资产目录保存索引、策略和评估关联，不再另建一份独立可编辑的 skill 正文。运行快照/交付包是受控副本，不反向成为编辑源。

### 2.1 本地文件与正式交付

临时工作空间和员工电脑不是正式公司资产的唯一存储。生成/选择文件后，经过类型/大小/内容安全检查、内容哈希校验、上传与版本登记，中央存储提交确认后展示已归档；完整保存点与当前授权满足才可接手，指定责任人验收后才展示正式交付；上传失败或离线时显示待归档，不以本机路径或 AI 口头完成替代。重试使用防重标识，冲突保留可辨认版本，不静默覆盖。

只同步获准工作目录、选定输入和工作产物，不整盘采集。浏览器 Cookie、模型 Key、个人隐私、全局环境和不必要原始运行日志不进入公司知识库。产物保留任务、设备、执行身份和能力版本来源，不要求复制整个运行环境。模型外发与公司留存分别检查；本地文件可读并不自动允许发送给云模型。

Skill/SOP 如依赖浏览器、Python/Node、运行库或特定文件能力，应声明版本与所需能力，凭据只用引用，目录参数化；安装 skill 不自动授予这些权限。可复用能力不能绑定某位员工的私人路径或登录态。运行记录固定实际使用版本，换设备后的可复现性需要验证。

### 2.2 跨设备上下文与并行产物

群共享上下文包记录任务/目标版本、必要可读消息及历史范围、输入资产版本、Bot 配置/指令内容快照/skill 版本、权限版本和事件游标；不同步全部个人模型会话、私人目录或 Cookie。运行会话/工作区按 task/run 隔离，共享 Agent 的两个任务也不写同一份可变记忆。新决策/撤权以版本增量通知，交付前重新检查，不盲用旧快照。

暂存/上传成功不自动等于正式资产发布或任务交付；转为正式关联/投递时须在提交生效处验证代次、版本和权限，旧 run 的迟到数据仅隔离为证据。恢复清单要包含检查点之后已发布资产和已创建子任务，不能因旧检查点不含它们而重复发布/创建。

并行产物以独立 run 和资产版本保存；更新同一正式资产必须校验基础版本并显式合并/审核，不能最后写入覆盖他人结果。可复用知识/skill 更新走候选与发布，不以设备内本地记忆覆盖公司正文。费用和公司归属跟业务责任走，执行设备/设备管理人不是自动的费用承担者或内容所有者。

部门公用 Agent 换池节点不改公司 Agent、任务和资产身份；维护人离职后移交维护/池授权责任，不删除公共身份或复制个人登录。设备必须持续获准承载资料：新资产、上下文增量和旧会话在首次送到宿主/授予获取能力前核验；同任务新身份也不能恢复无权旧 session。资料升敏或权限收紧时暂停/按授权重建；有算力权不等于有权处理一切公司数据，无法保证已送达资料可从失联宿主收回。

### 2.3 离线缓存不是公司备份

完整 harness 在员工设备执行，检查点、工作摘要、必要运行证据和成果由系统自动在工作单元/等待边界保存并按周期兜底，失败自动有界重试；不依赖员工手动保存、Git 提交或补传，模型也不负责决定是否保存。最小本地恢复/回传缓存需加密、有容量上限、可重试；满额暂停并提示，未收到公司提交确认前不删除唯一待上传副本。不可将本地记忆或工作目录当作公司资产唯一权威。

断联不继续自主调用模型或新工具；已有允许保存的输出标为待归档，重连先核对身份/租约与来源，再提交。迟到的旧运行成果可作为证据隔离核对，不能直接覆盖当前交付。失联设备损坏前未上传的数据可能无法恢复，离职或资产面板必须展示缺口，不声称零数据损失。

### 2.4 工作中间态与完整交接版本

不能只留最后成果。[任务与工作空间接续](WORKSPACE-CONTINUITY.md) 定义代码/Git 与普通目录两类适配，保存任务进度、已确认效果、精确文件/Git 状态、依赖及权限来源；受控对象先持久化再发布权威任务关联。保存点可恢复不等于候选成果已验收；未上传内容不在公司恢复保证内。快照包含 Git 历史时核验全部历史授权，分支不是保密边界。R1/R2 接续须分别验证，不复制私人会话/凭据。

### 2.5 关机后保留的是公司工作事实，不是继续执行

中央沉淀以下经授权的内容：任务状态与责任关系、输入/成果及自动保存点、操作事件/结果/未知项、版本与来源、验收/候选记录、权限变更和用量回执。每项关联公司、任务/run、操作者/执行身份、来源和时间；敏感范围沿原政策保留，不因进入公司存储变成全员可见。“操作记录”不等于整机键鼠/屏幕监控，也不意味着采集个人文件、Cookie、Key 或全部原始模型会话。

保存发生在工作过程中，不依赖员工关机前手动提交，也不以关机钩子作为唯一保障。正常退出可以尽力补传，突然断电只承诺中央已确认部分；中央从未收到的字节不能靠状态日志重建。开机后先核对当前权限、版本、未完成工作与未知效果，再恢复获准运行，不直接重放所有旧操作。

已持久化的任务/资产和普通检索、审计、备份可继续提供服务；需要模型的复盘、摘要或 skill 提炼仍等待获授权本地 runtime，不能借“数据沉淀”在中央隐藏另一套 Agent。保存/沉淀不等于业务验收或 skill 自动发布。

### 2.6 记忆维护复用文档版本，不新建记忆系统

产品里的“记忆”是运行可消费的工作记录、项目/部门知识或方法引用，不是新增第四类资产。优先接入选定内容服务，不默认在 Multica 自建知识引擎；已允许飞书正文主存储，Docmost 保留自托管备选。Multica 复用统一入口、任务引用与执行接缝；Paperclip documents/document_revisions/annotations 只作历史语义参考。正文、修订、源 ACL 与附件由选定服务管理，缺口须单独核验；群原消息只作来源，不复制为第二份可编辑正文。受控版本附件可作为过渡载体，但不冒充已交付在线知识维护。

- 核心协作先在原任务纠正事实、留来源和形成候选；外部知识维护与表格连接器后接，不作首条切片依赖。后接后员工/负责人均能权内维护，加载范围/版本与条件恢复必须可核验，发布到部门/公司另验权。
- 编辑必须有可核验基础版本及源端原子条件或已验证等价协议，竞争时保留草稿/差异。旧 Paperclip restore 结论不外推到新服务；Docmost 当前公开写入 DTO 无 CAS，历史恢复为客户端正文替换，不能视为原子回滚。未验证条件保存前，Bot 只提建议/创建独立草稿，不开放任意 replace；代理先读后写或只串行代理请求不能防源站并发。批注/成果关联实际来源版本。
- Bot 运行只取得本 run 获准的知识版本引用/只读投影；本地临时笔记可在任务工作区自动保存，但不作公司知识唯一权威。两个任务不得共写同一 Bot MEMORY.md；正式知识改进作为有来源候选或获授权条件修改。
- 关闭记忆功能、停止在模型中加载、撤销内容访问、删除/保留是四件事。关闭入口不保证文件工具不能读取，真正撤权贯穿检索/本地投影/模型出口/历史/缓存；已送达管理员电脑的合法副本不能承诺远程全部擦除。
- 不复制 OMB 个人 memory-journal 的异步/无条件 Undo；其 team-memory 的 revision 规则与个人记忆不同。Undo/回退必须基于当前版本产生新变更，保留操作者、来源和冲突；日志缺口不得显示完整审计。引用知识换 owner 不换资产身份，保留与权限仍由公司政策决定。

历史源码反例与当前复用边界见 [复用研究](REFERENCE-REUSE.md)。不另定第二 memory/schema；自动整理与后台全库学习不进入首版，全部合格设备关机则等待，不在服务器代跑复盘。

### 2.7 文件提交、替换与验收不能沿用个人 Cloud 语义

上传沿 Multica 附件/文件载体补企业授权与版本，不再接 Paperclip issue attachments/assets。绑定公司、task/run/attempt、操作者和内容 hash，幂等重试返回同一确定版本，同键异字节拒绝；ACK 未知先查询对账。当前自动归档失败、手动上传成功且匿名 uploads 200 为 P0 失败，必须修复路径授权、预览/图片/Range/下载/缓存验权后再开放私密资料；不把裸 uploads 当公司资产库。公司持久确认前只显示待归档，来源 ACL 与任务当前权限取交集。

中央交付链接固定到字节版本，不能只引用设备绝对路径或可变工作目录。草稿可移除；已归档候选可撤回关联，已保留的交付/验收历史不经裸删除接口物理抹除。替换发新版本、校验当前基线，验收由指定有权责任人对明确版本记录；退回不改写旧验收。具体保留期/隐私纠正仍待 D03/D09，不等于永久保存。

OMB 个人 Cloud、借出目录、当前路径下载及默认记忆导出不搬；内容过滤不能只靠 .gitignore。旧 run 上传只按隔离证据协议收取，不覆盖当前成果。OP-05 继续验证上传幂等、替换、固定字节、权限与验收；细节见 [复用研究](REFERENCE-REUSE.md)，不建立第二资产权威。

### 2.8 个人/共享知识与结构化业务资料（2026-11-06）

知识库保存说明、事实、结论和来源；多维表保存可维护的结构化业务记录。它们与任务/skill 通过稳定引用关联，不互相替代：业务表的看板不是第二任务系统，表格行不默认复制成任务，skill 也不是业务记录数据库。

- 同一客户端内显示自己的工作资源与已授权资源；默认私有工作草稿可以按公司政策保留，但不能因此向全员开放。个人隐私不进入工作沉淀。
- 先有资产归属、维护人、资源 ID、当前版本/权限版本、来源和审计，再选正文或表格存储实现。知识版本、表记录版本和表结构版本分别追踪，不要求全部塞进 Git。
- 知识维护的最小闭环：员工创建/编辑→按权分享给小队→Bot 读取指定版本并引用→生成改进建议或获准条件修改→维护人确认→形成新版本，撤权后旧链接/缓存/检索不得继续提供内容。
- 多维表格的最小产品范围待分期确认：表/字段/记录编辑、筛选与授权视图、行/字段权限、变更历史、任务引用、Bot 受控读写。现成表格引擎负责业务表事实，Multica 仍是任务/run 唯一权威；中央可以存储和查询数据，不因此运行第二套 Agent。
- 不自研网格渲染、公式引擎和实时协同算法；优先成熟组件/可自托管服务。统一身份、委托上下文、授权边界、资产引用与审计对接是企业适配责任；不能把整库管理员 token 交给 Bot。
- **已确认顺序：**先跑统一客户端与 Agent 协作，知识/业务表外部连接器后接。其最小编辑范围和权限须另验；飞书可作为主存储但未最终替换，腾讯/企微无租户实测，本轮不展开新调研。

## 3. 权限继承与发布

已确认：部门内普通任务明细默认同部门可见；跨部门授权开放指定项目或任务及其对应业务流转。上述默认权限不覆盖敏感内容、私密群或受限来源的独立授权。普通任务的非敏感交付可沿其授权范围呈现；已有附件/资产的更严格权限必须保留，不能仅因关联任务或跨部门共享而被放宽。

- 消息摘要、检索片段、向量索引、缓存、报告和新 skill 都属于衍生内容，要继承来源的限制。
- 多来源合成默认不扩大任何来源的受众；需要扩大时，先脱敏/改写并按权限发布独立资产版本，保留来源关系。
- 检索时按当前身份过滤；提交给模型前和返回给群前再次检查。查询、后台 worker 和下载地址都不能绕过授权。
- 降权、离职、删除或隐私纠正需要失效相关检索索引与缓存。备份按保留策略处置，不承诺即时擦除所有历史介质。
- 若当前 Multica skill 载体无法表达部门/私密范围，先禁止敏感内容进入公司可读 skill；企业权限投影与下载/加载边界须补验。受限动态数据按请求授权读取，不能继承 Paperclip scope 假设。此为 P0 门禁。

### 3.1 MVP 的隔离粒度与不确定信息

- 任务标题、正文、状态原因、交接等核心字段共用任务 ACL；群消息、附件/资产是独立授权对象。不承诺任意字段级智能脱敏。此处指任务正文，不取消多维表格显式行/字段查看与编辑授权，后者按 §3.2 执行。
- 普通任务仅引用敏感附件时，任务本身可保持普通，但对无权受众不展示敏感附件名称、内容、索引片段或泄密摘要。关联不解除附件限制，也不自动让任务参与者加入私密群。
- 如果任务核心字段本身含敏感信息，或从受限来源生成而不能证明安全，则整条任务先按受限处理，发布前检查所有投影/缓存/计数/检索；不让模型自行宣布“已脱敏”来扩权。普通任务默认同部门可读的规则不变，含敏感信息的任务不归入普通类。
- 多来源摘要/产物按所有来源允许受众的交集授权；无法确定时隔离待审，不投递普通群。只有同时具有来源访问权与目标范围发布权的维护/发布者可审核独立安全版本；保留来源及审核记录，不改源 ACL。

### 3.2 知识/多维表权限强制点与失败条件（2026-11-06）

已确认：同表按行、字段分别控制查看和编辑，Bot 同样遵守。以下为待验证的执行契约，不是现成功能声明。

1. 默认拒绝。每次操作同时核验公司/资源权限、行范围与字段操作；字段可写不授予全表写权。创建/删除、结构变更、分享和导出单独授权；普通编辑不能通过改“负责人/部门”等权限条件字段给自己扩大范围。
2. 服务端先过滤行，再投影可见字段，再返回结果；不可把整表发给前端或模型后再隐藏。列表、单条、批量、搜索命中/总数、历史、实时推送、附件直链、导出、关联/公式/汇总均纳入授权。不能证明派生结果安全时拒绝/关闭该功能，不猜测性脱敏。
3. Bot 每次读取、工具调用、提交均携带可核验委托人、Bot、任务和当前授权范围；有效范围取这些约束的交集，并检查设备/管理人的承载资格。自动任务以明确的服务主体授权执行，不借“系统任务”获得全库权限。
4. 写操作须校验当前权限、基础版本和允许字段，防止先查询后撤权仍写入；混合合法/非法字段的单次写请求默认整体拒绝，不静默部分成功。批量事务/逐项回执语义须在实现前冻结，不以模型口头确认替代。
5. 资源撤权同时约束搜索索引、历史、缓存、实时订阅和未消费模型上下文；停止后续取数/提交，必要时重建受限会话。已被人或云模型读过的内容不能声称收回；已离线落地内容按既有设备安全边界处理。知识派生摘要或 skill 不自动扩大源权限。

**接入验证顺序：**先知识资源与附件原址的权限/撤权，再表格单条/批量 API 的行读、行写、字段读、字段写，再 Bot 委托及派生输出/撤权；最后才验多视图和协同体验。表格延期则其能力标 NOT RUN，不影响“未交付表格”的首版验收，也绝不能宣布表格权限通过。

**任一即 FAIL：**员工或其 Bot 能读无权字段/行；只靠 UI 隐藏；公开附件/历史/搜索/公式泄露受限内容；可用授权字段更新同时夹带禁止字段；改权限条件字段自提权；撤权后旧会话/令牌仍取得新数据或成功提交；使用管理员 token 逃避身份委托；跨部门共享一行开放整表。并发编辑旧版本不得覆盖新版本，冲突须可见。

### 3.3 外部知识源与 Bot 授权/版本接入（2026-11-06）

当前已允许飞书作为文档和业务表主存储，但尚未决定接入或替换；现用企业微信后的企微原生文档、腾讯文档企业版与 ima 证据见 REFERENCE-REUSE 当前参考研究，Docmost 是自托管备选。以下条件对所有候选适用；不改变行/字段四类权限要求，也不以购买授权替代安全验收。

- **资源引用而非重复正文库：**来源 provider/tenant/type/id 为稳定键，关联 task/run、维护人、源版本或读取证据、当前授权状态。源站文档附件仍走源站授权，不复制到 Multica 当前裸 uploads 来伪装统一预览；公司正式交付包按既有归档规则另行授权、留来源。
- **每次联合验权：**源权限、委托人授权、Bot grants、任务动作/资源范围和执行设备/管理人资格同时成立；能阅读不自动允许云模型外发、转发群、导出或分享。公开网页/索引/历史/附件 URL/实时会话与直接 API 都纳入验收。
- **撤销分层：**停用 morchat 用户、撤第三方 OAuth、源文档 ACL、MCP 安装/工具授权及已有协作会话分别测；SSO 或清 cookie 不保证撤销旧 token。撤权对已读副本不可逆这一边界不变，但后续读取/回源/提交必须阻断。
- **写入先收窄：**未证明原子条件更新时 Bot 仅生成独立草稿、评论或修改建议；不凭“读了最新版本”开放任意 replace。Docmost 当前公开核心 DTO 未提供 CAS；smart_table 服务虽有可选时间检查，已读 REST 入口未传，不能视为闭环。飞书目标工具的版本/幂等语义仍须实测。
- **权限变更与归档竞态：**提交点重验当前权限及版本；未知效果先对账，不盲重试造成重复文档/记录。记录 actor、delegator、Bot、task/run、资源、动作、结果、版本前后和供应商 request ID；日志不得含 token 或不必要正文。
- **离职与供应商边界：**公司租户/部门知识空间与个人工作区区分，停用后内容保留和维护权移交需可验；飞书正文存云端与“平台内部自托管”可并存，但不能再声称全部内容自托管。保留/导出/备份按政策，不默认全库同步。
- **场景判定：**两员工同页/同表协作时，可见范围和任务授权可以不同；共处一群、同部门、同一电脑或同一 Bot 都不是互用凭据的理由。多来源摘要向群投递仍取受众交集。

验证清单归 Discovery §4.6；此处是业务与安全语义权威，不新增第二套测试编号。

### 3.4 已确认的写入、公司接管与受控清理边界（2026-11-06）

Ethan 已确认下述范围；这是验收要求，不代表任何候选或现有客户端已实现。

1. **允许按权修改。**员工明确授权且源端、Bot、任务及执行设备资格同时满足时，Bot 可以修改既有内容。普通编辑不包含授权、结构或所有权变更。写入仍须通过 §3.2 的冲突/撤权门禁；只能生成建议是临时降级，不是完成读写需求。
2. **工作资产从创建起归入公司可接管范围。**优先公司租户/受管知识空间，记录维护人及接管责任人；个人工作区是可见性边界，不等于个人私产，也不开放全公司查看。纯个人隐私不纳入。离职流程须停用身份/委托、交接内容/附件/版本和未完工作、验证接管，再完成对账；不能依赖离职者重新登录、交出密码或把受限文档公开。供应商原生转交优先复用；公司合法接管范围、失败清单与人工补救要可审计。
3. **撤权不是删除公司原件。**对被撤权主体停止读取、检索、工具提交、后台同步和旧任务续用。清理平台及受控客户端的正文/附件临时副本、预览、离线副本、搜索片段/向量投影、摘要、Bot 记忆与会话上下文；继承来源限制的衍生内容一并失效。共享公司资产及其他仍获授权主体的索引不无差别销毁，但当前授权过滤不可绕过。模型中已发出的内容无法收回；丢弃旧上下文并重建获授权会话，拒收迟到输出，不宣称云端数据已被擦除。
4. **两个独立回执。**记录“访问已阻断”和“受控缓存清理完成”，包括主体、资源/授权代次、设备/存储范围、截止时间、失败项。发出清理命令不是清理成功；状态未知时关闭受限读取/执行并显示待处理。服务端在已知权威撤销后新准入/提交不得继续沿用旧权；源 ACL 的传播上限和在线清理时限必须在 KD-03 前冻结并实测，不承诺零延迟。
5. **敏感资料禁止离线使用。**受控客户端断网后不得继续用敏感正文或缓存运行 Bot；重连先撤销对账、清理旧代次并重新授权，后恢复任务。离线设备不虚报远程已清理，仍显示待清理；此前允许的非敏感检查点/待归档副本遵守 §2.3 和当前授权，不能借此保留已撤权可读副本。未归档的敏感成果若无法安全保存/恢复，任务标阻塞并记录损失，不能靠无限期本地留存规避。
6. **边界已接受。**不承诺远程抹掉员工管理员自行下载、复制、截图或离线设备上的任意副本，不承诺存储介质取证级擦除。供应商自有缓存/模型留存另按供应商契约验，不冒充平台可控范围。公司原件、归档及必要审计依现行权限和保留政策保存；备份不是可供被撤权者读取的缓存，恢复时必须应用当前撤销状态，不能复活旧授权。

最小落地只补身份/任务范围桥、来源与资产接管清单、可核对的撤销传播/清理回执，不重做编辑器、知识库引擎或多维表格后端。不能可靠标识并清理 DSH/桌面壳产生的受限数据时，该内容类型不得上线；不是在文档写一句“清缓存”就视为闭环。


## 4. 从经验到 skill 的 MVP 闭环

完整产品使用方式见 [六步流程与能力定义](PRODUCT-LIFECYCLE.md)。复盘区分项目事实/知识、岗位约定、团队组合和通用方法；不是把所有聊天总结成技能。

### 4.1 Bot 模板、实例与可复用能力的权威

- **Bot 模板/实例：**Bot 是 AI 同事，实例对应唯一稳定 Multica Agent ID；模板是有独立版本的配方。更新、换设备或组队不换身份；模板不带旧授权、个人记忆或会话。
- **岗位入职包：**职责/不做事项、输入输出、材料引用、配置/指令快照与 skill 版本、工具需求、就绪样例。真人/Bot 都可引用，不另建身份；安装不授予资料/设备/发布权。
- **小队模板/实例：**真人/Bot 槽位、能力/岗位包版本、任务蓝图与交接验收、参数和维护责任；实例优先绑定已有成员并保存采用版本。无旧会话、凭据、grants 或完成状态，模板升级不热改现有小队。
- **skill：**方法正文/资源优先 Multica 现有载体；不可变版本、候选隔离、评估和发布缺口逐项验证，不能声明已有 Paperclip managed fork/Studio/test API。评估执行统一走 Multica task/run 与本地 DSH。

员工/负责人按权维护；部门/公司发布另查来源访问及目标发布权。源私密材料不因总结而公开；必要时生成独立安全 ACL 根的脱敏资产，不扩旧身份的历史可见性。任意插件/preset 不是业务模板。

能力清单只关联唯一正文载体的配置、指令、skill、模板版本、变更人/原因/时间、评估和生效记录；不再造可编辑正文库。hash/活动记录不能代替可取回字节；自动保存内容与 GC 保留根须验证，任务检查点也不自动覆盖 Bot 公共文件。缺版本/归档失败阻塞生效或新 run；不伪造 revision，不用浮动 latest，不要求员工手动 commit。每次 run 独立关联实际消费组合，权限/凭据不因回退复活。

### 4.2 候选、验证、发布、使用与撤回

1. **捕获：**原 task/run、交付版本、错误/成功依据、期望和来源 ACL，只处理获授权材料，不默认巡检全群。
2. **候选：**隔离基础版本、最小 diff、正文/资源 hash、适用/失效条件和维护人；不得直接试改生产 skill。具体隔离载体需 B03/B04 验证。
3. **验证：**原案例与不同输入各留独立输入版本、预先标准、Multica 评估 task/run、输出和真实费用；执行成功不等于业务通过。保留失败结果，不由生成者自报替代有权评判；重测不能破坏已发布版本所需旧证据。
4. **发布：**重验来源/受众、发布人和当前基础版本，经条件生效；失败、过期或证据缺失不发布。不把保存/latest/release 字段当企业批准，不假定跨服务原子性，C03 生效点仍 DRAFT。
5. **使用：**新 run 固定获准组合和输入，DSH 只挂本次只读版本投影，关闭未授权私人/项目 roots；核对正文/资源及工具/slash/环境注入。缺失、unsupported、同名覆盖或 hash 不符阻塞，不能退 latest；目录 digest 不等于正文加载证据。
6. **撤回：**观察验收、人工修订、失败和费用；停新使用问题版，条件回退已获准内容并形成新生效记录。运行中不热换、旧记录不改，撤权按当前政策暂停/终止并重建授权上下文。

**三层证据分开：**新 run 选用版本、准入/接续保存的实际组合、设备实际加载。Multica 每层均须核验；参考产品的开关、快照字段、sync 成功不继承为本底座保证。公司保留评估输入/模板/版本、输出资产、运行/成本和评判，处理保留期、清理、GC 和撤权传播；不能只留到期失效链接。

### 4.3 首版证据与参考边界

至少证明“纠错→隔离候选→两类案例→业务评判/授权发布→另一员工新任务真正复用”；保留评估失败、过期候选冲突、撤权拒绝和回退后加载验证，LC-09–12 待验。

Paperclip 的 Reflection Coach、配置/指令历史差异、Beta pin 与测试替代/到期，OMB 的候选/base hash/过期 Undo 作为治理参考与固定反例。OMB Ask 也可能 direct apply，其 bench 估算 token 不是业务/成本实证；不导入其 Store/chat/runtime/导入器。独立 helper 必须重接 Multica 授权/事件并核依赖/许可，不能把参考 API 换名声称已实现。

自动批量提炼、无界建 Bot、自动全员发布、训练模型和平台/harness/插件自修改不在首版。完整旧证据保留于 迁移前资产文档。

### 4.4 历史和测试材料也受当前权限约束

测试输入/模板/run 快照及输出不会因任务到期自然解除私密来源限制。所有历史、列表、详情、下载、检索、模型输入和群投递检查当前来源政策；修复验证前共享测试仅用合成或已明确公开案例。候选与已发布 skill 可读不等于测试私密数据可读。

断开来源不消除限制；脱敏扩大传播用独立安全资产/skill 身份，不放宽含旧私密版本的 identity。候选保留来源 ACL，评审不能让真实私密内容凭空消失。

任务目录沿 Multica；知识检索后接内容服务的当前授权查询，不复制全库正文建第二索引。必要治理/关联索引与幂等回执同样验当前权限，旧请求成功不授予永久读权。保留期、GC 与隐私纠正按 B04/C04 和治理决策落实，不用参考项目 issue 搜索冒充知识权限。

## 5. 离职与调岗

**已有原生底座（2026-11-06 源码核实）：**`workspace_revoke.go` 的成员退出/移除事务会停用其 runtime、归档绑定 Agent、取消相关未完运行、清调用与借机 grants/订阅；handler 会断开在线成员与失效成员缓存，客户端清 workspace 草稿和本地搜索。公司任务/评论留存，重新邀请不恢复旧 grants。必须复用，不能把离职撤销/缓存清理整体列成自建。它只覆盖相应 workspace 和所列数据，未证明全公司身份、其他人的公共 runtime 上由离职者发起的所有工作、DSH 会话/记忆/文件缓存都已清理；删除索引的错误也未形成完成回执。

下列步骤是在上述事务之上补公司范围编排、维护责任/连接与未上传材料交接、受控数据清理结果及离线补偿，不改写第二套成员库。访问阻断、服务端取消、设备实际停止、缓存已清分别验收；部门调岗不能通过删除整工作区或公司原件完成。

交接是可重试、可审计的流程，不是删除用户或调用 Paperclip archiveMember。基于 Multica 的真实账号、任务/Bot 和运行逐项核验可复用能力，补目标/模板/AI/资产维护责任、设备池、连接和未上传缺口；账号停用不自动证明内容/责任已交接。步骤与停止/效果对账协调，清锁或撤租约不等于旧进程已停：

1. 冻结新登录、账号/设备令牌与后续授权动作；运行在受控工具/投递点重新检查。离线设备不能瞬时收到中央撤销，按短租约和断联停止新动作处理，不承诺远程收回已合法下载的副本。
2. 列出未完成任务、负责的目标、群、AI、已归档资产、待上传缺口及连接依赖；记录旧 run/租约与已知或未知动作。未知副作用未核对前不自动再派执行。
3. 指定接手人或部门待接管队列；未明确接手的资源不得静默丢弃。
4. 转移维护责任和必要访问权，保留原创建者及历史审计；接手不意味着获得全部个人隐私。
5. 公司凭据保持公司管理；个人 OAuth/电脑依赖必须替换或暂停相关能力，不能只改 owner 字段。
6. 形成交接包：任务检查点、获授权工作摘要、输入/产物资产 ID 与版本、harness/工具/skill 版本和依赖清单、剩余步骤/责任人。只交接工作必要内容，不复制整个个人 HOME、私密非工作记忆、Cookie 或个人登录态。
7. 旧租约失效但账号/设备仍有效，只可重新申请限旧 run 的证据上传，入隔离区核对；已撤销账号/设备旧凭证全部拒收。由具材料权限的接管人以自己的获授权恢复导入收集可取回工作材料，不复活旧身份。异常/未知结果或离职人工接管时，由具有任务管理权和证据访问权的责任人记录缺口、核对产物后批准接续；安全条件已验证的公用池接续按下条策略执行，无证据不自动解除未知副作用阻塞。
8. 新设备重新校验当前授权，设备与管理人都须有交接资料的对应权限，不能只转 Bot/任务 owner 而忽略宿主；超出原授权范围才另行申请；公用 Agent 满足 R1（共享写入已隔离且可安全重算）或 R2（旧执行/资源可信终止）的接续条件，检查点及其后已提交效果已对账且无未知项时按预授权池自动接续，异常/未知结果仍由有权责任人核对。默认从中央资产/检查点建立接续 run；不承诺任意 CLI 原始会话跨设备可迁移。验证继任者能继续、旧身份与租约不能继续动作，最后归档成员身份；仅已上传并确认内容能由中央保证提供给接手者。

个人隐私独立排除，误归档内容有纠正通道。保留期限、特殊调查访问和离职交接的公司制度说明需由 Ethan 指定责任人确认；技术不能擅自承诺永久保留或全员透明。

## 6. 首版验收

- 无权员工不能通过搜索、AI 问答、附件链接、摘要或另一个群得到受限内容。
- 成果与 skill 均能追溯来源；发布后改变源权限不会让旧索引继续泄露。
- 原维护人离职后，公司资产和非个人连接仍可由授权继任者维护；无法替换的个人依赖明确显示阻塞。
- 能导出必要成果、skill 包及元数据；备份恢复后权限和来源关系仍有效。
- 一次错误经验不会未经验证自动成为全公司的默认规则。
- 验证本地产物上传失败/重试、版本冲突、缓存满额、旧租约迟到产物和换设备接续；无归档确认不算交付，秘密和个人目录不进入资产库。
- 模拟设备丢失：已提交资产和工作检查点按权限可接管，未上传内容明确不可恢复/待找回，不伪造“全部知识已保留”。
- 验证公用 Agent 跨池节点接续与并行产物版本冲突；无私人会话迁移、无覆盖他人交付、无因选机改变数据受众或费用归属。
