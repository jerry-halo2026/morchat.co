## 1. 三类内容，不混成一个记忆库

| 层次 | 内容 | 用途 |
|---|---|---|
| 工作记录与成果 | 消息、任务、文件、报告、决策依据、必要运行证据 | 交接、追溯和复盘；不自动成为通用知识 |
| 业务知识与上下文 | 指标口径、业务事实、项目结论、失效日期和适用范围 | 按当前权限检索；有来源、可纠正 |
| 可复用能力 | skill、SOP、检查清单、角色/小队协作模板 | 有版本、适用条件、测试案例和维护责任 |

工作流模板不是本期资产类型的必需实现。工作方法可以先以 skill、SOP 和小队协作模板沉淀，不依赖低代码引擎。

## 2. 资产模型的最小要求

每项资产记录：公司、类型、稳定 ID、来源任务/消息/运行、执行设备/工作空间及 harness/工具版本、内容哈希、创建者、管理部门、维护人、版本或正文引用、可见/可用/可编辑/可发布范围、状态、保留规则、依赖和变更审计。

公司归属与个人创建者分开；部门是管理责任范围，维护者可更换。仅在明确授权下生成部门/公司可复用版本，不通过改标签把私密资料直接公开。

skill 正文与版本优先复用 Paperclip；公司资产目录保存索引、策略和评估关联，不再另建一份独立可编辑的 skill 正文。运行快照/交付包是受控副本，不反向成为编辑源。

### 2.1 本地文件与正式交付

临时工作空间和员工电脑不是正式公司资产的唯一存储。生成/选择文件后，经过类型/大小/内容安全检查、内容哈希校验、上传与版本登记，中央存储提交确认后展示已归档；完整保存点与当前授权满足才可接手，指定责任人验收后才展示正式交付；上传失败或离线时显示待归档，不以本机路径或 AI 口头完成替代。重试使用防重标识，冲突保留可辨认版本，不静默覆盖。

只同步获准工作目录、选定输入和工作产物，不整盘采集。浏览器 Cookie、模型 Key、个人隐私、全局环境和不必要原始运行日志不进入公司知识库。产物保留任务、设备、执行身份和能力版本来源，不要求复制整个运行环境。模型外发与公司留存分别检查；本地文件可读并不自动允许发送给云模型。

Skill/SOP 如依赖浏览器、Python/Node、运行库或特定文件能力，应声明版本与所需能力，凭据只用引用，目录参数化；安装 skill 不自动授予这些权限。可复用能力不能绑定某位员工的私人路径或登录态。运行记录固定实际使用版本，换设备后的可复现性需要验证。

### 2.2 跨设备上下文与并行产物

群共享上下文包记录任务/目标版本、必要可读消息及历史范围、输入资产版本、Bot 配置/指令内容快照/skill 版本、权限版本和事件游标；不同步全部个人模型会话、私人目录或 Cookie。运行会话/工作区按 task/run 隔离，共享 Agent 的两个任务也不写同一份可变记忆。新决策/撤权以版本增量通知，交付前重新检查，不盲用旧快照。

暂存/上传成功不自动等于正式资产发布或任务交付；转为正式关联/投递时须在提交生效处验证代次、版本和权限，旧 run 的迟到数据仅隔离为证据。恢复清单要包含检查点之后已发布资产和已创建子任务，不能因旧检查点不含它们而重复发布/创建。

并行产物以独立 run 和资产版本保存；更新同一正式资产必须校验基础版本并显式合并/审核，不能最后写入覆盖他人结果。可复用知识/skill 更新走候选与发布，不以设备内本地记忆覆盖公司正文。费用和公司归属跟业务责任走，执行设备/设备管理人不是自动的费用承担者或内容所有者。

部门公用 Agent 换池节点不改公司 Agent、任务和资产身份；维护人离职后移交维护/池授权责任，不删除公共身份或复制个人登录。设备必须持续获准承载资料：新资产、上下文增量和旧会话在首次送到宿主/授予获取能力前核验；同任务新身份也不能恢复无权旧 session。资料升敏或权限收紧时暂停/按授权重建；有算力权不等于有权处理一切公司数据，无法保证已送达资料可从失联宿主收回。

### 2.3 离线缓存不是公司备份

完整 harness 在员工设备执行，检查点、工作摘要、必要运行证据和成果由系统自动在工作单元/等待边界保存并按周期兜底，失败自动有界重试；不依赖员工手动保存、Git 提交或补传，模型也不负责决定是否保存。最小本地恢复/回传缓存需加密、有容量上限、可重试；满额暂停并提示，未收到公司提交确认前不删除唯一待上传副本。不可将本地记忆或工作目录当作公司资产唯一权威。

断联不继续自主调用模型或新工具；已有允许保存的输出标为待归档，重连先核对身份/租约与来源，再提交。迟到的旧运行成果可作为证据隔离核对，不能直接覆盖当前交付。失联设备损坏前未上传的数据可能无法恢复，离职或资产面板必须展示缺口，不声称零数据损失。

### 2.4 工作中间态与完整交接版本

不能只留最后成果。[任务与工作空间接续](D:/dev/morchat.co/docs/WORKSPACE-CONTINUITY.md) 定义代码/Git 与普通目录两类适配，保存任务进度、已确认效果、精确文件/Git 状态、依赖及权限来源；受控对象先持久化再发布权威任务关联。保存点可恢复不等于候选成果已验收；未上传内容不在公司恢复保证内。快照包含 Git 历史时核验全部历史授权，分支不是保密边界。R1/R2 接续须分别验证，不复制私人会话/凭据。

### 2.5 关机后保留的是公司工作事实，不是继续执行

中央沉淀以下经授权的内容：任务状态与责任关系、输入/成果及自动保存点、操作事件/结果/未知项、版本与来源、验收/候选记录、权限变更和用量回执。每项关联公司、任务/run、操作者/执行身份、来源和时间；敏感范围沿原政策保留，不因进入公司存储变成全员可见。“操作记录”不等于整机键鼠/屏幕监控，也不意味着采集个人文件、Cookie、Key 或全部原始模型会话。

保存发生在工作过程中，不依赖员工关机前手动提交，也不以关机钩子作为唯一保障。正常退出可以尽力补传，突然断电只承诺中央已确认部分；中央从未收到的字节不能靠状态日志重建。开机后先核对当前权限、版本、未完成工作与未知效果，再恢复获准运行，不直接重放所有旧操作。

已持久化的任务/资产和普通检索、审计、备份可继续提供服务；需要模型的复盘、摘要或 skill 提炼仍等待获授权本地 runtime，不能借“数据沉淀”在中央隐藏另一套 Agent。保存/沉淀不等于业务验收或 skill 自动发布。

### 2.6 记忆维护复用文档版本，不新建记忆系统

产品里的“记忆”是运行可消费的工作记录、项目/部门知识或方法引用，不是新增第四类资产。知识正文/版本优先复用 Paperclip documents/document_revisions/annotations，文件/附件继续复用已有资产；群原消息只作来源，不复制为第二份可编辑正文。无法由既有类型承载的材料先用受控版本附件，不先建通用知识引擎。

- P1 能在原任务/文档纠正事实、记来源和形成候选；P2 补按权知识维护入口、加载范围/版本显示和受控恢复。员工/负责人都有权内维护入口，发布到部门/公司另验权。
- 编辑必须带当前 baseRevisionId，竞争时保留草稿与差异，不最后写入获胜。固定样本的原生 restore 未带 expected base：通过“读历史正文→用当前基线条件更新”追加版本，或评审最小原生 CAS 扩展；不能用无条件恢复覆盖别人新改动。批注也固定对应版本。
- Bot 运行只取得本 run 获准的知识版本引用/只读投影；本地临时笔记可在任务工作区自动保存，但不作公司知识唯一权威。两个任务不得共写同一 Bot MEMORY.md；正式知识改进作为有来源候选或获授权条件修改。
- 关闭记忆功能、停止在模型中加载、撤销内容访问、删除/保留是四件事。关闭入口不保证文件工具不能读取，真正撤权贯穿检索/本地投影/模型出口/历史/缓存；已送达管理员电脑的合法副本不能承诺远程全部擦除。
- 不复制 OMB 个人 memory-journal 的异步/无条件 Undo；其 team-memory 的 revision 规则与个人记忆不同。Undo/回退必须基于当前版本产生新变更，保留操作者、来源和冲突；日志缺口不得显示完整审计。引用知识换 owner 不换资产身份，保留与权限仍由公司政策决定。

源码证据集中在 [复用 §4.5.3](D:/dev/morchat.co/docs/REFERENCE-REUSE.md)，避免在各模块另定 memory/schema。自动整理和后台全库学习不进入首版；全部合格设备离线时也不在服务器偷跑复盘模型。

### 2.7 文件提交、替换与验收不能沿用个人 Cloud 语义

首次上传优先原生 issue attachments/assets，补绑定公司/任务/run/attempt/操作者/内容 hash 的业务幂等；重复请求返回同一确认版本，同幂等键异字节拒绝。公司提交确认之前只显示待归档，不允许“已交付”；ACK 不明时查询/对账而不是再建一份。来源 ACL 与当前 task 权限取交集，预览/图片/Range/下载和缓存回执一致执行。

中央交付链接固定到字节版本，不能只引用设备绝对路径或可变工作目录。草稿可移除；已归档候选可撤回关联，已保留的交付/验收历史不经裸删除接口物理抹除。替换发新版本、校验当前基线，验收由指定有权责任人对明确版本记录；退回不改写旧验收。具体保留期/隐私纠正仍待 D03/D09，不等于永久保存。

OMB 的个人 Cloud 同步、借出目录、当前路径下载、默认记忆导出都不搬；获准目录和内容安全过滤不能只靠 .gitignore。旧 run 上传只按既有隔离证据协议收取，不覆盖当前成果。具体上游路径见复用 §4.5.2，OP-05 验证这一条链，不新增对象存储或资产权威。

## 3. 权限继承与发布

已确认：部门内普通任务明细默认同部门可见；跨部门授权开放指定项目或任务及其对应业务流转。上述默认权限不覆盖敏感内容、私密群或受限来源的独立授权。普通任务的非敏感交付可沿其授权范围呈现；已有附件/资产的更严格权限必须保留，不能仅因关联任务或跨部门共享而被放宽。

- 消息摘要、检索片段、向量索引、缓存、报告和新 skill 都属于衍生内容，要继承来源的限制。
- 多来源合成默认不扩大任何来源的受众；需要扩大时，先脱敏/改写并按权限发布独立资产版本，保留来源关系。
- 检索时按当前身份过滤；提交给模型前和返回给群前再次检查。查询、后台 worker 和下载地址都不能绕过授权。
- 降权、离职、删除或隐私纠正需要失效相关检索索引与缓存。备份按保留策略处置，不承诺即时擦除所有历史介质。
- Paperclip 原生 skill scope 若无法表达部门或私密范围，不把敏感内容放进公司可读 skill；受限数据通过按请求授权的工具读取。此为 P0 接入门禁。

### 3.1 MVP 的隔离粒度与不确定信息

- 任务标题、正文、状态原因、交接等核心字段共用任务 ACL；群消息、附件/资产是独立授权对象。不承诺任意字段级智能脱敏。
- 普通任务仅引用敏感附件时，任务本身可保持普通，但对无权受众不展示敏感附件名称、内容、索引片段或泄密摘要。关联不解除附件限制，也不自动让任务参与者加入私密群。
- 如果任务核心字段本身含敏感信息，或从受限来源生成而不能证明安全，则整条任务先按受限处理，发布前检查所有投影/缓存/计数/检索；不让模型自行宣布“已脱敏”来扩权。普通任务默认同部门可读的规则不变，含敏感信息的任务不归入普通类。
- 多来源摘要/产物按所有来源允许受众的交集授权；无法确定时隔离待审，不投递普通群。只有同时具有来源访问权与目标范围发布权的维护/发布者可审核独立安全版本；保留来源及审核记录，不改源 ACL。

## 4. 从经验到 skill 的 MVP 闭环

完整产品使用方式见 [六步流程与能力定义](D:/dev/morchat.co/docs/PRODUCT-LIFECYCLE.md)。复盘区分项目事实/知识、岗位约定、团队组合和通用方法；不是把所有聊天总结成技能。

### 4.1 Bot 模板、实例与可复用能力各有权威

- **Bot 模板/实例：**Bot 是 AI 同事，实例映射唯一原生 Agent；模板是创建/受控更新的配方，优先原生 AGENTS 包。能力升级不换身份，不因组队或运行克隆新 Bot；模板不携带旧授权、个人记忆或会话。
- **岗位入职包：**职责/不做事项、输入和交付标准、学习材料、Bot 配置 revision、指令内容快照与 skill 版本引用、工具需求和就绪样例。可供真人学习或被 Bot 模板/实例引用，不单建 AI 身份。当前指令正文在 Paperclip 编辑，历史证据只保存不可变快照，不新增可编辑指令库。安装包不授予资料、设备或发布权。
- **小队模板：**真人/Bot 槽位、Bot 模板/能力和岗位包引用、原生任务蓝图与交接/验收映射、参数及维护责任；实例绑定已有真实成员/Bot，保存目标/群/任务 ID 和确定版本。模板无旧会话、个人记忆、凭据、现成 grants 或任务完成状态。
- **skill：**方法正文/资源与不可变版本优先 Paperclip 原生；测试输入/模板/运行也复用原生。morchat 只补业务评价、传播范围、授权发布和维护/效果记录，不能再建一个可编辑正文库或评测执行平台。

员工与负责人都能在授权内创建维护，部门/公司发布单独检查。模板是配方，不复制原实例；任意插件/preset 不是业务模板。源材料私密不因“总结”自然消失，审批发布也不能自动绕过源权限；需经可证明的脱敏/重新授权，无法证明则保持较窄范围。

Bot 版本记录不是另建一套正文：配置历史复用 agent_config_revisions，skill 复用原生版本；当前 managed 指令文件的新保存不追加完整历史，history 接口主要兼容旧记录。每次受控生效优先复用原生 durable blob/manifest 并补历史保留根，或接既有保留资产；缺失历史的模板包用固定来源/既有版本资产，保留原来源与字节 hash，不要求员工手动提交。hash/活动记录不能代替可取回的内容，项目保存点不自动覆盖 Bot 公共文件。证据见 [Paperclip §2.2](D:/dev/morchat.co/docs/PAPERCLIP-BASE.md)。

morchat 的 Bot 能力版本清单只关联配置 revision、指令快照、skill 版本、模板来源、变更原因、操作者/时间、评估和生效记录；不含秘密、私人记忆或旧授权。run 记录实际使用组合；模板/skill 更新不静默改现有 Bot/小队，回退不改变身份或旧运行，也不复活已撤销访问。归档失败或版本不一致时阻塞生效/新 run；自动回写与原生入口无法遵守门禁时先不开放。完整关系见 [产品流程 §1、§3.6](D:/dev/morchat.co/docs/PRODUCT-LIFECYCLE.md)。

### 4.2 候选、验证、发布、使用与撤回

1. **捕获：**记录原 task/run、交付版本、错误/成功证据、期望结果和来源 ACL；只选当前有权处理的工作内容，不默认巡检所有群。
2. **候选：**优先原生 managed fork 隔离，保留基础 skillVersionId、diff、正文/引用资源 hash、适用/失效条件及维护人。原生编辑推进 currentVersion，不能在未固定生产绑定时直接试改 live skill。
3. **验证：**原生 test-inputs/templates/runs 承载真实 skill_test issue 和成本；至少原案例与不同输入各有独立 inputId、预先验收标准和结果证据。按 native 规则处理同 input 的 supersede；避免多个自由文本 null input 相互取代。执行 succeeded 不是业务质量合格；有权评审者记录事实、权限和回归判断。
4. **发布：**再验来源/受众、发布者及基础版本；失败或过期候选不发布。更新受控的已发布版本组合/Agent 绑定，不依赖 currentVersion 或内置 release 字段代表企业审批。正常维护不强制所有协作人工逐步审批，扩权和公司传播另守授权。
5. **使用：**新任务记录获准版本，Paperclip 留准入快照；DSH 仅挂 run 的只读版本投影，禁默认私人/项目 roots，核对正文/资源实际加载，包含工具/slash 路径。缺版本、unsupported 或 hash 不符阻塞，不静默回退 latest。
6. **观察与撤回：**关联新任务的验收、人工修订、失败和真实成本。停止新使用问题版，显式绑定旧获准版本或原生恢复旧内容追加新版本后再发布；运行中不静默换版，历史不改写。源权限撤销仍按当前授权停用/重建，版本固定不能豁免安全要求。

**评测证据留存：**固定 Paperclip 样本的同 skill/input 重跑会取代旧测试，旧 harness issue 默认七天到期。发布关联需在到期前确认受公司保留策略控制的证据：原生 ID、输入/模板/Agent/skill 快照、输出资产版本、成本与评审记录；必要时归档不可变证据到公司资产，引用原生来源而不新增可写测试运行权威。保留期、清理影响及撤权传播须在 P0 验证，不能留下失效链接仍声称可审计。

**三层版本区别：**普通新 run 的 Agent 历史 pin 受 enableBetaSkills 约束；已准入 run 的 contextSnapshot.skillVersions 原生已有，恢复使用该 map，Studio 测试固定保存版本；设备端实际加载仍须适配。skills/sync 返回 unsupported 不代表部署完成。详见 [Paperclip 能力契约](D:/dev/morchat.co/docs/PAPERCLIP-BASE.md)。

### 4.3 首版证据与参考边界

至少证明一次“纠错→隔离候选→两类案例验证→业务评审/授权发布→另一员工新任务实际复用”；还要证明评估失败、过期候选、撤权不泄露、回滚后新任务用正确版本。对应 LC-09–12；当前均未执行。

Paperclip 原生 Reflection Coach 的证据→最小 diff→提案/replay 案例可复用；OpenMausBot 候选暂存/base hash/过期撤销可选择性借鉴，但其 Ask 模式也可能 direct apply，并非只有 Full 会自动应用；后台 direct update 不是公司发布政策，其 skill bench 是 scripted-provider、token 为估算，不能当真实模型业务效果或成本。固定证据见 [复用研究](D:/dev/morchat.co/docs/REFERENCE-REUSE.md)。

自动批量提炼、无界自建 Bot、自动全员发布、模型训练和平台/harness/插件自修改都不在首版。持续升级指上述有证据的能力迭代。

### 4.4 历史和测试材料也受当前权限约束

Paperclip 原生 test-input/template/run 的快照及输出不是天然与原私密任务 ACL 取交集；测试 issue 到期后快照仍可能存在。关联持久来源政策，列表、详情、下载、检索、模型输入与群投递都验当前权限。修复验证前共享测试只用合成/已明确公开案例，不用真实私密客户资料演示“公司可用 skill”。

断开 skill source 不是解除源限制；历史一般随当前 skill ACL 判断。脱敏后需扩大传播时，使用独立 ACL 根的安全资产/skill 身份，不直接放宽包含旧私密版本的 identity。候选 fork 保留来源限制；经评审不能凭空消除真实私密内容。

资产目录与搜索优先复用 Paperclip 已支持的 issue/project 条件；只索引自有消息/业务资料和关联元数据，不复制所有原生内容。幂等缓存回执同样验当前资源权，不因旧请求曾成功而返回已无权正文。历史保留期、GC 根和私密纠正由 D03/D09 决定，参见 [发现 F01/F06–F09 与 G3](D:/dev/morchat.co/docs/DISCOVERY-BASELINE.md)。

## 5. 离职与调岗

交接过程是可重试、可审计的流程记录，而不是一次删除用户调用。优先复用 Paperclip archiveMember 对未完真人承接任务的转派、授权撤回和连接访问清理；morchat 补目标/岗位包/小队模板/AI 维护责任、设备池和未上传缺口，不能假设原生归档已经完成全部交接。调用顺序需与运行停止/效果对账协调，不能将原生清锁当旧进程已停：

1. 冻结新登录、账号/设备令牌与后续授权动作；运行在受控工具/投递点重新检查。离线设备不能瞬时收到中央撤销，按短租约和断联停止新动作处理，不承诺远程收回已合法下载的副本。
2. 列出未完成任务、负责的目标、群、AI、已归档资产、待上传缺口及连接依赖；记录旧 run/租约与已知或未知动作。未知副作用未核对前不自动再派执行。
3. 指定接手人或部门待接管队列；未明确接手的资源不得静默丢弃。
4. 转移维护责任和必要访问权，保留原创建者及历史审计；接手不意味着获得全部个人隐私。
5. 公司凭据保持公司管理；个人 OAuth/电脑依赖必须替换或暂停相关能力，不能只改 owner 字段。
6. 形成交接包：任务检查点、获授权工作摘要、输入/产物资产 ID 与版本、harness/工具/skill 版本和依赖清单、剩余步骤/责任人。只交接工作必要内容，不复制整个个人 HOME、私密非工作记忆、Cookie 或个人登录态。
7. 旧租约失效但账号/设备仍有效，只可重新申请限旧 run 的证据上传，入隔离区核对；已撤销账号/设备旧凭证全部拒收。由具材料权限的接管人以自己的获授权恢复导入收集可取回工作材料，不复活旧身份。异常/未知结果或离职人工接管时，由具有任务管理权和证据访问权的责任人记录缺口、核对产物后批准接续；安全条件已验证的公用池接续按下条策略执行，无证据不自动解除未知副作用阻塞。
8. 新设备重新校验当前授权，设备与管理人都须有交接资料的对应权限，不能只转 Bot/任务 owner 而忽略宿主；超出原授权范围才另行申请；公用 Agent 满足 R1（共享写入已隔离且可安全重算）或 R2（旧执行/资源可信终止）的接续条件，检查点及其后已提交效果已对账且无未知项时按预授权池自动接续，异常/未知结果仍由有权责任人核对。默认从中央资产/检查点建立接续 run；不承诺任意 CLI 原始会话跨设备可迁移。验证继任者能继续、旧身份与租约不能继续动作，最后归档成员身份；仅已上传并确认内容能由中央保证提供给接手者。

个人隐私独立排除，误归档内容有纠正通道。保留期限、特殊调查访问和离职交接的公司制度说明需由 Ethan 指定责任人确认；技术不能擅自承诺永久保留或全员透明。

## 6. 首版验收

- 无权员工不能通过搜索、AI 问答、附件链接、摘要或另一个群得到受限内容。
- 成果与 skill 均能追溯来源；发布后改变源权限不会让旧索引继续泄露。
- 原维护人离职后，公司资产和非个人连接仍可由授权继任者维护；无法替换的个人依赖明确显示阻塞。
- 能导出必要成果、skill 包及元数据；备份恢复后权限和来源关系仍有效。
- 一次错误经验不会未经验证自动成为全公司的默认规则。
- 验证本地产物上传失败/重试、版本冲突、缓存满额、旧租约迟到产物和换设备接续；无归档确认不算交付，秘密和个人目录不进入资产库。
- 模拟设备丢失：已提交资产和工作检查点按权限可接管，未上传内容明确不可恢复/待找回，不伪造“全部知识已保留”。
- 验证公用 Agent 跨池节点接续与并行产物版本冲突；无私人会话迁移、无覆盖他人交付、无因选机改变数据受众或费用归属。
