# 首轮连续开发范围与授权

版本：R1-AUTH-r1，2026-11-06。授权来源：Ethan 明确批准“三个切片连续开发和持续授权边界”，并要求同步正确 docs 后供新会话连续执行。
本文件只登记范围、动作授权和阶段终态；协议状态仍由 Discovery 登记，任务顺序由 PLAN/执行计划管理，不建立第二套契约。

## 1. 连续目标与不再讨论的决定

MC-00 收束 → 无模型权限验证及最小修复 → 首轮三个切片开发 → 同一候选版本集成验收。准备完成不是 Goal 终点，不需要再次询问“是否开始开发”。
Multica 唯一底座；内部自托管；中央协作控制＋员工 Windows 本地完整 DSH＋云模型；一公司一个 Workspace，部门/资源细权；项目授权继承到后续普通任务，私密单授。
首轮沿原生项目、Issue 评论与 Squad 承载多人、多 Bot，不新建 IM；Paperclip 只治理参考，OMB 只协作参考/经审独立子件。公司 Key 不下发；公用 Bot 设备及管理人双授权；无合格在线设备可等待，不中央代跑。
正式能力变更先成候选，受控发布；run 固定实际加载版本，不静默热改。自动保存、归档、业务完成和人工验收分开；公司工作资产留存不等于全员可见。

## 2. 已批准的持续动作

| 允许 | 边界 |
|---|---|
| 首轮产品代码、测试、文档与最小原生修复 | 仅下面三个切片，按任务写集、测试契约与门禁推进；不得扩大权限或另造任务系统 |
| 同仓隔离分支/worktree、subagent、依赖安装、构建和本地服务 | 先核依赖/锁文件与进程端口，避免误跑上游发布脚本；不动用户其他工作 |
| 合成测试数据库初始化、迁移和清理 | 每个测试实例独立命名、目录/端口/连接串登记；正向证明为本卡创建后才能清理；禁止默认连接、生产库和其他实验库 |
| 本地提交 | 白名单逐路径暂存，审秘密与来源，使用实际 Git 身份并附真实 agent/task trailers；禁止批量纳入业务资料 |
| 合入专用集成分支 | 本轮 codex/round1-continuous；独立审核和受影响回归通过再整合，不是 main |
| 技术契约子集冻结 | owner、受影响消费者和独立安全 reviewer 按 Discovery 留证签认；满足条件后继续，不再要求 Ethan 审字段名或逐步开工 |

不包含：覆盖他人改动、直接合入 main、公开 push、生产部署、真实公司资料、第三方业务写入、未经确认的真实模型调用或费用、改全局 Git 身份。旧账号“允许一次”不续期。
同一测试库的安全清理在授权内；若不能证明目标归属，禁止删除。主树业务变更只读对照，不强制并入本轮；平台不消费的千川新增不阻塞开发。

## 3. 三个开发切片与退出条件

| 切片 | 交付 | 必须通过才算该切片完成 |
|---|---|---|
| R1-01 多人任务协作与权限 | 原生我的工作/项目/评论/Squad/认领；部门、私密、跨部门权限；受托身份与设备资料交集 | NM-01–12 适用项真实入口正负例通过；列表/详情/搜索/WS/附件/通知无旁路；A 发起、B 管设备不借 B 权限；普通讨论不唤醒；有权正常用例可用 |
| R1-02 本地执行与成果用量 | @ 定向派单、Windows 本地 DSH、各 Bot 回复/进度、追问/停止/离线原因、自动归档、单一用量回传 | Windows Electron 真实操作贯穿自动链路；不手动上传补成功；公司 Key 不落员工环境；重复/迟到回执不重复副作用或计费；未知用量不报零 |
| R1-03 Leader 闭环与可靠性 | 委托内组队派工、并行成员回传和汇总；固定版本/候选；撤权、自动保存和双设备接续 | 文本与资产两次汇合均过；输入/结果按权；已确认保存点完整、旧写隔离、冲突不覆盖、未知效果不重放；DV 双向故障与适用版本/权限门禁通过 |

R1-01/02 可分阶段形成产品成果；R1-03 硬门禁未过，不称公司真实业务可用。保留原生看板/甘特/Inbox，不从零重做；独立 IM、通用工作流、外部知识/表格连接、移动端扩建、Mac 实现、商业 SaaS 和千川生产写入不在本轮。

## 4. 不形成循环前置条件

授权 ≠ 精确契约冻结 ≠ 测试通过 ≠ 发布。
先将当前最薄切片的输入、输出、权限、失败、防重、fixture 和参数评审到 TEST-FROZEN，允许在隔离开发环境写测试和最小产品修复。预期 FAIL 形成缺陷卡并在同一授权内修复、重验，不因原生没有该权限而永远禁止实现。
适用 P0 通过、接口和消费者确认后，将该子集升 BUILD-FROZEN，再开放依赖产品卡。不是等八份完整契约全过，也不能以最小补丁为名先暴露未经验证功能。
Ethan 已批准业务方向；工程实现细节由工程角色审定。只有改变安全边界、首轮范围、业务可见性、费用或破坏现有数据时才提出新问题。外部条件阻塞时继续无依赖工作，不把阻塞报告当 Goal 完成。

## 5. 工程默认与仍需外部输入

- 合成验收采用 MINIMUM-CHAIN §2.3 的 S1-B 小包默认：Markdown/CSV、显式 deliverables、10 文件/10 MiB；这是工程夹具范围，不是平台容量承诺，不扩展 PDF/XLSX。
- NM 清理时限与 DV 保存/恢复参数沿各自唯一正文，执行前把参数版本和 hash 固定到实验 manifest，经独立安全 review 后使用，不事后放宽。尚不是已达成 SLA，也不伪称 Ethan 单独批准了每个数字。
- 待真实模型阶段一次性请求：模型 ID、公司网关/秘密配置位置、费用责任人、调用上限和预算；S1-C 的 10 元/20 次仍只是提案，未获准。
- 双设备阶段登记两台合格 Windows 的实际设备/管理人/资源授权与故障窗口；不能把同机两个进程、VM 或 mock 当双机。
- 真实公司资料、保留/删除政策的上线批准、真实试点/生产发布仍后置；合成库与本地开发无需等这些。

## 6. 验收与交接

技术集成者维护 ACTIVE；每张实现卡有真实 owner 与独立 reviewer。共享 schema/鉴权/状态/锁文件单写，独立消费者冻结后才并行。采用工程基线的模型分级、实际身份和白名单合并规则。
最终证据包含同一集成 SHA、契约子集 hash、真实命令/用例数、正负例、设备/模型/数据边界、原始证据引用、所有 FAIL/SKIP/BLOCKED/NOT RUN 及修复复验。真实模型和双机未测时，只能报告无模型/单机部分完成，不能宣布首轮验收完成。
新会话必须使用 [交接入口](DEVELOPMENT-HANDOFF.md)，不能执行归档里的旧启动提示词。
