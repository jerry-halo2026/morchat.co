# 统一客户端与员工本地完整 Harness

> 2026-11-05，设计评审稿。Ethan 已确认：中央协作控制＋员工本地完整 harness＋云端模型；所有角色使用同一客户端、按账号权限展示内嵌面板，公司统一管理 LLM Key。本轮撤回中央 harness 优先、服务器默认执行员工任务及每设备默认单任务限制；员工助手默认本人设备，部门公用 Agent 在预授权设备池自动选机，入群不授予设备控制权。以下是目标设计与后续验证门禁，不表示已经集成，不限定具体办公软件，不授权实施。

## 1. 已选方向与撤回内容

| 方案 | 结论 | 原因或边界 |
|---|---|---|
| 中央 harness + 远程本地工具 | 撤回首版优先方案 | 员工的模型—工具循环、浏览器、代码和文件处理应在获授权的员工设备运行 |
| 每位员工独立部署完整 Agent 产品 | 不采用 | 不分散公司身份、任务、凭据、资产权威；本地完整 harness 不等于一人一套公司后台 |
| 中央协作控制 + 员工本地完整 harness + 云端模型 | 已确认 | 中央管协作和治理，本地完成运行循环及工具执行，云模型负责推理 |
| 常在线执行电脑/云端执行池 | 不纳入当前建设范围 | 已接受无合格在线设备时停工等待；不为员工关机增加执行兜底，未来只有新增业务需求才重新评审 |

员工、负责人、老板用同一客户端，不是三套应用。客户端可用 Web 技术构建，但首版不是只有浏览器入口；辅助 Web 入口无本地 runtime 时不能操作本机。Ethan 已确认不要求全部员工关机后继续执行：没有合格在线员工设备时任务等待，不增设常在线节点或云端执行兜底。任务和公司已确认资产不随关机消失；重新上线后验权、对账，再按已批准的继续/接续规则运行。已有其他合格在线设备时的授权池协作规则不变，员工明确暂停/取消任务不能被当作设备故障而换机绕过。

### 1.1 首轮原生平台与引擎候选

Ethan 最新确认首轮聚焦两台 Windows 11 x64 原生设备，Mac 预备但不阻塞首轮，取代上一版要求 Win/Mac 同轮通过的安排。仍不要求员工安装 VM/WSL/Docker。预留进程/路径/安全存储/工具隔离与 capture/restore 平台接口，不提前建设 Mac 实现，也不把 Windows 通过当作跨平台通过。

按公司多供应商 OpenAI Chat Completions／Anthropic Messages 协议需求，Ethan 已确认先按 DeepSeek Harness（官方 dsh）优先方向核查，Codex App Server 保留对照/备选；撤回 Codex 默认优先，不是最终锁版或多引擎建设授权。Paperclip Runner Windows 有发布、进程生命周期、工具桥和快照 transport 缺口；OpenMausBot 有原生安装/driver实现但不能整体套用 Client 模式。具体证据、路线 A/B/C 与 NG 门禁见 [原生运行与 Harness 核查](D:/dev/morchat.co/docs/NATIVE-RUNTIME-RESEARCH.md)。

## 2. Harness、Runtime 与模型的区别

| 概念 | 本项目定义 | 不是什么 |
|---|---|---|
| 云端 LLM | 接收获准上下文、推理并返回文本或工具请求 | 不直接登录员工电脑，不是本地 Python/Node |
| Bot（AI 同事，工程名 Agent） | 中央登记的稳定 AI 身份、职责、能力引用、授权和任务关系；正式实例映射唯一 Paperclip Agent | 不等于模板、真人账号、模型、harness、电脑或常驻进程 |
| Bot 模板 / 小队模板 | 单个 AI 同事的配方 / 真人与 Bot 的分工配方，复用已有包载体 | 不是实际授权成员，不携带旧会话或自动开启执行 |
| task / run / attempt | 工作身份 / Bot 的一次执行 / 设备派发或恢复尝试，按既定关联协议管理 | 重试/换机不是新 Bot；临时子 Agent 不自动加入公司名册 |
| 完整 harness | 在员工本地组装上下文、调用云模型、处理工具请求、反馈结果、管理会话/等待/取消并输出事件与用量 | 不是仅供服务器遥控的工具插件，不是安全沙箱，也不替代公司权限 |
| 客户端 runtime | 本地运行管理器＋选定 harness 引擎＋受控工具宿主＋恢复/回传队列 | 不含公司权威任务库、供应商原始 Key 或本地大模型 |
| 工具宿主 | 本地 runtime 内执行浏览器、Python、Node、文件能力的受控组件 | 不独立决定任务目标，不因模型发出请求就获得授权 |
| Paperclip 控制面 | 公司任务/run、Bot 配置历史、当前指令、skill 版本和预算审批；通过 adapter连接执行环境 | 不是模型—工具循环的 harness，也不只是转发 API；人类部门/群策略仍由 morchat补齐 |
| Paperclip adapter / 派发桥 | 把中央任务/run 与指定设备的领取、启动、事件、取消及回执对应起来 | 不默认已有完整员工设备集群管理能力 |
| 工作空间 | 一次运行获准的目录、输入、依赖、浏览器会话与资源限制 | 目录、venv、worktree 本身不构成安全隔离 |

Paperclip 的 local adapter 中“本地”指启动进程的主机。在中央服务器启用 codex_local/claude_local，不会自动把进程放到员工电脑。必须验证远程派发接入，不能用名称冒充员工本地运行。[适配器说明](https://docs.paperclip.ing/reference/adapters/overview/)

## 3. 三端分工与一次完整执行

| 位置 | 负责 | 本期不负责 |
|---|---|---|
| 中央协作后台 | 公司/部门/账号与权限、群协作、Paperclip 任务/run、设备派发与租约、费用准入、资产存储/检索/备份、审计 | 员工任务的常驻 harness、浏览器/代码执行池 |
| 员工客户端 runtime | 本地完整模型—工具循环、受控浏览器/Python/Node/文件、暂停/恢复检查、产物和事件回传 | 第二套任务真相、任意使用个人凭据、绕开中央授权 |
| 公司模型访问层 | 鉴权、模型路由、供应商凭据注入、公司限流/预算准入、流式转发、用量回执 | 模型推理本身、员工任务 harness、业务自主调度 |
| 云模型供应商 | 模型推理和供应商用量回执 | 公司组织权限、员工电脑执行、公司资产权威 |

中央是协作与数据治理后台，不是员工执行机。它接收并校验任务状态、授权业务数据/文件、操作事件与结果回执、版本/来源、权限及用量记录；权限校验、任务协调、模型网关和持久化职责仍在中央，“不执行 Agent”不等于取消这些控制。中央仍可运行数据库维护、连接器令牌刷新/已授权接口读取、资产检查/索引和备份等核心服务工作。这不等于恢复“服务器跑员工完整 Agent”；AI 摘要、skill 提炼等模型—工具任务也按获准本地 runtime 派发，不另藏中央 harness。模型网关可独立扩容，不把高流量转发绑死在单个协作 API 进程。

执行链路：

1. 员工/负责人下目标、建群或交给 AI；中央按真实身份授权写入 Paperclip。
2. 先确定逻辑 Agent 承接者，再选执行位置：员工助手默认其本人指定授权设备；部门公用 Agent 在预授权池自动筛选设备、runtime/工具版本、数据可承载范围、本地资源绑定及可用容量。发消息人、群主、Agent 维护人和执行设备管理人分别记录；入群不授予电脑使用权。
3. 建立可追踪的派发尝试；设备领取、中央确认有效租约后才能启动。任务已创建、已派发、设备已接收、运行中、等待人、待归档是不同概念，具体与 Paperclip 原生状态/API 的映射在 P0 验证，不虚构原生枚举。
4. 本地管理器以独立公司配置启动完整 harness；通过公司网关调用云模型，工具请求在本机受限工作空间执行。模型要求的操作必须再经授权检查。
5. 工具输出按权限、外发策略、脱敏和体积限制处理，才能进入下一轮模型上下文。
6. 事件、用量和产物持续回传；中央去重、校验权限与租约后更新 Paperclip/资产。公司资产提交确认后是已归档；满足完整保存点及当前授权才可接手，另经业务验收才形成正式交付。

### 3.1 首版所有模型调用均属于真实任务

MVP 只开放任务绑定的模型调用。员工明确向 AI 提问/要求规划时可创建一条可见的轻量真实任务，后续追问关联该任务与新 run；普通群消息不自动建任务或调用模型。摘要、skill 提炼/评估等若启用，也必须有真实目标、发起/委托身份、输入范围、责任人和费用归属，经 Paperclip 任务/run 派到本地；不能只为凑计量伪造 Agent/run。

任务外的自动标题、无归属后台聊天等模型功能首版关闭（可由用户填写或规则处理）；不另建服务模型调用旁路。以后若需要非任务 AI 服务，单独设计服务主体、授权/取消、派发与费用契约。这样首版每次模型调用均可绑定真实 task/run、设备派发和有效租约。

组织助手的规划/组队、岗位就绪样例、复盘和 skill 测试也适用以上真实 task/run 规则，在获准员工设备执行；中央只接受结构化操作/证据。无合格节点显示该 AI 工作等待，人工组队/认领/验收仍可用；不把组织助手做成服务器常驻 harness 或全公司单线程入口。详见 [产品流程](D:/dev/morchat.co/docs/PRODUCT-LIFECYCLE.md)。

### 3.2 不要求员工自行安装和维护个人 CLI

必须交付一个公司可管理的完整运行环境，而非“检测到员工装了 Claude/Codex 就直接借用”：

- P0 选一个 harness 引擎先打通。可采用 SDK 携带运行二进制，或客户端受控安装固定版本；是否物理打包在同一安装包不是架构本质，但员工不应手工装 CLI、开终端或登录个人订阅才能工作。
- 管理器检查平台、引擎/工具版本、完整性、依赖、隔离能力和公司模型连接；既有安装只能作为可验证的可选来源，不默认复用 PATH、个人 HOME、OAuth 或配置。
- 公司工作配置按公司/身份/Agent/工作空间隔离。使用独立配置目录和最小环境，不覆盖员工原有 Codex/Claude 设置；缺公司配置时失败关闭，禁止回退个人 Key/订阅。
- 引擎和 Python/Node 分开管理，固定已测版本、依赖锁与来源；记录兼容矩阵、许可、签名/哈希、升级/回滚。升级在运行安全边界执行，不自动追 latest，不在任务中途强换引擎。
- UI 不直接获得任意进程/文件权限。设备令牌、模型网关凭证、Paperclip 服务凭据相互分离，员工进程不持有中央管理员凭据。

SDK 是否携带 CLI 要逐个核验，不能把“用了 SDK”理解为“没有 harness 进程”。Codex App Server 是面向自定义客户端的本地进程接口；Claude Agent SDK 官方说明 SDK 携带 Claude Code 运行二进制，但仍有平台/依赖条件。以上只证明接入路线可研究，不证明本项目已经兼容。[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Claude SDK quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart)

### 3.3 群成员与执行设备分开

公用 Agent 的池内自动选机是已获授权策略，不要求每次人工批准，但每次必须重验资格并原子领取；员工助手不自动借用池或同群电脑。一个 Agent 可在不同任务上启动隔离运行，一台设备也可同时运行不同 Agent；同一派单不能由多台设备重复执行。

共享上下文只含获授权群消息、任务/目标版本和资产引用，不合并私人文件、Cookie、其他群和全部模型会话。长任务不堵住消息/派单接收/取消/状态通信，Agent 回复不自动广播唤醒所有其他 Agent。所有拟落地任务资料都须满足设备及管理人的对应授权，不能只给敏感标签任务做检查；客户端 UI 隐藏不能消除宿主查看风险。

入池授权、自动选择、上下文包及重复/循环抑制的完整契约见 [群内 Agent 与设备池](D:/dev/morchat.co/docs/DISTRIBUTED-COLLABORATION.md)。

### 3.3.1 员工管理员身份不传递给 Agent

Ethan 已确认员工各自保留电脑管理员权限；平台控制 Agent 的执行能力，不接管整机。Agent/harness/工具仍按受限身份与显式目录、会话、网络和工具授权运行，不继承员工全部权限，不因 UAC/安装授权永久提权。员工可暂停或退出本机执行；公司不以整机管理、全盘扫描或远程擦盘作为首版前提。

公用 Bot 每次派发及资料首次进入/恢复前，检查设备承载授权和管理人的对应资料授权，二者都成立还须满足 Bot/任务权限。管理员可接触本机数据这一事实通过选机资格处理，不伪称客户端能对抗主动篡改的本机管理员；中央授权、Key 保管、代次和成本仍独立执行。具体规则以 [设备池 §3.1](D:/dev/morchat.co/docs/DISTRIBUTED-COLLABORATION.md) 为准。

### 3.4 多模型不等于多套员工客户端

统一客户端内的同一 harness 通过公司网关接获准模型。DeepSeek、MiniMax、Qwen、GLM、Kimi 是目标供应商范围，具体型号/端点/协议与能力逐项登记和验证；不能以“OpenAI-compatible”标签保证都能完成 Agent 任务。优先 Chat Completions 与 Anthropic Messages，Responses 可选；模型 API 是云端推理接口，SDK/ACP/App Server 是客户端与本地 harness 的控制接口，两者不混用。

公司持有供应商原始 Key，本地受管理宿主使用短期、绑定任务/run/设备与模型范围的网关凭证。明确凭据引用、独立公司 HOME/profile、禁止个人回退及未授权直连；公司员工看到可用模型，不看到供应商 Key。公司网关只做受控转发/准入/计量，不运行员工 agent loop；所有启用辅助推理也纳管。网关真实用量回到 Paperclip 唯一成本账，不因同时有 harness 回执重复收费。

DSH 插件允许平台研发扩展工具、模型与生命周期钩子；不允许员工或 Agent 自行安装高权限插件、改公司策略或绕开保存。批准版本/来源/能力及回退可审计；skill 的知识沉淀和执行插件发布分别治理。插件钩子不代替操作系统隔离或中央幂等/旧代次隔离。

准入与对比细则见 [原生运行核查 §4.1](D:/dev/morchat.co/docs/NATIVE-RUNTIME-RESEARCH.md#41-多供应商接入契约能连通不等于-agent-可用)。首轮仍只选一个 harness；支持多个获准模型不要求同时建设 Codex/DSH 双引擎产品。

### 3.5 Windows 原生载体与最小补齐

当前优先验证：Paperclip 外部远程 adapter → 公司本地 supervisor → MXC ProcessContainer → 独立 DSH ACP 进程；官方 ACP SDK接双向标准流，不重写协议。每 run 独立 HOME/工作区/身份，允许同机多个run并行；Mac 仅预备。整 DSH 必须在外层边界内，不能只隔离 shell而漏内建文件读取。浏览器另域、独立 profile与授权。

最小 run级权限方案会让 Python/Node 同样可达该run批准的模型专用route；它是无任意外网，不是工具零网络。若公司要求工具不可达模型通道，需独立工具域和broker，不能用清空环境变量冒充。这个策略粒度与 Windows build/有效tier均须在 P0冻结，不能静默扩大。取消需ACP close＋OS整树/外部工具证明，ACP context usage不用于记账；Paperclip快照还需节点传输扩展。详情、来源与 WI-01–10见 [Windows DSH 接入](D:/dev/morchat.co/docs/WINDOWS-DSH-INTEGRATION.md)。

## 4. 本地浏览器、Python、Node 与文件

### 浏览器与真实业务动作

首版至少验证一个管理器维护的独立工作浏览器会话，限定站点及文件范围。个人默认浏览器、密码库、全部标签页和已有 Cookie 不自动开放；使用现有会话需要另行授权。网页/下载内容是不可信输入，不能更改权限或诱导访问其他目录。浏览器驱动不等于任意桌面软件控制；后者暂缓。

MVP 对真实第三方业务只开放已验证读取、导航和下载；不默认开放表单提交、发送、发布、付款、修改业务记录及向第三方上传。这不是长期自主权等级，未来写入另做连接器授权、防重和对账。授权本地目录写入、公司资产库上传独立允许；隔离测试环境可用合成资料验证写动作。域名白名单、HTTP 方法和只读 prompt 都不能证明没有业务副作用，未验证语义及阻断能力就不开通，不能用通用浏览器绕过连接器。

### Python、Node 与工作目录

- 管理受控版本、依赖锁、工作目录与最小环境；不自动全局 pip/npm 安装，不默认管理员权限，不继承完整宿主环境或个人 CLI 登录态。
- venv、依赖目录和 worktree 只减少冲突。任意代码仍可访问文件/网络/子进程，首轮须验证原生操作系统/受限工具的实际限制，不以容器作为员工使用前提；做不到则关闭该能力或改受审查的受限工具，明确范围缺口，不转成无限制 shell，也不静默回退中央 harness。
- 限制 CPU/内存、磁盘、进程数、超时、输出、网络和读写范围；授权须覆盖代码实际可触达资源，不仅命令名称。
- 员工选择具体工作目录/文件，记录用途、期限和读写权；禁止默认同步整个用户目录、私人盘、浏览器资料或凭据目录。校验路径穿越、符号链接、Windows junction 及运行期间权限变化。
- 普通文档/表格优先直接生成文件，不为模仿人工而使用 GUI。生成成功不等于公司交付成功。

## 5. 账号、设备、工具三层授权

账号开通配置公司成员、部门/岗位、角色、资源范围、AI/工具权及费用归属模板；设备另注册。账号策略、任务资源、设备委托、运行授权和隔离上限取交集。

| 授权层 | 管理内容 | 不能自动获得 |
|---|---|---|
| 组织/业务数据 | 同部门普通任务默认可读；敏感/私密另授权；跨部门获授权项目/任务及对应流转 | 同事电脑、个人文件、整个其他部门或相邻依赖 |
| 操作能力 | 创建、认领、分派、审批、发布、管理分别授权 | 可读不等于可写；负责人/管理员不是全部内容和设备的所有者 |
| AI 委托 | Agent、工具、资源、用途、期限 | 多人权限自动合并、上游身份完整继承 |
| 设备/会话 | 设备身份、管理责任人及资料授权、承载/执行范围、允许用户/Agent | 员工保留管理员权限；Agent 不继承，登录或入池均不等于接管整机 |
| 工作空间 | 浏览器会话、目录、运行时、网络、资源上限 | 同群自动共享文件或登录态；skill 发布不赋予操作系统权限 |
| 模型/费用 | 模型允许列表、预算范围、费用承担方 | 模型使用者可查看 Key 或修改预算 |

所有人只能授权自己有权委托的资源。跨部门任务授予不自动上溯项目、横向开放依赖，也不自动给其部门负责人。创建私密群不使关联普通任务自动私密；反过来关联普通任务也不能解密私密群/敏感附件。数据读取与操作权限分开检查。

每次运行/工具操作关联公司、发起/委托身份、Agent、任务/run、设备/工作空间、权限版本、租约及防重标识；中央决定关联，不能相信模型或客户端自报身份。交接只传获准任务/资产引用，接手者重新授权。

## 6. 派发、离线与恢复

设备主动建立认证加密的出站连接；不把 shell、App Server、浏览器调试端口暴露公网。设备密钥使用系统安全存储，注册/轮换/吊销可审计。在线心跳是设备可用性探测，不等于触发一次收费的 Agent 运行。

- Paperclip 是任务/run 权威；morchat 只扩展设备派发尝试、租约、事件游标与恢复关联，本地只保存最小检查点和待回传队列，不另建可独立修改的任务状态机。
- 派发具备 attempt ID、租约期限和递增代次（fencing）。设备领取、启动前和每个新动作校验；同一任务的重复唤醒不重复开跑。离线等待不能伪装成已启动/正在耗费运行额度，实际 adapter 的等待/超时模型须 P0 验证。
- 本地忙、离线、休眠、需交互的会话锁定或能力不兼容分别展示原因。员工助手默认设备不可用则等待本人设备，不借同群电脑；公用 Agent 的未启动任务自动选其他合格池设备，不能以“不得偷偷换设备”禁止已经授权的池内自动选择。无合格设备或本地资源绑定不可满足则等待，不转中央执行。
- 断联停止发起新的模型/工具动作，在途操作尽力取消/到安全点保存；中央拒绝新请求、可信 runtime 停止新动作、在途操作实际终止是三条不同边界。短租约约束可信端准入，不保证已启动下载/子进程按时停止，也不强停受攻陷宿主。半开连接、休眠恢复和时钟异常须重验，检测/失效/实际停止时限分别实测。
- 重连先验证当前账号/设备/租约，再对账事件、费用和产物。回执按运行/操作 ID 与序号去重；已完成动作不盲目重放，结果未知先调查，取消不等于外部副作用回滚。
- 租约过期不证明旧进程及副作用从未发生。旧代次不得提交为当前任务完成或继续用模型；迟到证据隔离待核对，但真实已发生的成本仍须幂等记账，不能因运行失效丢弃账单。未知在途动作未收敛前不自动再派执行。
- 公用 Agent 的未获启动权限 offer 可原子撤销并拒绝迟到领取，再选另一合格设备。已领取/运行的尝试失联不能直接迁移；只有满足 R1（共享写入已隔离且可安全重算）或 R2（旧执行/资源可信终止）的接续条件，检查点及其后已提交效果已对账且无未知项，才按池策略自动创建新 attempt/run 接续；启动许可已提交但 ACK 丢失视为可能执行，不得当未开始。未知动作或仅本机资料缺失就阻塞核对。
- 不承诺任何 CLI 会话可跨设备迁移。默认以中央检查点/输入资产新建接续 run；只有所选引擎同版本恢复已验证才可复用会话。每次选机重新校验现有授权，超出池或员工助手改变设备需明确授权，绝不复制个人登录态。

### 6.1 终止后的证据接收不恢复执行权

- 租约过期/任务取消但账号与设备仍有效：重新鉴权后可获取仅限原 run 的证据/产物上传授权，材料进入隔离待核对区；不能用它调用模型、执行工具或修改任务完成状态。
- 账号或设备已撤销：旧凭证连上传也拒绝。必要时由具备该任务/材料权限的接管人经另行授权的恢复导入提交获准文件，保留原设备/run 与导入人来源；不复活旧账号/设备，不默认接管私人目录。失联无法取回则标记缺口。
- 异常或未知结果由拥有任务管理权且可读相应证据的责任人核对产物、记录不可恢复项并批准接续；仅有系统运维身份不足。已满足可验证安全条件的公用 Agent 按预授权池策略自动接续，无须再逐次批准。未知动作须有结果证据才能解除阻塞，不能因超时自行认定安全重跑；接续均经过新的运行授权。
- 模型费用从中央网关/供应商回执对账，独立于设备存活和证据上传权限。选定方案必须可在设备撤销/损坏后恢复真实调用账目；只靠本地 adapter 唯一汇总且无法重建的路径不通过 P0，费用未知仍标未知。

首版无完整离线 AI。员工设备离线不影响其他在线设备和中央协作服务：员工助手或本地资源绑定步骤等待，公用 Agent 按上述未启动/安全接续/未知结果分类处理。故障状态、需要谁处理、哪些成果已归档必须在群卡和面板可见。

### 6.2 提交、恢复与持续授权的硬边界

派单防重按逻辑派单/独立子任务而不是仅 attempt；多调度器、同机多个 runtime 或重启不能产生重复有效启动。旧代次/旧版本必须在任务状态、子任务、正式资产及群投递的提交生效处被拒，不能只在发请求前验权。优先验证权威端条件写入；否则只有全入口受控、同资源提交顺序与超时待确认可证明的协议才可采用，不将短提交区间串行误作整个执行串行。两者都不能证明就不通过 P0。

恢复检查点带已覆盖操作序号，中央对账其后已提交的子任务、资产及共享文件效果；形成跳过已完成/续做未完成的恢复清单再接续。旧租约过期或本机自报不等于受管理进程树/外部效果已终止。按 [任务与工作空间接续](D:/dev/morchat.co/docs/WORKSPACE-CONTINUITY.md) §6 分类：R1 必须证明所有共享写入隔离与重算安全；R2 必须证明终止并对账。无法证明适用条件则阻塞，不盲重跑。

设备数据资格贯穿上下文增量、工具发现/下载和会话恢复：资料首次送到宿主或授予获取能力前核验，无法限制未知来源就不开放该读取能力。升敏/撤权暂停相关动作；同任务新 run/追问身份改变也重新核验原始 session，无法证明旧内容仍获准就按当前授权重建，不借 resume 绕过中央裁剪。详见 [分布式协作 §6.1–6.4](D:/dev/morchat.co/docs/DISTRIBUTED-COLLABORATION.md)。

## 7. 公司统一 LLM Key 与计量

确认公司统一采购/管理云模型，不依赖员工个人 Key 或订阅。统一管理不等于全公司一把永久 Key，可按供应商、环境、用途拆分。

1. 供应商原始 Key 只在中央受控模型访问服务/秘密存储；不下发客户端、工具子进程、prompt、skill 或普通日志。秘密权威在 P0 选择 Paperclip secret store 或公司秘密服务，其他侧仅持引用。
2. 本地 harness 使用短期、限公司/身份/run/模型/额度的网关凭证。网关核验当前授权和有效租约，把真实 Key 注入供应商请求；用户头字段不能自定归属。设备身份令牌不是公司模型万能 Key。
3. 引擎使用独立配置明确指向受支持的公司网关和认证模式，清除个人 OAuth/环境继承。只改 base URL 不等于统一了认证/计费；故障时失败关闭，不走个人账户或直连兜底。
4. 验证实际引擎的协议、流式响应、工具调用、取消、重试、用量，以及所有启用的标题/摘要/skill 等模型入口。先选一个引擎＋一种兼容供应商路径，不承诺不同模型协议随意混用。
5. 公司模型访问层复用 Paperclip 的已验证预算事实并补调用准入；原始网关回执是证据，不是第二本费用总账。一次消耗固定请求级或运行级记账粒度，防止 adapter 汇总与网关明细重复入账。
6. 责任用户、承担部门/项目、设备、run 在开始时保存快照；调岗不重写历史。首版部门/个人做归集，硬预算先复用公司/Agent/项目的已验证范围。
7. 重试实际消耗、失败前消耗、流式取消和迟到回执均须记账；未知价格/用量不是零。在途请求和迟报会带来预算超额窗口，不承诺绝对零超支。
8. 本地运行不意味着数据不出电脑：文件片段、页面、截图和输出进入云模型前须满足公司外发政策；无权外发就拒绝，不因为工作资料就放行。

Paperclip secret 引用/轮换不自动保证员工设备看不到 secret。Claude 官方网关方案区分网关凭证与服务端供应商 Key；Codex 自定义 provider 也需独立配置/认证。兼容性、计量分类与防绕路仍是本项目门禁。[Paperclip 密钥](https://docs.paperclip.ing/how-to/rotate-provider-api-key/)、[Claude LLM gateway](https://code.claude.com/docs/en/llm-gateway)、[Codex 高级配置](https://learn.chatgpt.com/docs/config-file/config-advanced)、[Paperclip 用量边界](D:/dev/morchat.co/docs/PAPERCLIP-BASE.md)。

## 8. 并发：默认允许并行，按资源限制

撤回“每台设备默认一个活跃执行链”。跨设备默认并行，同设备的无冲突工作也必须支持并行；限制落在真实资源和容量，而不是整个员工、群或公司。分散负载不等于无限并发，队列用于可靠派发/超额等待而不是全局串行。

| 范围 | 运行规则 |
|---|---|
| 同一设备 | 按任务/run 隔离 session、工作区、输出，多个客户端实例与子 Agent 纳入真实总配额；CPU/内存/进程/IO/网络限额由实测设定，不预设单任务 |
| 共享 Agent | 不同任务可多会话并行；同一派单防重/唯一有效领取不等于禁止多个独立任务 |
| 冲突资源 | 需独占的浏览器会话、交互桌面、同文件写入局部互斥，无关任务继续；不使用设备全局锁代替资源锁 |
| 等待依赖 | 仅依赖步骤等待；持久化检查点、在途操作到安全点后释放可释放的执行/写锁，防止父子持锁死等 |
| 公司模型 | 网关 RPM/TPM/并发/预算准入与有限排队/退避/取消，避免设备池超出公司额度，不等同全公司一次一个调用 |
| 消息/控制/上传 | 控制消息不被长任务占住；中央有界队列、分批、背压与独立扩容，进度可合并但审计/费用/交接/资产确认不可静默丢失 |

等待后续跑重新授权/取锁并检查文件版本和会话状态；不能安全释放的资源标阻塞，子任务使用独立工作区/不可变输入。多资源请求须防环形等待，设备暂停与单任务取消区分，不误杀无关并行运行。本机办公负载和员工暂停权进入验收。

P0 即验证同机至少两项无冲突任务实际同时执行、跨设备并行、同一公用 Agent 的会话隔离、局部锁和离线分类；P3 再按已定目标压测。两任务是最小正确性证据，不是容量上限。详见 [DC-01–08 架构门槛](D:/dev/morchat.co/docs/DISTRIBUTED-COLLABORATION.md)。

## 9. 公司资产与离线交接

生成/选取文件 → 内容/类型/大小/来源校验 → hash 校验上传 → 公司存储提交 → 资产版本/ACL → 关联任务/run → 投递给获授权对象。

产物关联 company、task/run、设备/工作空间、执行身份、harness/工具/skill 版本。未收到公司存储确认就显示待上传/待归档，不能把本机路径或模型口述算交付。分块/防重/重试与同名冲突可见，提交成功前不删除唯一待上传副本。

本地使用加密、有容量上限的恢复/回传缓存，由 runtime 自动在工作单元/等待边界触发并以周期检查兜底同步检查点和产物，自动有界重试，不依赖员工手动提交或模型自觉；满额或上传失败暂停新增产物并提示，不无限囤积或偷偷丢失。中央不可用时只保留允许的最小恢复信息，不继续离线自主运行。断联导致设备损坏前未上传的数据可能无法恢复，不能承诺零丢失或所有知识必然留住。

调岗/离职交接包包含：任务状态与已知/未知动作、可复用工作摘要、获准输入/产物的资产 ID 与版本、skill/harness/工具版本、环境依赖清单、未完步骤及责任人。新设备基于中央资产重新授权并开接续 run；不复制全目录、个人记忆、Cookie、原始 Key 或个人登录。离职先撤销账号/设备/网关权限、停止旧租约，再处理安全接续；已经归档的公司资产可交接，失联设备未上传内容要明确列为缺口。不能保证远程抹掉失联个人电脑上曾合法取得的文件。

留存不等于全员可见，源敏感权限不会因交接/skill 化变成普通部门可见。完整规则见 [资产与持续升级](D:/dev/morchat.co/docs/ASSETS-AND-LEARNING.md)。

自动保存的时限/容量界限、无手动提交基线、断电/分区/重连/冲突实验见 [自动保存与最小双设备证伪方案](D:/dev/morchat.co/docs/DUAL-DEVICE-VALIDATION.md)。长工具需提供安全阶段边界，无法形成一致点不能假报成功。

### 9.1 受管理工作区与换机重建

按 [任务与工作空间接续](D:/dev/morchat.co/docs/WORKSPACE-CONTINUITY.md) 为每次任务尝试建立独立目录/worktree；Git 项目和普通文件夹都须保存可恢复中间态。人类编辑走接管/导入版本流程，不与 AI 抢写同一活动目录。客户端分开显示业务进度、执行位置、已确认保存点与交付验收；传输成功不冒充已确认接手。

R1/R2 分类是本轮修订建议：只有全部共享效果可隔离且可安全重算的受控任务，才可不等待旧机物理停止从新目录接续；不能对未验证任意 CLI/GUI/网络权限直接贴 R1 标签。员工助手不自动换同事电脑，任务转派与助手设备授权分别处理。

### 9.2 岗位包与技能版本的本地交付

Bot 模板/岗位包引用原生配置 revision、指令内容快照、skill 版本和授权材料；小队模板再引用这些能力与真人槽位。模板只声明需求，不自带 device grant、秘密、个人记忆或任意 preset 插件。实例是同一个稳定 Bot/Agent；临时项目背景只进入 per-run 授权输入，不改共享 Bot 全局配置。

Paperclip 当前 managed 指令文件的新保存不追加完整历史，旧 history/restore 不足以保证可回退。系统优先复用原生 durable blob/manifest 并补历史保留根，或既有保留资产，自动保存允许交付的指令/资源内容，生成能力组合引用；未归档/基线冲突不得生效。每次 run 取确定内容到隔离工作副本并核对实际 hash，不直接跟随可变公共目录。候选自改/自动回写不等于正式升级，原生入口同样受控。配置回滚不能冒充指令与 skill 全组回退，回退不复活权限。详见 [版本记录边界](D:/dev/morchat.co/docs/PRODUCT-LIFECYCLE.md)。

Paperclip 已准入 run 记录 skillVersions，普通新 run 的历史 pin 要验证 Beta 开关/兼容路径；配置/skills sync 不代表 DSH 实际加载。首版复用 DSH filesystem provider，includeDefaultRoots:false，按本次获准版本建立只读投影；正文及引用资源 hash 与实际工具/slash 加载都留证，禁私人/项目同名覆盖。缺失、unsupported、权限收紧或 hash 不符阻塞，不静默 latest；不重新实现 skill registry/agent loop。完整证据与负测见 [产品流程 §3.5](D:/dev/morchat.co/docs/PRODUCT-LIFECYCLE.md)。

## 10. MVP 门槛与暂缓

- 一个企业平台、两台 Windows 11 x64 原生设备、一个选定 harness 路径；Mac 仅预留适配边界；在未安装个人 Agent CLI、没有个人订阅/Key 的干净试点设备上，从客户端受控准备环境并运行成功。
- 本地完整模型—工具循环实际运行；浏览器、Python、Node、文件回传逐项验证，服务器不代跑员工 harness。用合成或获准资料，不先绑定具体办公软件。
- 验证员工助手路由、公用 Agent 池内自动选择、同机/跨设备并行、共享 Agent 会话隔离、资源冲突、授权上下文、公司网关/用量、离线改选/安全接续/未知阻塞、旧回执与撤销；不得只测正常路径或改为全局串行充数。
- 保留原有企业组织、人机/AI 协作、部门/跨部门面板、资产/skill 复用和双场景验收，不把 MVP 缩成 CLI 启动器。

暂缓多引擎同时支持、Mac 原生实现/跨系统验收及其他平台与未验版本、本地大模型、完整离线 AI、任意桌面软件控制、托管执行集群、通用工作流。具体引擎/SDK或CLI、壳、隔离、供应商、限额与恢复时限在 P0 选择验证，不在本轮安装实现。

## 11. 参考项目的复用边界

- Paperclip 提供中央任务/运行/预算基础，五分钟入门不是员工设备派发方案；Runner/workspaces 的实验性能力需对齐固定版本，不能视为生产保证。[入门](https://docs.paperclip.ing/guides/getting-started/five-minute-path/)、[Runner](https://docs.paperclip.ing/reference/adapters/paperclip-runner/)、[Workspaces](https://docs.paperclip.ing/guides/projects-workflow/workspaces/)
- OpenMausBot 可参考桌面壳、引擎管理、独立公司配置和本机工具，但其既有 Client 模式会关闭本地 harness/电脑操作进程，不能原样充当本方案客户端。需适配“连接中央且保留本地完整 runtime”，不引入其第二套任务/身份/资产后台。[Desktop companion](https://github.com/milind-soni/OpenMausBot/blob/597e70d7930db632747acfb4ea047ca520bd958c/docs/desktop-companion.md)
- Multica 的任务—产物—skill 闭环作为参考，不承担第三个运行平台。复用前核验许可与版本，不等于 fork 整个产品。
