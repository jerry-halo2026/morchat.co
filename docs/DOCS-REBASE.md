## 2. 决策级取舍

|---|---|---|
| 产品是千川统一统计与预算治理中台 | 推翻 | 产品是公司人机协作平台；千川为首个连接器和验证场景 |
| 统计是唯一首交付、员工只读本户 | 推翻 | 首交付是工作群→任务→人/AI→成果的纵向切片；员工可发起协作和维护资产 |

| Paperclip 提供组织与看板全部原生件 | 推翻 | 原生 Agent 树不能代替人类部门；业务面板由 morchat 组合展示 |
| D1 上游 Paperclip、固定版本、尽量不改内核 | 保留并收窄 | 接入核心，优先 API；非“绝不改”教条，必要补丁须评审 |
| D2 所有 PATCH 只许一个 command-bus、插件绕过是固定前提 | 重评 | 保留受控写入与服务端执法；按真实身份验证每条通路，不把历史漏洞当永久契约 |
| D3 广告 ledger 自建 | 延期 | AI 成本与广告资金分开仍有效；资金账本随未来广告生产写入立项 |

| D7 企微冻结期让 Paperclip 代替员工主入口 | 推翻 | 首期统一 morchat 客户端即员工端，面板内嵌；企微等渠道后续可选 |
| D8 不依赖 BC、公司控制 OAuth | 保留目标 | 当前历史配置迁移不是本轮动作；未来按连接器计划执行 |
| D9/D10 45 户全量与统计仓为平台核心 | 收窄 | 资料与业务规模保留；核心无账户数常量，先验证再扩展；不作为平台唯一上线门槛 |
| D11 Nodo + Restate 固定入架构 | 暂缓 | 本期用任务/交接/持久待办；不引入通用工作流基础设施 |
| D12 hash-chain + OpenTimestamps + Object Lock 必须齐备 | 延期强化 | 基础审计、权限、备份和恢复先做；更强不可篡改要求另立依据 |
| 学习/SOP 到 Phase 3、学习平台砍半 | 推翻 | 资产来源权限从 P1 起，知识/skill 复用闭环 P2 必须可验收 |
| 大额 50%、双签间隔 30 分钟、固定自主权等级 | 撤回默认强制 | 尚未按当前定位确认；未来具体写业务再定 |
| 直播录制、ASR、实时控场与员工监测 | 延期 | 不属于本轮 MVP，需要独立需求和隐私/成本评估 |
| 调度不干活、所有 leader 必须 AI | 不作为平台规则 | 协调与执行职责可区分，但人类负责人不被 Agent 组织模型替代 |
| 重整稿先纯 Web、桌面壳排除首版 | 修正 | 统一桌面客户端 + 中央协作控制 + 员工本地完整 harness + 云端模型；浏览器入口只是可选辅助 |
| 中央 harness 优先、通用分析/文件默认在服务器运行 | 撤回 | 完整 harness 与受控工具在员工设备；中央只做协作控制/核心服务/模型网关，无员工离线时的服务器默认代跑 |
| 检测员工安装的个人 CLI 即可统一公司运行 | 推翻其推论 | 客户端管理固定版本引擎/独立公司配置；不依赖个人登录/Key，不回退个人计费 |
| 本地运行就不存在并发或系统拖累 | 澄清 | 必须支持同机/跨设备并行，同时用局部资源锁、实测容量与公司模型限额/背压控制负载 |
| 每设备默认一个任务/活跃执行链 | 撤回 | 无冲突任务同机也可并行；同一派单防重不等于全设备串行，最小并发用例 P0 验证 |
| 群主/请求人电脑承载全群 AI，入群即有电脑使用权 | 不采用 | 员工助手默认本人授权设备；公用 Agent 按预授权池自动选机，设备/数据权限分别核验 |
| 换设备一律手动，或失联就一律自动重跑 | 均不采用 | 公用 Agent 未启动自动改选、安全点可自动接续，未知结果阻塞；员工助手默认离线等本人设备 |
| 使用本机工具等于本机大模型 | 澄清 | 模型推理在云端，harness 驱动循环，本机浏览器/Python/Node 是工具；公司统一管理 LLM Key |
| 账号角色足以决定电脑操作权限 | 推翻 | 组织/资源权限、设备委托、工具范围和执行环境限制独立检查 |
| 本机生成文件就算公司交付 | 推翻 | 校验上传、版本/权限登记和公司存储确认后是已归档；完整保存点确认及当前授权才可接手，另经业务验收才是正式交付 |
| Paperclip 用量需全部重建或能自动统计一切 | 均不采用 | 复用原生成本/预算，补归属和授权汇总；打通调用回执并验证预算生效 |
| 用 Git/worktree 或会话 resume 就等于异机接手 | 推翻其推论 | 必须保存精确工作字节、任务版本与效果回执；工作区隔离不是跨设备同步或安全沙箱 |
| 所有接续都必须先证明旧进程物理停止 | 本轮建议细化，待评审 | R1 经验证的共享效果隔离/安全重算可接续；R2 仍须可信终止和对账，不能靠租约过期盲重试 |
| Paperclip 文件保存必须全部自建，OpenMausBot 只有远控 | 纠正过强判断 | 已有项目快照与离线文件证据；优先适配，而非声称现成员工池完整接续 |
| 保存点依赖员工点击保存/commit/push 或模型提醒 | 明确排除 | Ethan 确认系统自动保存；工作单元触发＋周期兜底＋自动有界重试，无人工提交正向测试必须通过 |
| 重试、去重、回读验证、版本、来源、备份 | 保留 | 从广告域抽象成通用工程规则；外部副作用仍需场景化处理 |

## 3. 必须补充的产品与工程能力

- 真正的公司/部门/员工/AI 关系，以及用户与公司成员关系分离。
- 员工和负责人均可建群，独立群成员权限、历史消息访问和关联资产权限。
- 唯一任务事实；工作群、我的工作、部门/老板面板同源。
- 人与 AI/AI 与 AI 的明确交接，不以多机器人聊天替代任务执行。
- 工作私密与个人隐私分开，公司资产、维护责任和可见性分开。
- skill 从候选、评估、版本发布到再次使用的最小闭环。
- 离职/调岗后的任务、AI、知识、连接依赖移交；检索和缓存权限撤销。
- 一条千川只读场景 + 一条不依赖千川的通用协作场景共同验收。

## 2026-11-05 Bot 定位与版本历史纠正

Ethan 确认 Bot 就是 AI 同事。产品层统一用 Bot，工程/API 保留 Agent；正式实例映射同一原生身份。Bot 模板是配方，小队模板定义真人/Bot 槽位及交付，小队实例是本次成员绑定；task/run/attempt 不是新 Bot，临时子 Agent 不自动进入名册。

| 处理 | 本轮统一结论 |
|---|---|
| 保留并明确复用 | 原生 Bot 配置历史、skill 版本/测试、AGENTS/TEAM 模板包与预览；不重新开发独立 Bot/模板/版本引擎 |
| 修正事实 | 固定样本新 managed 指令保存只更新当前文件和活动记录，不追加完整指令历史；旧 history/diff/restore 兼容既有记录，表和接口存在不等于新保存可恢复 |
| 补齐必要证据 | 指令/资源优先复用原生 durable blob/manifest 加历史保留根或既有保留资产；缺失历史模板包通过固定来源/既有版本资产自动归档；Bot 能力清单关联配置 revision、内容快照、skill 和来源/评估/生效记录，run 留实际加载证据 |
| 禁止混淆 | 配置回滚不等于整 Bot 回退；hash/包版本标签不等于保存了历史字节；模板升级不自动改实例；回退不复活权限，不改旧 run |
| 不扩大范围 | 现有两个岗位包落为 Bot 模板示例、一个小队模板；P1 首次生效即留版本，P2 复用/改进/回退，P0 验缺口；不改变 Windows/公司 Key/跨机保存参数或后续工作流范围 |
