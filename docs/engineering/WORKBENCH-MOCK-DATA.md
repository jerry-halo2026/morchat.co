# 工作台 mock 数据（粘贴即用）

用于在没有真实数据时验证导入与台账渲染。三块分别对应职位 / 候选人 / 员工档案的「导入」入口，
表头故意混用中英文，并各留一处**故意出错**的行，用来确认错误提示是否落到正确的行与列。

## 1. 职位（jobs）

先导这一块：候选人和员工都要引用岗位。

```
职位	部门	编制	级别	薪资下限	薪资上限	用人经理
短视频编导	内容部	2	P5	15000	25000	林一
投放优化师	市场部	1	P4	12000	18000	周敏
客户经理		1	P5	面议	面议	
```

预期：
- 前两行可导入；部门与用人经理需先在系统里有同名部门/成员，否则分别报「部门不存在」「成员不存在」。
- 第三行 `面议` 解析失败 → 报「读不出数字，请把区间拆成两列」；`部门` 为空不报错。

## 2. 候选人（candidates）

```
姓名	应聘岗位	阶段	手机	邮箱	期望薪资	用人经理
陈子墨	短视频编导	面试	13800000001	chen@example.com	18k	林一
何铭轩	短视频编导	初筛	13800000002		-	林一
何铭轩	短视频编导	初筛	13800000003	he@example.com	20k	林一
黄梓萱	投放优化师	待定	13800000004	huang@example.com	15-18K	周敏
```

预期：
- 第 1 行导入成功。
- 第 2 行 `期望薪资 = -` → 报金额错误；手机里的 `-` 也会被识别成非法金额。
- 第 3 行与第 2 行同名同岗位 → 报「与第 2 行重复」。
- 第 4 行 `阶段 = 待定` 不在枚举内 → 报「没有这个阶段」。

## 3. 员工档案（employees）

```
员工	职位	职级	入职日期	转正日期	合同到期	部门
林一	内容负责人	M1	2024/3/1	2024-06-01	2027-02-28	内容部
周敏	市场经理	M1	2023.11.20	2024-02-20	2026-11-19	市场部
不存在的同事	专员	P3	2025-01-06			内容部
```

预期：
- 前两行导入成功（三种日期写法都能解析）。
- 第三行成员不存在 → 报「不是本工作区成员」。
- 转正/合同到期留空不报错。

## 4. 简历文件（resume）

准备几个文件名与候选人姓名一致的 PDF/Word 即可：

```
陈子墨-简历.pdf
何铭轩_2026.docx
随机文件.pdf
```

预期：
- 前两个自动匹配到候选人；`随机文件.pdf` 显示未匹配且不参与上传。
- 上传成功后候选人详情里应能看到 `resume_attachment_id` 指向的文件。

## 5. 验证清单

| # | 验什么 | 怎么看 |
| --- | --- | --- |
| 1 | 导入结果落在正确的台账 | 三个台账的列表各多出对应行 |
| 2 | 错误定位到行列 | 弹窗里红行 + 行尾原因，「共 N 行，可导入 M，X 有问题」对上 |
| 3 | 部门/成员/岗位引用 | 先把部门与成员建好，再导候选人，否则会成片报错——这是预期行为 |
| 4 | 人数统计 | `/overview` 的 People 分组计数随之变化 |
| 5 | 指标变化 | 「在办候选人」应等于非 hired/rejected/withdrawn 的行数 |

## 6. 已知限制（不是 bug）

- 同姓名成员解析取第一个命中（create 只接受 id），同名时需改用唯一列区分。
- 单列薪资区间（`15-25K`）只取中值；要保留带宽就用「薪资下限/上限」两列。
- 未匹配的简历不做持久化，需先导入候选人再上传。
