## 三个改掉的原页功能（不是遗漏）

### 1. 笔试管理 → 面试提纲

原页是「出卷 / 答题 / 判分」。客户判断：**出卷要人写题、答题要人监考，AI 时代两头都没人愿意干**。

改成提问资产：

- `hr_question`：每条题带 `intent`（考察什么）、`signals`（好答案的特征）、`red_flags`（什么要警惕）
- `hr_interview_guide`：`items` 是**快照**，题库改了不影响用过或正在用的提纲
- 页面三块：列表 / 编辑器（起草·挑题·自定义·排序）/ **面试中视图**（一次一题、勾已问、记原话、0–5 打分）

`hr_candidate.score_test` 字段保留在库里但全站不再读写。

### 2. 面试通知（`rs-notify` / `iv-nt`）不做

我们栈里没有站内消息与短信通道。硬做只能造一个"已通知"的假状态。

### 3. 办公室动画（`office`）整页不复刻

它占了原文件 1300 多行的 SVG 场景代码（座位网格、抽奖、挂钟、小人动作）。对我们的价值是"这个部门很活泼"，代价是维护。**其余十一页的功能一条没少。**

## 口径（容易被误读的数字）

| 数字 | 口径 |
|---|---|
| 综合分 | 面试均分 ×70% + 提纲均分 ×30%；没有面试均分 = `—` 且排最后 |
| 提纲均分 | **排除 `risk` 维度**——risk 题打的是"风险有多高"，高分等于候选人更差，混进均值会让红旗抬高综合分 |
| 在职 | 有 `hire_date` 且 `leave_date` 为空 |
| 离职率 | 期间离职人数 ÷ **期初在职人数**；分母 0 显示 `—` |
| 匹配度 | 四维 40/20/20/20，未评维度摊权而不是记 0 |

## 异动留痕的行为

`hr_employee_change` 是**只追加的事件流**，改档案时同事务写入。

- 一次改多个字段 → 只留一条，`kind` 取优先级最高（regularize > renew > move > grade > promote），`note` 列出全部字段
- **同值 PATCH 不留痕**（判定"读到的那行 vs 即将写的列"，不看请求体）
- 只改能力画像 / DISC / 备注 → 不留痕

## 仍缺的一块

**奖惩**（`hr_employee_reward`）在建。建好后花名册第四页签从"待建表"变成真列表。

## 文件柜的前提（已确认）

客户确认：**盖章走线下流程**，系统只出文件。所以文件柜 = 模板管理 + 选员工生成 + 下载历史，不做审批、不做电子签。

Word 用 Go 标准库生成（zip + OOXML）。PDF 优先用 PDF 标准 CJK 字体（不嵌字体文件），**若中文渲染不可靠就只交付 Word**，不产出一个中文变方框的 PDF。
