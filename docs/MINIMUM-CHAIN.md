# 最小纵向链路：契约切片与任务卡草案

> 2026-11-06，MC-S1-r8（R1-AUTH-r1 连续开发授权）。**三个切片实现已批准，精确契约/任务仍须达到对应技术门禁。** 本页任务定义由 docs/tasks/R1-01–03 消费，不再只停在准备；真实模型费用仍另批；另已完成的合成组队实验在 §1.1 登记，不抹去真实失败。C01–C08 状态仍由 Discovery 登记为 DRAFT。本页仅把现行契约裁成一条可验的链，不取代专项协议或降低完整 MVP 门禁。

## 1. 首轮必须验证多人协作与多 Bot

**Ethan 已确认：首轮就要覆盖多人、多 Agent 协作；最新 S1-D 接受原生任务讨论，独立 IM 群入口后补。**撤回 r0 单人单 Bot 作为首轮验收出口的建议。单 Bot 只用于排障；不能缩掉多人身份、多 Bot 协作和权限。下文“群内”用例在本切片指获授权的共同任务协作面，不要求新建群后台。

**我的工作→原生项目/父任务及独立工作 Issue 的评论→两名员工按分工 @ 多位 Bot→服务端逐目标受理→授权 Windows 设备上的 DSH 并行执行→Bot 结构化交接/消费成果→自动归档和逐 run 用量→群内可追溯交付→有权真人验收。**

最小合成 fixture 建议：两名真实测试用户（负责人/员工）、两位预置 Bot（资料/内容）、一个共同项目/父任务、两个独立工作 Issue 及评论线程、一项父工作及其原生子任务、两台合格 Windows 设备；另有一个非群成员账号和受限来源做负例。人数、角色和机器是最小测试样本建议，不是平台上限。设备与管理人均需对应资料授权；入群不授予电脑权。公用 Bot 先用明确登记的最小授权池，未合格/离线显示原因，不任选空闲机器。

范围取舍：
- **采用：完整原生 Multica 产品＋有证据的最小差异。**撤回“首轮必先建群/成员/线程 schema”的实现假设；原生 Project/Issue 多人评论、子任务、Squad、多目标 @ 先用。S1-D 已确认首轮用任务讨论，独立 IM 群入口后补；私聊 Chat、Workspace 或 Squad 不能冒充私密群 ACL。
- **不采用：单人链路通过即首轮通过。**那只能证明工具可执行，不能验证公司协作定位。
- **不采用：首轮全做完整 IM。**语音、复杂群运营、消息全文编辑器、模板市场、知识连接器仍暂缓；首轮沿原生项目/任务/小队完成协作成员配置、讨论、@、关键控制及交付。独立群入口后补；创建者不能扩大资料授权。

可先 Web 联调共享 views，**首轮仍须在 Windows Electron 真实界面做两账号多人协作验收**。Web 成功不替代桌面，不能用 webSecurity:false 换启动成功。只用合成资料，公司模型入口不回退员工个人账户。

### 1.2 首轮实际走查与判失败

1. **双人组队：**按已确认 S1-D，负责人/员工分别在获授权范围创建项目/任务、配置小队真人与 Bot 成员，关联父工作及两个独立工作 Issue；Workspace 成员、任务访问、Bot 调用、资料和设备许可分别检查。组队不改变 workspace 资源权限；负责人不默认可读员工私密资料。
2. **真人协作：**两人在群中普通讨论、分工、认领与同线程补充；另一人及时看见获权消息。无 @ 不调用模型，不能为监听所有群消息启动隐藏 Agent。
3. **多 Bot 并行：**两人分别 @ 资料 Bot 与内容 Bot，形成可追溯原生子工作与独立 run；两台已授权设备并行，本机目录/session 分开，回复分别署名，父任务真人责任不变。同一条消息 @ 两位也要单独测逐目标受理/拒绝/未知，不把局部成功显示成全批成功。
4. **Bot 与 Bot 合作：**另测资料 Bot 通过受控结构化委派交给内容 Bot；使用已确认资产版本和来源/受众授权，不读对方硬盘。依赖结果重复/晚到只能按同意图对账；普通 Bot 回复中的 @ 不自动唤醒。等待依赖时释放可释放槽位，不让父 Bot 占槽空等。
5. **同一 Bot 服务不同员工：**两人对不同线程同时请求同一 Bot，分离发起人、输入范围、工作目录和费用归属；不得串入另一线程/私聊/历史摘要。不能把同一 Bot 全局 session 当共享上下文。
6. **交付汇合：**每个 run 的成果自动归档、独立 hash/版本及真实用量可查；只有约定依赖满足才能显示对应汇合就绪，失败/取消/待补充单列，不能无限等不存在的文件。有权真人验收具体交付版；汇总不能覆盖各 Bot 原回复。
7. **权限与故障：**非成员、被移出成员、失去来源权限的 Bot、未授权设备；普通消息/重放/历史编辑；一端离线、两人重复操作、单 run 停止和整个协作停止；一个 Bot 失败时另一个结果仍保留。测 UI、直接 API、推送/补拉、搜索/附件和实际模型输入，不只看气泡是否分开。

任一越权上下文进入模型、消息回显触发接龙、重复派单/收费、强制全局串行、成果被另一 run 覆盖、取消复活、私群内容扩播或单 Bot 演示冒充群协作，MC-S1 判失败。跨设备同时运行不等于断电后自动换机接续，后者仍按完整 DV 门禁单列。

## 3. 契约切片：继承 C01–C08，不新立第二协议

### 3.1 原生 ID 与企业字段边界

本次只读核对 Multica SHA **58402f5d11d2f8f3a22c1bb9fe0d6c52992d3dbe**。原生 server/pkg/agent/dsh.go 明确 JSONL v1、multica profile、execute/cancel/request_id，与 ACP 独立。沿该 driver，不另造桥。

特别注意：原生 task_usage.task_id 关联 agent_task_queue.id，**不是业务 Issue ID**。UI 文案“任务”可以指 Issue，但接口不能混用。推荐逻辑契约字段如下，名字是设计词汇，不是声称已存在 API：

| 标识 | 含义与权威 |
|---|---|
| issueId | 原生业务 Issue；首页、任务详情、成果索引用它关联 |
| runId | 原生运行/队列记录 ID，映射 task_usage.task_id；attempt/epoch 若缺则同域扩展，不能把计费写到 issueId |
| agentId / runtimeId / deviceId | Bot 稳定身份、原生 runtime 与受控设备映射；不能由昵称或发消息人的电脑推定 |
| groupId / threadId / membershipRevision / audience | 协作范围逻辑词，不是必须新建表；S1-D 原生方案优先映射 workspace/project/issue/comment/thread。只有独立群/历史受众缺口才扩展；评论线程不自动形成安全边界 |
| messageId / messageRevision | 原评论/消息记录与修订，编辑历史不重派；若原生缺修订须明确扩展 |
| intentId / rootId / causationId | 同一次真实委派、协作根与因果；由服务端持久映射，传输重试沿用，不允许客户端自由换 root 绕费用 |
| requestId / payloadDigest | 一次命令的幂等键与规范化参数摘要；同键同内容返回当前可读回执，同键异内容拒绝 |
| policyRevision / releaseDigest | 当前企业授权与已固定能力组合；旧授权不能随恢复/回滚复活 |
| artifactId / artifactVersion / sha256 | 原生附件及其同域不可变版本关联；hash 不替代原始字节或权限 |
| providerCallId / receiptId / reportRevision | 每次真实模型请求、计量证据与修订；明确实际重试和重复回执的区别 |

MC-00 必须把以上每项逐条标“已有原生字段/同域扩展/本切片未启用”，确认字节长度、可空条件、错误形式、数据库约束与兼容版本。禁止 worker 各自发明 DTO，禁止据这张逻辑表直接创建重复 schema。

### 3.2 最小命令、回执与失败语义（推荐冻结项）

以下是语义操作，不是新增 HTTP 路由承诺；具体路由/JSON schema 在 MC-00 从原生入口映射，统一签认后才 TEST-FROZEN。

### 3.2.1 终态、上传凭据和原生入口的关键接缝

再次只读核对：handler/daemon.go 的 Complete/Fail 路径会删除 task token；handler/file.go 的 task_id 上传分支只接受 Chat 任务。本链群内任务线程关联 Issue，**不能把 runId 塞进该 task_id 表单字段，就宣称成果已正确归属**。沿 issue_id 原生上传，可信 run/attempt 关联由受权接收端补齐验证，不相信模型提供的归属。

推荐收尾时序：DSH 进程结束→固定文件字节及本地待上传记录→在有限收尾期限内自动上传并取得中央绑定回执→报告原生 run 终态和成果状态；上限和重试参数在 MC-00 事前冻结，上传不得无限占执行槽。DSH 已结束应立即在界面可见，不伪称模型仍运行。

若收尾超时/终态先提交/daemon 重启，旧执行 token 不续命：受控 daemon 重新鉴权、重验当前 actor/Bot/设备/资料资格，申请仅针对该 run 已登记输出清单的短期补传能力。它不能调用模型、执行工具、改任务/当前成果或上传其他路径。仍属当前合法 run 的待归档版本可按条件完成；换代/撤权后仅有明确证据接管授权时隔离收取，不能覆盖现行成果，否则拒绝并给有权责任人待办。补传接口若原生缺失，就在同一 Multica 后台扩展；禁止改用员工管理员 PAT 或共享管理员 token 代传。

MC-01 定补传授权，MC-04 定本地持久材料，MC-06 定中央确认与终态顺序，MC-00 单独冻结该联合 fixture。测试必须覆盖“原生 token 已删除后补传”与“补传能力不能执行/扩权”，否则自动归档不能算故障闭环。硬断言：中央 run 已终态、原执行 token 失效、本机重启后，不重跑模型仍能在当前合法授权下补齐归档；已撤权必须拒绝。

### 3.3 必须分开显示的四个维度

- 执行：尚未受理、等待设备、准备、运行、停止中、已终结、结果待核对；实际原生状态映射由 C02/C06 冻结。
- 成果：未产生、本地已生成、待归档、已归档、归档失败、已撤回/受限。断网只显示待归档，不能显示同事已可下载。
- 计量：未报告、部分报告、token 已核对、金额未知/估算/供应商证实。没有价格证据不伪造金额，也不把估算叫账单。
- 业务：仍按原生 Issue 工作流及验收记录；原生指令已区分 run 结束、in_review 和人工 done，但 prompt 不是强制授权。首轮建议 pr_merge_status=none；另测 Agent/API/拖动/工作流不能绕指定成果版本验收，不重写 VCS。

界面“不丢维度”，后台“不新造状态机”：展示 DTO 从原生记录和必要同域回执派生。首次 MC-S1 成功须完成 §1.2 多人/多 Bot 正反例，并且各相关运行真实结束、约定成果自动归档且有权账号可回读相同 hash、真实 token 幂等入账；金额完整性单列，不能因此声称财务结算完成。

### 3.4 自动归档不是整个工作空间接续

B05 管本机有界待上传队列/稳定文件读取，B04 管中央附件、版本、ACL 与持久确认；B07 提供一致性/恢复边界评审。建议在 run 收尾按 §3.2.1 由受控执行器自动发布约定 deliverables，不把“模型调用 CLI 上传”作为唯一机制。运行失败/取消后的文件只按明确草稿/隔离证据语义收取，不假装业务成功；权限已撤或旧代次只按受权证据入口对账。

文件校验包括目录逃逸、junction/symlink/重解析点、读取期间变更、异常大小/类型、重复文件名、同键异字节；只靠 .gitignore 或扩展名不构成授权。凭据、个人目录、隐藏环境文件不得因自动扫描归档。受控输出与来源 ACL 的交集随资产保留。

MC-S1 测跨设备独立并行与各机重启/网络重试后的待上传材料对账，**不把它叫 C07 完整检查点或双设备恢复**。周期中间态自动保存、Git dirty/untracked、断电、旧机回连、冲突与副作用对账继续按 WORKSPACE-CONTINUITY / DUAL-DEVICE-VALIDATION 验收；参数只在 DV 定义。不得因为最小成果链通过就将 B07 移出完整 MVP。

### 9.4 撤权观察点与实验判定参数

- `t0` 是服务端权威授权变更提交，不是点击按钮时间。调用者收到撤权成功后，新读取/写入/派发必须按新政策；**服务端不设“几秒内仍可读”的宽限**。已选输入在新投递/提交前再验权；并发测试用明确屏障和服务端事件顺序，不凭 sleep 判断。
- 在线健康客户端的受控 UI、内存数据、持久缓存/IndexedDB 和该资源通知清理，本轮目标为 `t0` 后 **10 秒内**完成并留下回执；连续观察 **30 秒**确认无迟到响应/WS/游标回填，重启再检查。10 秒是清理目标，不是允许服务端继续供数的窗口；缺观测证据不能算 PASS。
- 离线客户端不声称在 `t0` 瞬间清理。敏感内容不得持久离线存储；断联禁止新动作。普通旧缓存能否短期离线显示沿现行策略，不能用这轮作新增许可；重连先同步授权、锁住旧资源呈现，再清理，按重新取得权限状态时间测 10 秒目标。故意离线应记录“待清理”；重连完成前不报撤权清理闭环。
- 每个状态变更/撤销用例至少在独立初始状态重复 **3 次**；一个反例即 FAIL，不用平均值或多数通过掩盖。其他用例至少一个明确正例和负例，所有数据标记检查覆盖实际响应/持久副本。阈值由本节统一维护，不复制成 D06 设备心跳或双机 RPO/RTO；执行前签认，运行后不得追改。
- 隐藏 UI 但网络/索引仍收到内容、HTTP 拒绝却后台改动、全拒导致合法用例不能工作，均 FAIL。可选功能确实服务端禁用且无后台同步可记 DISABLED（注明降级），不能将核心部门/私密能力禁用后宣布整体 PASS。
