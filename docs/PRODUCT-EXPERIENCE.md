## 1. 直接回答用哪套

| 使用者/场景 | 使用哪套 | 不采用什么 |
|---|---|---|
| 员工日常工作 | morchat 统一工作台，以“我的工作”为首页，侧边栏进入对话、任务/面板、Bot 与资产 | 不直接发一套 OpenMausBot 客户端再让员工登录 Paperclip |
| 部门负责人 | 同一个 morchat 客户端的部门视图，与工作群/任务相连 | 不把 Paperclip 的 Agent 组织树当部门架构 |
| 老板 | 同一个 morchat 客户端的公司目标视图 | 不以 AI 运行次数/消息量代替经营成果 |
| 执行配置、诊断与异常排查 | 授权人员使用 Paperclip 原生管理台，或 morchat 的受控诊断视图 | 不把管理员凭据嵌进 iframe 或发给普通员工 |

“整体页面用 Paperclip”的准确说法：以其完整公司工作台为基线，保留公司/成员、Bot 与 AI 汇报关系、目标/项目/任务、Inbox/人工决策、审批与执行控制、Skills/Sources/Studio、文档/成果、包/导入、Apps/连接审查、运行/审计/费用/预算等功能及前端源码，不只是复用布局和看板。我的工作、真人部门面板、人机群及设备治理补企业差异；对话区选择性抽取 OpenMausBot 展示/输入子件，Paperclip 已有可用卡片优先保留。原生例程和实验功能逐项登记是否启用，不自动全部进入首版。原样管理员台仍受限，不能把源码复用理解成开放管理员权限或再挂一套应用。

## 2. 员工体验与 OpenMausBot 的关系

产品命名统一为 Bot（AI 同事）；工程仍用 Agent，不另造身份。Bot 模板是创建配方，Bot 实例是具体 AI 同事，小队模板是分工配方，run 是一次工作执行；临时子 Agent 不自动进名册。体验参考：Bot 像同事，协作可在对话展开，但工作不以聊天记录作为唯一入口。员工先看到待认领/待处理/待交付等工作，再进入相应群和任务线程；AI 的追问、回复和成果保留上下文，任务卡与资料可双向定位。

实现选择：在 Paperclip React/TypeScript 前端基础上形成一套统一客户端与权限入口；OpenMausBot 的对话展示/输入/活动折叠优先源码抽取适配，不以仿写为默认路径。OpenMausBot 的完整 server、账号、私聊归属、任务状态和 bot 配置不同时启动为另一套权威系统。源码可读不等于存在稳定可嵌入 SDK，前端实现前先验证最小抽取闭包；不能保留独立 Store/身份/任务后台才能工作时，记录卡点，仅替换不可分离部分，不默认重写整块对话，也不为复用引入第二控制面。

首版包含桌面客户端及完整本地 runtime（运行管理器、harness 和受控工具）；员工、负责人和老板用同一安装包，面板内嵌。浏览器访问是可选的同源辅助入口，不能因此自动调用本机工具。原生移动端、语音、会议和任意桌面软件通用控制不在首版。

OpenMausBot 的现有 Client 模式是连接另一台 Host，并不同时启动本机工具宿主；中央后台 + 保持本地完整 harness 的 runtime 需要适配，不能把远程 Web 页面装进壳就视为完成。具体边界见 [执行环境](D:/dev/morchat.co/docs/CLIENT-RUNTIME.md)。

### 2.1 群里的 AI 在哪里工作

员工工作助手默认在其本人指定授权设备运行；部门公用 Agent 自动选择预授权设备池内符合数据、能力、资源与容量条件的节点。不是谁 @ 就用谁电脑，也不是都用群主电脑。入群不授予设备使用权，公用 Agent 的维护人不必亲自在线才能由其他合格池节点执行。

AI 名片展示归属/维护人、可服务范围与执行策略；有权者可配置设备池，普通群成员不因此看到全公司设备清单。任务卡展示 Agent 身份、实际执行位置/变更原因、状态和交付版本。池内自动选择无需逐次人工批准，但每次验权；员工助手超出默认设备的转移要明确授权。

群共享获授权的消息/目标/任务/资产，不共享私人文件、其他群、浏览器登录和完整个人模型会话。多 AI 通过明确子任务/交接协作，普通回复不产生新的 Agent 唤醒。详见 [群协作与设备池](D:/dev/morchat.co/docs/DISTRIBUTED-COLLABORATION.md)。

## 3. 工作入口的最小组成

以下是能力清单，不是把每项都做成一个一级菜单；统一导航建议见 §3.1。

| 入口 | 员工看到什么 | 与业务事实的关系 |
|---|---|---|
| 我的工作 | 待认领、我负责、等待我补充、我关注的交付 | 查询任务权威状态及自有交接请求，不另建状态 |
| 部门业务 | 本部门普通任务明细及目标关联、工作阶段、交接和阻塞情况 | 员工与负责人均可用；普通任务默认同部门可见，敏感内容另授权 |
| 跨部门协作 | 获授权项目或任务的明细、进度、交接、阻塞和交付 | 同一工作台按授权范围呈现业务流转，不展示对方整个部门 |
| 工作群 | 人与 AI 消息、@、附件/链接、任务卡、阶段成果 | 每条消息有真实发言身份和来源；引用任务需独立授权 |
| AI 同事（Bot） | 可用 Bot、职责、维护人、模板来源、能力版本和当前就绪情况 | 实例映射同一个 Agent；升级/换设备/新任务不创建影子 Bot |
| 目标与项目 | 自己参与或有权查看的目标、任务与成果 | 展示目标/任务关联和责任，群不强制一对一绑定项目 |
| 设备与运行 | 本人默认设备、有权管理的公用 Agent 池、版本/能力、并行运行、局部等待原因、待归档大小，单任务取消/设备暂停/撤销入口 | 入群不入池，按权查看；自动选机与已执行分别展示，不公开无权设备清单 |
| 用量与设置 | 自己可见的用量；负责人/老板增加获授权预算汇总和管理操作 | 使用模型、查看成本、管理预算、管理 Key 分开；员工不填写供应商 Key |
| 资产 | 可访问的成果、知识、skill；我维护/待评估的条目 | 资产所属公司、维护人与可见范围分开展示 |

员工与负责人都有部门面板：本部门普通任务明细及其流转默认同部门可见；负责人另有所负责部门的管理操作。跨部门参与者也能在同一工作台查看获授权项目或任务对应的业务流转。老板增加公司目标、部门交付和有来源的业务指标。不是老板独享面板，也不是三个独立应用；查看权限不自动授予修改、分派或管理权限。

### 3.1 前端定位：以工作为中心，不拼接参考产品

**已确认：**员工、负责人、老板使用同一工作台；默认首页为“我的工作”，先展示今天/当前待认领、待处理、待交付、待确认的事项，再从侧边栏进入对话列表。无截止日期和逾期事项不能因“今天”筛选消失；P1 期限/逾期展示先冻结 C02 的截止日期来源和时区，不从创建/运行时间推算，缺契约时显示当前待办/未设期限，不伪报逾期；通知、任务和待审批不是三份重复待办。负责人和老板增加获授权视图/操作，不换一套产品。

方案取舍：①聊天优先的个人助手壳，适合对话延续，但易把未完工作埋在消息里，不作为默认首页；②**工作首页＋协作对话＋同源任务/资产视图，采用此方向**，保留聊天便利且让责任/阻塞可见；③并排运行 Paperclip、OpenMausBot、Multica 完整应用会引入多套导航、身份与状态，已排除。采用 Paperclip 前端基础并适配 OpenMausBot 对话源码，不等于这种拼盘；不是再造完整 OA/IM，也不是把管理员权限换皮给员工。

以下侧边栏分组为推荐信息架构，名称、顺序和视觉密度待低保真评审；不影响已确认首页：

| 推荐分组 | 内部内容 | 唯一实现 / 首版露出方式 |
|---|---|---|
| 我的工作（默认首页） | 待认领、待处理、待交付、待确认；阻塞/逾期/待同步；最近工作 | 原生任务/Inbox/attention/审批投影，不再并列一套独立 Decisions 待办中心 |
| 对话 | 获授权工作群与 Bot 对话、未读、任务线程 | OMB 选件接企业消息与同一任务；不按参考产品分列表，不因普通发言派工 |
| 工作 | 目标/项目/任务；列表、看板、只读计划甘特；部门/公司/获授权跨部门范围 | Paperclip 原生对象/组件；同一任务详情。例行任务保留能力登记，启用需另行选择，不加低代码画布 |
| 组织与 AI | 真人部门/成员、Bot 名册与 AI 汇报图、小队、岗位/模板入口、就绪缺口 | 公司/用户/成员/Bot 尽量原生；部门及真人岗位补齐。真人组织图不混成 Agent reportsTo；模板从此处跳同一来源 |
| 资产与能力 | 成果/知识；Skills / Sources / Studio；岗位/Bot/小队模板及版本来源 | 原生文档/成果/skill/包分别是对应正本，在同组分子页，不混成一张万能资产表，不再造编辑/测试库 |
| 应用与连接 | 获准业务来源/应用连接、动作范围、连接审核/过期状态；公司模型可用性 | Paperclip Apps/grants/审查优先；普通员工只见有权连接，Key/供应商路由管理另限权；不展示完整 OMB 市场 |
| 用量与治理 | 我的用量；获授权部门/公司费用/预算、审计与治理记录 | 原生成本/运行账；按权逐级露出。普通员工不见全部日志/秘密，也不因老板身份默认可读私密内容 |
| 底部：设备与运行、设置 | 本机/授权池状态、等待原因/待上传/诊断；个人偏好与获权管理 | 本地 DSH 与 Paperclip run 关联；配置/插件/适配器管理不混入普通员工设置 |

这是完整功能分组建议，不要求首屏平铺七个大菜单：高频我的工作/对话/工作固定可见，组织/资产按职责展开，连接/治理可收在“更多/管理”，设备/设置在底部。无权分组不露出，有权但未配置显示真实就绪原因；具体标签/顺序仍待低保真评审，未把新建议记为已确认范围。

部门/公司范围由真实授权决定，不靠切换菜单扩权。跨部门授权只出现相应项目/任务；可以收藏入口，但不另造跨部门任务库。组织架构、权限、费用管理入口按权置于相应视图/设置，不为老板单独做门户。首版不做任意自定义导航、插件页面市场或多产品 iframe 拼盘。

### 3.2 对话、任务线程与执行详情

- **群主时间线：**每个实际对群发言的 Bot 独立署名，展示结果、问题和重要交接并关联任务。完整回复在该消息/任务线程可展开；负责人总结不覆盖原文。多个 Bot 同时交付时按任务组织，不只留最后一位。
- **任务线程：**从群卡、首页待办或工作面板进入同一个 task ID 的讨论视图；查看参与者回复、交接、文件版本和待决问题。不同入口打开同一任务详情和有权讨论，但各消息/附件仍单独验权。同任务可有不同受众的线程，不拼成一个跨群广播窗口；从首页/面板发言先选择线程/讨论域并显示受众，回复沿用当前线程，未选不发。私密群内容不会因链接了普通任务就出现在全部门线程；来源不明的原生正文不扩播。
- **执行详情：**同轮过程说明和连续工具活动折叠，进度更新原卡，不把每个日志事件发成新群消息。审批、阻塞、失败与停止原因必须可发现；系统收件回执标为系统，不冒充 Bot 已经思考。
- **一个输入框，@ 后发送：**已确认取消“普通讨论 / 请 Bot 处理”模式选择。群与任务线程内输入 @，从有权候选中选中具体 Bot，直接发送即提交该目标的提问/委派；没有执行型 Bot 提及就是普通消息。选中项保留稳定 Bot ID，不由后台扫正文猜目标；同名展示归属以消歧。仅写名字、未解析文本、引用/代码/粘贴及 Bot 输出中的 @ 不产生新的执行授权。发送前可见本次目标；未识别/失权目标明确报错，不静默换人或群发。编辑已发送消息只改消息修订，不改变已准入任务；修改工作指令要新发一条 @ 请求并关联原工作；已存在追问/审批/待处理补充的专用按钮走其原生交互，不需再 @，见 §3.5。授权范围/费用与任务关联可查。
- **结果不作假：**本地出现、待同步、团队已收到、任务已验收分开；原生任务状态、运行状态、自动保存与业务验收仍按 §5.3 展示。没有 provider 原始增量就显示正在处理/已完成消息，不伪造逐字生成。

公开工作回复不含模型隐藏推理或原始秘密。用户可看的消息、某 Bot 可消费的上下文、会启动哪个 Bot 必须分开处理；精确触发/防重规则唯一见 [群协作 §4](D:/dev/morchat.co/docs/DISTRIBUTED-COLLABORATION.md)。

### 3.3 统一界面契约与首版体验门禁

整个产品以 Paperclip 前端源码为基础，共享一套应用壳、路由、身份与资源范围、设计变量和基础组件；任务卡/详情、Bot 身份、资产引用、消息和版本标签各有唯一语义。沿用适配后的 Paperclip 查询与组件基础，不另外搭一套等价 UI 框架；数据读写经企业权限和命令契约，不直连数据库或绕过准入。OpenMausBot 展示组件通过薄适配接统一 DTO/命令，不带入其完整 Store、私有 API、自动群路由和账号体系。React/TypeScript 与源码优先复用方向已确认；具体上游 UI 构建基线、提取边界、桌面壳及分发仍按 D08 验证，不在本轮安装或搭骨架。

共享的空态、加载、失联/同步中、过期数据、无权、失败与重试状态必须先约定；禁止假成功、无权先渲染后隐藏、通知/计数泄露内容、复制原生按钮却缺后台权限。AI Markdown/链接/附件按不可信内容展示，不可借渲染调用本机 IPC/工具。待办、运行、保存和验收各有一致标签，不把不同含义都叫“完成”。

B02 指定一个前端集成 owner 管应用壳、设计变量、共享卡片和展示 DTO；页面 agent 只在冻结边界内开发，不各装一套 UI 库/状态框架/路由器。具体协作与合并门禁见 [工程基线 §5](D:/dev/morchat.co/docs/ENGINEERING-BASELINE.md)。

P1 先用一条“首页待办→群/任务线程→两个 Bot 各自回复→文件→返回首页”验证，不先铺满页面。P2 扩部门/公司和资产版本；P3 做角色/异常回归。最低体验验收：同任务跨入口身份和状态一致、各 Bot 回复可追溯、受限来源不因跳转泄露、断线不伪称送达、键盘/可读标签及待决事项不依赖仅颜色。默认首页及 Paperclip 整体前端＋OpenMausBot 对话源码方向已定；低保真细节、组件依赖闭包和适配方案须在相应前端实现任务前评审，不阻塞无完整 UI 的 P0 安全/协议实验。

### 3.4 低保真：同一份工作，五个入口

采用 Paperclip 的公司/工作分组导航、紧凑任务行、列表/看板切换、详情与属性区结构；OpenMausBot 的署名消息簇、真人/AI 消息、回复附件、输入器和过程折叠置于同一设计体系内。只替换对话内容区域，不嵌入另一套窗口、侧边栏或登录。Paperclip 已有任务讨论组件，不再同时展示两份可写评论流：其任务元数据/附件/执行记录继续复用，对话呈现由适配层接所选消息模块，原生评论与协作域按 C02 区分来源、投影和唤醒。

| 入口 | 关联方式 | 原则与首版范围 |
|---|---|---|
| 我的工作 | 待认领/处理/交付/确认点击同一 issue；负责人增加所管范围的阻塞/验收 | 薄查询组合，复用任务行/状态控件，不复制待办状态机 |
| 对话 | 群内每个 Bot 独立署名，任务卡进入同一 issue 的有权线程 | 普通讨论不执行；在同一输入框 @ 选中 Bot 后发送即提交处理意图，无模式切换，工具过程折叠，审批/失败不隐藏 |
| 任务列表/看板 | 使用同一查询、状态与 task ID，卡片打开同一详情 | 复用 Paperclip 源码；原生状态映射有明确表，不在 UI 自造可写状态；生产拖动须过权限、修订和状态迁移验证 |
| 计划甘特 | 与看板共享任务、范围和详情，展示计划日期/依赖，未排期独列 | 首版只读，不拖动改排期、不自动调度；日期含义/时区/未排期/依赖类型及唯一写入方须在 C02 冻结；不拿运行起止冒充计划 |
| 成果 | 消息附件、任务成果区、资产目录指向同一版本 | 公司已归档、待验收、已验收分别展示；同一任务可保留多个版本，预览再验权，不复制文件库 |

**员工走查：**林悦首页见 ACT-102 待交付→打开任务线程，分别查看资料 Bot 的摘要 v1 与内容 Bot 的方案 v2→在群中直接讨论，或 @ 选中内容 Bot 后发送修改要求→确认公司已归档再提交验收→看板变为待验收，甘特仍保留计划日期，不因运行结束伪称完成→成果预览回到同一任务。

**负责人走查：**周然首页见所管运营部待确认/阻塞→查看同一任务原回复、版本与保存证据→通过或退回，保留版本及修改记录→看板同步业务状态，跨部门获授权的 ACT-103 可查看交接状态。验收不自动唤醒全群，也不自动发布为 skill；任务完成只影响已有受控依赖规则。查看项目不等于查看整个内容部。

现有五入口低保真只验证一条主工作流，不是全产品导航或全部功能的定义；未画出的成员、技能工作室、应用连接、审计等不能据此删除。本轮补功能地图，不声称重绘了完整低保真。演示中用一套本地示例记录联动五个入口、切换员工/负责人；这不是已经导入或运行 Paperclip/OpenMausBot 的产品，也不是 P0 证据。低保真不提供真实发消息、模型调用、文件下载或拖拽写任务。实际抽取边界和固定源文件见 [源码复用清单](D:/dev/morchat.co/docs/REFERENCE-REUSE.md)；本轮只调整设计与文档。

### 3.5 完整操作链：一个工作台内做人机交接

操作先按对象定义，不按参考产品划分页面。优先沿用 Paperclip 已有 interaction/approval/queued-comments/run 控制与卡片，OMB 只补不足的交互和展示；同一事项在“我的工作”和线程出现是同一原生 ID 的投影，处理一次两处同步，不再造待办/审批状态机。

| 员工 / 负责人操作 | 用户看到的内容与结果 | 必须保留的边界 |
|---|---|---|
| 回答 Bot 追问 | 问题、原任务/Bot、选项或补充输入；区分“答案已记录”“待送达本地执行器”“已消费/需重新确认” | 有当前回答权限的人才可提交；负责人不是自动代答人。指定真人回答的问题不由另一个 Bot/默认值代答；历史回答不改写，变更形成新要求 |
| 批准或拒绝一个动作 | 具体请求、资料/工具范围、用途、有效期与本次影响；明确拒绝/过期/撤销 | 不是“全权允许”；批准记录不等于执行成功。查看任务、批准工具、验收成果是不同权利；MVP 禁止的第三方写入不能借弹窗放行 |
| 运行中补充 | @ 原 Bot 追加并关联工作；展示“待处理”，可在未消费前改/撤；已消费展示处理回执 | 原生队列修订冲突不覆盖；修改旧聊天不改变指令。不支持即时补充就诚实显示“下一轮处理”，不显示虚假的“已注入” |
| 停止本次运行 | 选定 run，显示停止请求、待执行器确认、已停止或状态待核对 | 不是停止全部队友；显示仍在运行的关联子项。离线不能即时确认，更不能显示进程已停 |
| 停止本次协作 | 预览本 root 的运行、子任务及待处理要求；关闭该范围新增工作并逐项停止，展示未停/无权项 | 不停止其他 root/同一 Bot 的无关任务；不会因重连、旧补充或子项迟到自动重启。新授权“继续”才允许后续运行 |
| 停止并按新要求继续 | 独立、明确命名的中断操作，展示将使用的新要求和实际执行状态 | 这不是普通“停止”；旧执行未可信终止/效果未核对不能直接重放。未验证能力不显示可用按钮 |
| 查看 / 提交文件 | 本机产物/待归档 → 公司已确认版本 → 已提交待验收 → 已验收；消息附件和任务成果打开同版 | 同部门可读不等于可验收；指定有权验收人针对确定版本验收。退回改为新版本；旧链接不漂移；撤权后预览/下载拒绝 |
| 配置 Bot / 小队 | 配方草稿、将新建/绑定/变化、版本差异、所需权限、缺项和部分失败；员工与负责人均能在授权内维护 | 小队优先绑定既有真人/Bot；职责、工具、资料和设备分别就绪。模板导入不复制旧记忆/授权；发布和现存实例升级另行明确，不自动热改 |
| 纠正记忆 / 改进 skill | 展示本次实际加载知识的来源/范围/版本；纠正知识或提出方法候选，保留差异和评审记录 | 不展示整个私人 HOME。知识用既有文档版本、skill 用原生版本/测试；Undo/回退也是有条件的新变更，不复活权限；自动记下不等于公司发布 |

最小按钮按实际能力开放：Paperclip 已有同轮 steer 不代表 DSH remote 已支持。P1 必须有安全的下一轮补充、回答/拒绝、停止与文件交付；即时 steer 在验证后再开放。多人抢答、双窗口批准、上传重试、取消中离线都必须有确定回执，不能让用户靠刷新猜结果。精确命令/停止语义见 [群协作 §4.6](D:/dev/morchat.co/docs/DISTRIBUTED-COLLABORATION.md)，不是新的聊天模式切换。

### 3.6 从完整参考能力收敛到一套产品

证据清单在 [复用 §4.6](D:/dev/morchat.co/docs/REFERENCE-REUSE.md)。页面存在、生产路由挂载、默认可见、允许谁操作、组合运行验收是五回事。Paperclip TeamCatalog 仅有组件/API、未挂生产页；Decisions 默认隐藏且接口受限；MyIssues 不是现行首页；Apps 核心在固定样本已默认开，不能一律标实验关闭。我们的入口选择必须记录这些条件，不直接照抄官网菜单。

| 产品链 | Paperclip 原生基础 | 补充来源 / 必须自建的差异 | 首版呈现边界 |
|---|---|---|---|
| 找工作与看经营 | Inbox/Blocked、任务、目标/项目、Dashboard | 企业责任分组、部门/跨部门查询范围；借 Multica 工作视图布局 | 首页优先，不把每条通知当独立任务；负责人和老板看同一事实的获权汇总 |
| 建人机团队 | company/user/membership、Agent/汇报图、包/预览导入 | 真人部门、小队真实成员与发布授权；借 OMB 成员/差异预览、Nodo 岗位槽 | 沿同一身份/包，没有第二 Bot 配置库；模板入口未就绪不得假称已安装 |
| 对话与人工交接 | issue 讨论、interaction/approval/queue/cancel | 企业群与稳定 @ 意图；OMB 可分离对话/附件展示；跨 Bot 回复和整次协作停止范围 | 原生卡片能满足就直接适配；不复制完整 OMB Store/Composer 控制系统 |
| 执行与交付 | 原生 run/workspace/artifact/document/revision/批注 | Windows DSH、合格池、自动保存/接续；借 Multica 输入/过程/交付区分 | 一次运行不等于任务完成；文件归档与业务验收分开；每份结果能回任务和来源版本 |
| 复盘与复用 | Skills/Sources/Studio、原生测试/版本/包 | 来源授权、业务评判、能力组合实际生效；OMB 差异/来源体验 | 候选→案例/测试→授权发布→下次获准使用；不把自动整理、执行成功或保存文件叫自我升级完成 |
| 连接与治理 | Apps/grants/工具动作审查、成本/预算/活动 | 业务只读范围、部门归集、公司模型网关/设备授权 | 用量、预算、工具许可和验收不混合；例程/插件/实验逐项启用，非首版默认全开 |

**沿真实工作走一遍（非千川专用）：**

1. 员工林悦打开我的工作，看到自己待交付任务和一条原生 Bot 追问；打开该任务线程回答，首页同一条待办结算，不再去第二个审批中心。
2. 负责人周然在同壳项目页下“完成活动方案”目标，选已有员工及资料/内容 Bot；用小队模板预览新增与绑定、缺失技能/业务来源/设备授权。不足时显示缺口，不能因为组队成功就自动授予资料或电脑权限。
3. 林悦在获权群 @ 资料 Bot 提出分析。发送回执→原生受理任务/run→设备就绪/执行分别显示；另一 Bot 有明确任务可并行。群里分别呈现两位 Bot 的有权回复，原生追问/工具审查回源处理，日志折叠而非群发每个步骤。
4. 任务列表/看板/只读计划甘特打开同一 issue。成果区把输入材料、过程稿、归档 v2 和待验收 v2 分开；周然针对确定版本验收或退回。老板按权看目标与交付风险，不自动读私密群/受限附件。
5. 林悦将有效做法提为 skill 候选；有发布权的人在同一 Skills/Studio 查看来源、差异、测试与业务评判后发布。下一任务实际消费获准版本才算复用，不把 Bot 回复“记住了”当公司资产沉淀。
6. 维护者从连接/设备页排查过期来源、等待设备或模型不可用，从用量页核对同一 run 费用；不要求员工去 OpenMausBot/Multica/DSH 另登录处理工作。

**实施顺序而非功能删减：**P0 冻结版本/接口/实际开关并证伪硬边界；P1 先一个原生壳里的工作首页、组织最低可用入口、对话/原生控制、任务与成果纵向链；P2 完整部门/资产能力/授权连接与治理视图；P3 双场景、角色与异常回归。新增例程是否首批启用、具体连接名单/管理角色、最终导航标签仍按 D08/D09 评审，不自动成为新增用户故事。复杂自动化、通用画布、语音/移动、插件市场继续暂缓。

**前端派发前的最小页面卡：**用户动作与角色、来源页面/固定 SHA、实际 route/flag、原生对象 ID 与读取/写入命令、授权/撤权/离线状态、D/A/R/T 处置、所属 B 模块及验收证据。已有功能有明确“保留并适配/暂缓/不采用”处置，不允许因 agent 没看到低保真就重建另一套，或未经评审删掉。


## 4. 员工如何完成一次工作

完整业务契约见 [六步产品流程](D:/dev/morchat.co/docs/PRODUCT-LIFECYCLE.md)。入口仍在现有群、我的工作、AI 同事和资产目录内，不增加四套独立产品。

1. **提出目标：**员工/负责人均可直接创建或请组织助手澄清，展示预期结果、输入、责任人、期限和验收口径。普通讨论不逐句建单；明确 AI 提问/规划才创建可见轻量真实任务，追问沿用关联，任务外自动标题等模型功能首版关闭。
2. **组建人和 AI 团队：**推荐已有成员/AI，选择已有 Bot 或 Bot 模板/岗位包，再用小队模板映射成员，预览新增/复用、权限和资源缺项；Bot 模板创建 AI 同事，小队模板创建本次团队实例，不复制旧会话/记忆/授权。员工和负责人按各自权限维护，新增 AI 不等于可以立即运行。
3. **拆分认领：**任务卡展示来源目标、唯一主承接者、业务责任、输入版本、产出/验收、依赖和期限；自己认领或按权限委派。跨部门可读与邀请不产生任意指派权；双人竞争只能一方成功。
4. **协作交付：**员工助手默认本人设备，公用 Agent 自动选择授权池；完整 harness 在本机调用公司云模型，独立任务可同机/跨机并行，消息/取消/状态不受长执行阻塞。交接有接收回执和资产版本；自动保存、公司归档、提交验收、验收完成分开显示，尚未上传不能称已交付。
5. **复盘沉淀：**在原任务指出问题或成功依据，形成知识/岗位包/模板/skill 候选。评估、维护和发布权限分开；不默认读取私密群或把一次成功升级为公司规则。
6. **下次复用：**选择已发布组合版本，映射新的真实成员和输入，重新验权；实际加载版本可追溯，缺工具/不兼容/加载不符可见阻塞。模板更新不静默改在途任务，继任者不依赖原维护人电脑。

AI 组织助手可辅助受理、组队、检查缺项和复盘，但不是必经入口或超级管理员。关闭它后，员工照常手动建群、认领、交接、验收。岗位包区分已登记/已物化/实际加载/检查通过；小队区分草案/准备中/可用/部分失败。重试恢复同一操作，不重复建群建单。

小队可由真人负责业务协调，AI 辅助；不强制 AI leader 或“一群一项目”。以上产品标签不建立第二份任务状态，面板继续读取唯一事实。

### 4.1 用户看到的版本记录

Bot 详情区分“来源模板”“当前生效能力”“修改记录”和“任务运行”。能力页关联原生配置历史、指令内容快照、skill 版本；小队页区分模板版本与本次真实成员。版本号不代替实际内容与运行证据，升级不改变 Bot 身份，也不自动升级所有小队。

变更记录展示操作者/时间、原因、前后差异、候选/评估/生效状态及受影响的新任务范围。已有配置/skill 历史直接消费原生；指令新保存没有完整原生历史，须系统自动保留字节并验证历史引用/GC 后可取才显示“可回退”，不能拿 contentHash 或旧 history 接口充数。回退显示具体回退哪些配置/指令/skill，不回退权限或改写旧 run。

这些在现有 Bot/资产详情内组合展示，不新增模板/版本独立产品；完整关系见 [产品流程](D:/dev/morchat.co/docs/PRODUCT-LIFECYCLE.md)。

### 4.2 员工与负责人沿同一条活动方案走查

1. **员工发起：**从“我的工作”认领活动方案，选现有小队模板，预览运营同事、资料 Bot、内容 Bot 的绑定与资料范围；缺授权就待补，不克隆同事 Bot 或借其电脑。负责人也能从部门目标以相同流程发起。
2. **澄清与并行：**员工在任务线程 @ 资料 Bot 和内容 Bot。两项获准子任务并行；资料 Bot 问受众范围，首页与线程出现同一追问。员工回答后先见“已记录”，执行器收到显示“已送达”，对应 harness 实际消费后才显示“已处理”；内容 Bot 可继续不依赖该答案的工作，不等待整个设备队列。
3. **补充与许可：**员工追加“同时给出线下版本”，未消费前可以修改/撤回。确有授权需求时显示具体请求；有该权限的负责人批准一次范围内操作，不自动给所有下属或全部工具授权。下一轮补充不伪装成即时 steer。
4. **改变方向：**员工点“停止本次协作”，看到两个 Bot 和待处理补充的范围及各自回执；关机节点只能标待核对，另一独立项目继续。确认已停及效果边界后，员工明确继续/改需求，新 run 保留原记录。
5. **交付：**Bot 在获准本机目录生成方案，线程先显示待归档，中央确认 v1 后提交。负责人从部门待验收直接打开同一版本，退回形成 v2；验收 v2 后首页、任务看板、成果引用同步，v1 记录不改写。
6. **沉淀与复用：**员工纠正资料中的事实，条件保存为知识新版本；把可复用方法提为 skill 候选。负责人只有兼具材料访问与目标发布权才可评审/发布。原生案例测试与业务评审通过后，另一员工的新任务显式使用获准版本；旧运行/旧模板实例不被静默更新。

工作资产属于公司不等于老板/负责人可读全部材料；私密来源不随群、子任务、模板或复盘扩大可见性。本场景不用千川字段，也不依赖复杂 IM、个人 Cloud 或第二套任务引擎。

## 5. 权限和私密工作的呈现

首版默认创建“公司工作空间”；普通任务明细默认同部门可见。敏感工作或私密群可显式限定本人或指定小组访问，但仍受公司工作资产保留与授权交接政策管理，这种受限设置不是普通任务的默认值。任务可见不等于其来源群聊天可见。界面必须明确写出这些属性，不使用“管理员永远看不到、离职全部删除”等不真实承诺。

个人隐私不属于公司资产。首版不建设完整个人生活助理空间；用户误放隐私时须有标记、隔离、纠正/删除与衍生索引处理渠道。明确可识别的隐私未处理前不进入知识/skill 提炼。不得声称分类能自动识别一切隐私。

加入群、查看历史消息、查看关联附件、运行 AI、修改任务分别检查权限。已有群新增成员不默认公开全部受限历史；MVP 建议默认只看加入后的消息，历史授权另行显式办理。移除成员后，后续读取和推送立即停止；已经合法看过的内容不宣称可以从其记忆或截图中收回。

平台管理员默认只有管理职责，不自动拥有全部内容访问权。若 Paperclip 原生管理员角色无法满足这一隔离，不能把该角色发给普通运维；需要完整内容访问的受限管理员须另行授权并审计，其他人员只看脱敏健康信息。

### 5.1 账号开通与设备授权的体验

账号开通时指定部门、岗位/角色、资源范围、AI/工具使用权和费用归属；员工随后绑定获准设备、选择工作目录与浏览器会话。客户端检测并受控准备已批准版本的完整 harness 和工具环境，展示下载/校验/兼容状态；不要求员工自行装 CLI、开终端、提供个人 Key/订阅，不默认复用个人配置和登录。公司连接不可用就提示阻塞，不回退个人计费。客户端明确告知哪些内容将传云模型或公司资产库，不自动扫描整台电脑。

员工保留电脑管理员权限，界面清楚区分“我的电脑权限”与“本次 Agent 获准能力”，显示工作目录/浏览器/工具/资料承载范围和撤销入口；加入公用池不是整机接管。负责人身份不自动带来同事设备控制权；员工可暂停本机工作或收回授权。授权变更后菜单、面板、检索、后台运行与本地能力一并收敛，不能只隐藏按钮。公司模型由管理员配置，普通员工只选择有权使用的模型或 AI，不接触原始 Key。

公用 Bot 无法派发时，按查看者权限显示“设备未授权”“设备管理人无对应资料授权”“能力/容量不足”等原因，不显示对方无权查看的资料名称/内容。换机不静默扩大任何人的资料权。

### 5.2 排队、离线和交接的可见性

同机和跨设备的无冲突任务均可并行，不再默认一台电脑只运行一个任务。仅对真实依赖、冲突资源或容量不足显示等待，并分别解释浏览器锁、模型限额、资源不足与上传积压，不能统称“AI 思考中”；单任务取消不误停无关任务。

员工助手设备离线显示等待本人设备；公用 Agent 未启动任务可自动改选其他合格池节点，安全点接续显示新旧 run 关联，未知旧操作显示待核对。全池不合格或资源绑定无法迁移就显示阻塞，不自动借未授权设备。离线停止新动作，恢复先对账，不能把重新连接等同安全重跑。

文件显示本机生成、待上传、公司已归档的区别。失联设备上未上传内容可能丢失，不能称已保留；换设备或离职通过中央资产/检查点和重新授权接续，不要求员工复制个人会话目录。群卡/面板展示未完任务和待交接缺口；未知旧操作未查清不自动再执行。

### 5.3 任务进度、文件保存与接手分开显示

同一任务卡分业务进度、执行设备/运行状态、公司确认保存点、候选/已验收交付四个维度。显示最近已保存步骤/时间与未同步风险，不只显示 AI 自报百分比；保存成功不是任务已完成。Git/普通文件版本在同一资产界面，员工不用掌握 Git 命令。

接手从最近获授权、完整已确认版本建立新的本地工作区，不覆盖新员工已有文件、不复制原员工登录态。同一个公用 Agent 的另一任务可以直接独立运行，不占用或抢原任务目录。人类编辑用接管/导入版本入口；冲突保留候选并提示，不静默覆盖。规则和离线示例见 [任务与工作空间接续](D:/dev/morchat.co/docs/WORKSPACE-CONTINUITY.md)。

## 6. 面板应显示什么

- 员工：我的工作 + 本部门普通任务明细与业务流转；另可查看获授权跨部门项目/任务的进度、交接、期限、阻塞与交付，不局限于个人待办。
- 负责人：所负责部门的目标、任务流转、未认领工作、阻塞、交付、协作依赖和能力维护责任；默认无其他部门全貌。
- 老板：目标进展、部门协作、关键成果与业务指标；下钻仍受资源权限约束。
- 运维：运行故障、队列/同步延迟、模型成本、连接健康；业务内容访问另行授权。

用量面板复用 Paperclip 的成本/预算数据，按真实责任人与部门/项目归属过滤；员工看本人获授权用量，负责人看所负责范围，公司管理者看获授权总览。普通任务可读不自动开放他人完整费用明细，费用本身另按权限展示。未知价格和待结算必须标出，不能显示为零费用。

首版不做按聊天字数、在线时长或 Agent token 数给员工打绩效分。AI 成本与经营预算分开，任务完成与经营指标达成分开。

### 6.1 面板的默认可见范围

面板是各角色的共同能力，不是老板专属。部门范围决定默认工作视野，角色决定允许的操作，资源权限决定能否打开具体内容；三者不能互相替代。

| 身份 | 默认业务范围 | 不能因此获得的权限 |
|---|---|---|
| 老板/公司管理角色 | 公司及各部门的经营与工作总览 | 个人隐私、受限内容的无条件访问 |
| 部门负责人 | 明确由其负责的部门；多部门负责人只覆盖已授予管理范围 | 其他部门完整业务、受限私聊或资产的自动访问 |
| 员工 | 我的工作 + 本部门普通任务的明细与业务流转，默认同部门可见 | 全公司或其他部门面板，以及未单独授权的敏感内容和私密群 |
| 跨部门协作参与者 | 获授权项目或任务的明细及对应业务流转，包括进度、交接、阻塞和交付 | 对方部门其他任务、群记录与资产；其直属负责人也不会自动继承该跨部门授权 |
| AI | 当前任务与委托身份允许的范围，输出还受接收方权限限制 | 因服务账号或所在群而取得全公司知识 |

**已确认规则：部门内普通任务的明细默认同部门可见，不要求逐个任务单独邀请，也不局限于任务参与者。**明细包括非敏感的任务说明、责任人、期限、进度、交接记录与交付信息。敏感内容、私密群及受限附件/资产仍需单独授权；将其关联到普通任务不会解除原有访问限制。默认可查看不等于默认可编辑、分派、发布或管理。

**跨部门授权必须同时覆盖相应的协作可见性，而不只是给一个任务结果链接。**项目级授权可查看授权项目范围内普通任务及其业务流转；任务级授权只覆盖指定任务及授权的交接信息。敏感内容和私密群仍单独授权，不因项目共享自动开放。

对应业务流转至少展示授权范围内的当前阶段、责任人、进度、前后交接、期限、阻塞和交付。跨部门视图与任务卡使用同一权威状态，不另建一套可写状态。跨出授权范围的依赖不自动展开；可由有权人员在共享任务内提供最小必要的交接状态，但不能暴露未授权任务名称、明细或私密群记录。

跨部门协作不开放对方整个部门。授权范围、来源与期限可查，撤销后后续查询、导出、AI 检索和推送都失效。

面板统计、筛选、计数、导出、下载和 AI 摘要同样受权限约束；无权内容不得通过数量或汇总反推。后端先检查部门与资源范围，不能只在前端隐藏菜单。这里的“业务流转”指目标、任务和交接状态，不代表恢复建设工作流引擎。

## 7. 三个不变的体验要求

1. 只需要一个日常入口；不能在聊天里显示完成、任务台却仍执行中且没有同步提示。
2. 结果可追溯到任务、证据、实际执行者与能力版本；模型口头声称完成不算结果。
3. 替换员工、AI 模型或未来外部工具，不应改变公司的任务和资产身份。
